# Design: Маршрут этапов проекта ai386

> История Go-издания: упоминания Go-команд, путей и цифр ниже относятся к Go-реализации (ai386).

## Context

Исходный снимок выполнен 2026-09-09; актуальный статус ниже обновлён 2026-09-11. В репозитории есть `internal/machine`, `config`, `cli`, `cpu`, `storage`, `bios`, `vga`, `pic`, `ps2`. Архивированы семь changes: каркас/CLI, CPU, storage, BIOS, CPU conformance, VGA и ввод (ссылки в tasks.md).

`go build ./...` и `go vet ./...` успешны. `go test ./...` завершается FAIL: CPU conformance — 34652 passed, 2668 failed; остальные пакеты успешны. Это исходное состояние, а не выполненный критерий общей приёмки.

CLI вызывает Start и сразу Stop. Start сбрасывает CPU и выполняет Bootstrap, но не запускает цикл исполнения; тесты вызывают CPU.Run отдельно. VGA возвращает кадр, PS/2 принимает события через Go API. Загрузка реальных Linux/FreeBSD пока не подтверждена.

Актуально на 2026-09-11: CPU conformance и полный общий прогон успешны; CLI исполняет гостя непрерывно, PIT и RTC/CMOS приняты. DSL 4.4.10 загружается с live-CD до shell и выполняет команды через PS/2/VGA. Оконный frontend и ввод хоста приняты. Рабочие сессии DSL 4.4.10 и FreeBSD 4.11 с отдельных HD по 2 ГиБ и RAM 64 МиБ приняты: ввод команд, запись файла, сохранность после перезапуска и чистая остановка (9.1–9.2). Предыдущие абзацы описывают исходное состояние, а не текущие блокеры.

## Goals / Non-Goals

**Goals:** сохранить связь между исходными требованиями, реализованными компонентами и остатком работ; задать зависимости следующих scoped changes и проверяемые границы приёмки.

**Non-Goals:** менять реализацию, считать синтетические тесты доказательством совместимости с ОС, выбирать новые библиотеки и протоколы в документе маршрута.

## Decisions

### D1: Шина и интерфейсы устройств

Существующая архитектура связывает CPU и устройства через шину памяти и портов в `internal/machine`. Она сохраняется как основа следующих этапов: устройства можно добавлять независимо. Монолитная переработка не требуется для актуализации плана.

### D2: Интерпретатор CPU

Пользователь согласовал функциональную совместимость i486DX4-100: результаты, архитектурное состояние и исключения CPU/FPU. Потактовое совпадение времени инструкций не входит в приёмку; контракт виртуального времени устройств сохраняется. Первое поколение CPU реализовано интерпретатором; JIT остаётся отложенной альтернативой. Производительность для реальной ОС ещё не измерена, поэтому достаточность скорости не считается установленным фактом. Управление, базовая арифметика, контекст и пользовательские операции x87 приняты отдельными changes и позволяют DSL выполнять утилиты. Полнота инструкций и исключений FPU целевого i486DX4 ещё требует продолжения 2.7–2.8.

### D3: Уже выбранные BIOS и диски

BIOS реализован собственными Go hooks (`internal/bios`), а не внешним ROM. Поддерживаются bootstrap, INT 10h/13h/15h/16h и El Torito. Это принятое решение этапа bios-boot; его достаточность для выбранных ОС проверяется в этапе 4.

HD — raw-файл. `--cd` подключает ISO, `--shared` строит виртуальный ISO из каталога. IDE и ATAPI PIO приняты (3.4), драйвер Linux обнаруживает и читает CD. В attach-all-cds Machine подключает до трёх CD суммарно из обоих списков и отклоняет превышение до создания HD. Интеграционные тесты подтвердили чтение каждого носителя через ATAPI; гостевой FreeBSD CD-драйвер подтвердил чтение всех трёх носителей и запрет записи. Пользователь согласовал статичное дерево shared-CD с чтением текущего содержимого хоста; размеры и имена фиксируются на старте. Формат HD и исходный выбор BIOS больше не являются открытыми вопросами.

### D4: API устройств и пользовательская работа

`VGA.Frame()` и `Machine.KeyEvent/MouseEvent` дают основу для фронтенда. Цикл исполнения принят в machine-run-loop. В host-vga-input приняты Ebitengine, Console/RunInteractive, конфигурация окна и преобразование событий хоста; конкурентный доступ проверен race-тестами. Задачи 5.6 и все задачи этапа 6 закрыты. Стандартный набор VGA/VBE принят в5.3–5.5 по матрицам QEMU/SeaBIOS и тестам мигания.

### D5: Порядок продолжения

Номера этапов сохраняются для ссылок, но не требуют откладывать проверку ОС до конца проекта:

1. CPU conformance (2.6) закрыт 2026-09-10: 37640 случаев без падений и пропусков, включая две документированные адресные корректировки раннера. Полные тесты, race, vet/build успешны. Далее — планирование продолжений.
2. Цикл исполнения (1.5), согласование образов (4.5) и ранняя диагностика (4.6) приняты; сценарии и результаты в operating-system-acceptance.
3. По результатам проверки детализировать и реализовать недостающие части платформы (1.6–1.7), CPU и BIOS; подтвердить раннюю загрузку (4.3). PIT, RTC/CMOS и виртуальное время уже приняты (1.6–1.7); ранняя загрузка Linux подтверждена (4.3). Ранняя загрузка FreeBSD также принята; новые блокеры выявляются при рабочих сессиях ОС.
4. Диски (этап 3), VGA (этап 5), ввод (этап 6) и рабочие сессии обеих ОС (9.1–9.2) приняты. Завершить функциональную полноту CPU/FPU и приёмку этапа 2.
5. Реализовать DMA и звук (7), сеть (8), затем завершить 9.3–9.4.

Задача 4.6 завершается воспроизводимым отчётом даже при остановке загрузки. Задачи 4.3 и 9.1–9.2 требуют успешного результата. Это позволяет обнаружить зависимости без циклической блокировки планирования.

### D6: Учёт прогресса

Отметка `[x]` означает выполнение конкретного критерия задачи в указанном объёме. Историческая приёмка подтверждается архивом и журналом; она не делает текущий общий прогон зелёным. Открытые исходные задачи сохраняют номера и содержат пояснения частичной реализации. Отложенные требования не удаляются из specs/ и получают задачи продолжения.

### D7: Согласованные ограничения CD и сеть

Пользователь согласовал до трёх CD на оставшихся IDE-слотах рядом с одним HD. Лимит общий для ISO и CD из каталогов; превышение должно завершаться явной ошибкой до запуска ВМ. Реализация и проверка всех допустимых путей завершены в 3.6; весь этап дисков принят.

Для первого рабочего варианта сети согласованы NE2000 и пользовательская сеть NAT для доступа гостя в интернет без настройки TAP. Объём уточнён пользователем: только исходящий обмен из ВМ и ответы на него, без входящих соединений и проброса портов. Детальный контракт конфигурации, обмена пакетами и приёмки предстоит оформить в задаче 8.1.

### D8: Видеорежимы и эталон

Пользователь согласовал стандартные режимы VGA плюс VBE для 640×480/256 цветов. Эталон сравнения кадров — QEMU/SeaBIOS. Реализация и сравнение приняты в 5.4; текст, палитры, мигание и весь этап VGA также приняты.

### D9: Звук на хостах Linux и Windows

Пользователь согласовал воспроизведение и запись SB16 на Linux и Windows. Выбор backend, DSP, DMA, IRQ и конфигурация оформляются в 7.1. Приёмка требует реального воспроизведения и захвата на каждой хостовой ОС; одной кросс-компиляции или тестового источника недостаточно. macOS в текущий объём звука не входит.

## Risks / Trade-offs

- [Повторная регрессия CPU] → сохранять полный conformance-прогон и регрессионные тесты; две корректировки исходных записей закреплены хешами и описаны в README корпуса. Успешный прогон не подтверждает полноту i486 или загрузку ОС.
- [Регрессия загрузки ОС] → сохранить отчёты принятых HD-сессий и повторить сценарии на итоговой сборке в 9.4.
- [Регрессия VGA] → сохранять принятые матрицы кадров QEMU/SeaBIOS для стандартных VGA и VBE 640×480/256, текста и палитр.
- [Отложенные PIT, RTC/CMOS, время и DMA потеряются между этапами] → отдельное планирование и проверка платформы (1.6–1.7), DMA — до воспроизведения/записи SB16 (7.5).
- [Исходные ADDED-спеки маршрута пересекаются с уже синхронизированными scoped-спеками] → перед архивацией сверить дельты с базой, не перезаписывать её историческим текстом.

## Open Questions

Решения не предполагаются заранее; их согласование является критерием соответствующей задачи планирования:

- Детальный контракт FPU и эталонные проверки функциональной совместимости — 2.7.
- DSP/DMA и backend воспроизведения/записи для Linux и Windows — 7.1.
- Детальная конфигурация и проверка исходящего доступа NE2000/NAT — 8.1. Проброс портов и входящие соединения исключены из текущего объёма.

## Найденные проблемы FreeDOS/Doom (2026-10-12)

Источник: [отчёт запуска Doom 1.9 Shareware](../../../docs/doom-acceptance-2026-10-11.md),
прогон 2026-10-11, FreeDOS 1.4 BASE, 16 МиБ RAM, виртуальная частота 1 МГц,
копия `build/freedos/freedos-ready.img`, ввод PS/2 через API Machine.
Результаты относятся к этим условиям; повторение при штатных 100 МГц
и через оконный frontend входит в последующую приёмку.

| ID | Наблюдение | Статус и область проверки |
| --- | --- | --- |
| DOOM-TIMER | Режим 2 (JEMMEX), `DOOM -NOSOUND`: DPMI/WAD загружаются, затем игровой счётчик времени не продвигается, меню не открывается. В режиме 4 (HIMEMX/Safe Mode) уровень и демозапись отрисовываются. | Открыто. Проверить PIT, PIC, доставку IRQ0 и переходы CPU/VM86/DPMI; первопричина не установлена. Задача 9.5. |
| DOOM-INPUT | Режим 4: Esc не открывает меню; PIC mask=FE, IRQ1 запрещён, запрос остаётся в IRR=02. | Открыто. Проверить BIOS-инициализацию PIC/PS2, обработчик IRQ1 гостя, make/break и EOI. Не снимать программно маски, установленные гостем. Задача 9.6. |
| DOOM-AUDIO | Режим 4, `DOOM -NOMUSIC -TIMEDEMO DEMO1`, SB16 220h/IRQ5/DMA1/5, backend=file: 5 074 818 байт PCM, все 80h; IRQ5 разрешён (PIC mask=DE). | Эффекты не подтверждены. До вывода о дефекте SB16 обеспечить воспроизводимое событие с известным ненулевым звуком и проследить его данные до DMA/PCM. Задача 9.7. |
| DOOM-VGA | До исправления порт 3DAh всегда возвращал ноль; Doom зависал в ожидании вертикального обратного хода по адресу 471C81h. | Исправлено и покрыто тестами CLI/ожидания трёх импульсов. Приближённая развёртка 70 Гц, обратный ход 1/64 кадра; точная модель CRTC не принята. Сохранить регрессию в 9.8. |

Для звукового прогона на тестовой копии задан `DEFAULT.CFG`:
`snd_sfxdevice=3`, `snd_musicdevice=0`, `snd_sbport=544`, `snd_sbirq=5`,
`snd_sbdma=1`. Музыка отключена: OPL/MIDI остаются вне текущей реализации.
Наличие DMA/PCM не доказывает воспроизведение эффекта. Работа устройств
вывода хоста Linux/Windows проверяется отдельно от файлового backend.

Исторические задачи ввода и платформы сохраняют свою приёмку Linux/FreeBSD;
новые регрессии FreeDOS/Doom учитываются открытыми задачами 9.5–9.8.
Задача 9.4 требует их завершения. Исправления должны сохранять гостевые
маски PIC, виртуальное время и работающие сценарии Linux/FreeBSD.

## Результат приёмки FreeDOS/Doom (2026-10-14)

Исторические проблемы выше закрыты задачами9.5–9.8; исправления и фактическая
матрица опубликованы в [актуальном отчёте](../../../docs/doom-acceptance.md).
Полные DEMO1, управление и PCM эффекта приняты в режимах2/4 при1/100МГц;
оконный ввод принят при1МГц. Это не закрывает CPU/FPU M/X, гостевую/физическую
приёмку звука, HTTPS или весь проект.

## Сверка дельт маршрута с базовыми спецификациями (2026-11-01)

Исторические ADDED-секции `specs/` маршрута сверены с актуальными базовыми
спецификациями (выполнено перед архивацией маршрута, как требовал proposal):

- **Перенесено в базу:** «Проверяемые звуковые эффекты Doom» → `sb16`;
  «Ожидание вертикального обратного хода» → `vga`; граница совместимости
  «потактовое совпадение времени не требуется» → `cpu`; сценарий
  «Управление Doom через гостевой обработчик IRQ1» → `input`; сценарий
  HIMEMX/E1M1 → `machine-core` («Таймер Doom при JEMMEX»); граница объёма
  NAT (без входящих соединений и проброса портов) → `network`.
- **Удалено как дубликаты базы:** требования `config-cli` (HD/CD/RAM/очередь
  загрузки/конфиг), `cpu` (регистры/прерывания/режимы), `input`
  (клавиатура/мышь/IRQ), `machine-core` (жизненный цикл/память), `network`
  (доступ/конфигурация), `sb16` (воспроизведение/запись/порты), `storage`
  (HD/CD/контроллер/загрузка), `vga` (текст/графика/регистры) — все они
  покрыты детальнее базовыми требованиями после архивации scoped-changes.
- Итог: дельты `specs/` маршрута удалены (`skip_specs: true`); финальная
  архивация маршрута — doc-only.
