> История Go-издания: упоминания Go-команд, путей и цифр ниже относятся к Go-реализации (ai386).

## Why

Проект ai386 находится в нулевой стадии: кода нет, есть только маршрут этапов. Без исполнимого каркаса, на котором держится жизненный цикл виртуальной машины, шина устройств и модель памяти, невозможно начинать этапы CPU, дисков, VGA и далее. Этап 1 даёт этот фундамент вместе с конфигурацией и CLI — точкой входа пользователя, — после чего проект собирается, тестируется и остаётся работоспособным.

## What Changes

- Создаётся Go-модуль и исполняемый файл `ai386`, который запускает виртуальную машину и корректно останавливает её.
- Вводится каркас виртуальной машины (`machine-core`): жизненный цикл (запуск/останов), шина устройств, модель памяти с маршрутизацией обращений CPU к RAM и устройствам.
- Вводится конфигурация и CLI (`config-cli`): параметры командной строки в стиле GNU-флагов и файл конфигурации в формате TOML для пути HD, подключения CD (один и более), объёма RAM и очереди загрузки; значения командной строки имеют приоритет над файлом конфигурации.
- При отсутствии файла образа HD создаётся пустой файл-плейсхолдер при создании виртуальной машины (фактическое содержимое и размер образа определяет этап `storage`).
- Приёмка этапа: сборка `go build`, юниттесты (testify) на сценарии спеки, чистый `go vet`.

## Non-goals

- Не реализуются CPU, диски (IDE/ATAPI), VGA, ввод, звук, сеть и BIOS — это последующие этапы.
- Не определяется формат и размер образа HD (открытый вопрос маршрута, решается на этапе `storage`) — этап 1 создаёт только плейсхолдер.
- Не реализуется исполнение инструкций: машина стартует с адреса сброса и останавливается, не исполняя гостевой код, пока не готов CPU.
- Не выбирается схема реальной сети и не решаются вопросы производительности.

## Capabilities

### New Capabilities

- `machine-core`: каркас эмулятора — жизненный цикл виртуальной машины, шина устройств, модель памяти. Первый этап определяет эти требования детально (путь `machine-core` уже заявлен маршрутом проекта).
- `config-cli`: параметры командной строки и файл конфигурации — путь HD, подключение CD, объём RAM, очередь загрузки и приоритет CLI над конфигом.

### Modified Capabilities

- нет (базовые спецификации ещё не созданы).

## Impact

- Структура репозитория: в `openspec/specs/` появятся `machine-core/spec.md` и `config-cli/spec.md` после синхронизации дельт.
- Код: новый Go-модуль с пакетами каркаса, конфигурации и CLI; команда `ai386` в cmd.
- Зависимости: Go 1.26; для TOML используется внешняя библиотека (например, BurntSushi/toml); CLI — стандартный пакет `flag`; тесты — testify.
