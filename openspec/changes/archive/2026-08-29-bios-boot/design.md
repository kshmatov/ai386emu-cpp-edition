> История Go-издания: упоминания Go-команд, путей и цифр ниже относятся к Go-реализации (ai386).

## Context

Этап 3 завершил подсистему хранения. Текущее состояние:
- CPU после `Reset()` находится в аппаратном состоянии CS=0xF000 (база 0xFFFF0000), EIP=0xFFF0 — без исполняемого кода по этому адресу.
- `internal/storage` предоставляет `BlockDevice` для HD/floppy (raw) и CD (`isoDataStore` из ISO-файла, `virtualIsoStore` из каталога хоста).
- `internal/cpu` доставляет программные и аппаратные прерывания только через IVT (реальный режим) или IDT (защищённый режим) — нет точки перехвата для нативной обработки.
- Нет ни PIC (8259), ни PIT (8254), ни CMOS/RTC, ни 8042 — прерывания сейчас доставляются напрямую через `cpu.RequestInterrupt(vector)` из `machine.go`.

По итогам обсуждения приняты два решения, определяющие архитектуру этапа:
1. BIOS — свой минимальный, на Go (не встраивание готового ROM класса SeaBIOS): нет смысла эмулировать 8259/8254/CMOS/8042 только чтобы дать готовому BIOS-бинарнику пройти POST.
2. Загрузка с CD (El Torito) реализуется уже на этом этапе, не откладывается.

## Goals / Non-Goals

**Goals:**
- Механизм перехвата программных прерываний CPU нативными Go-обработчиками (без исполнения настоящего BIOS ROM-кода).
- Реализовать процесс начальной загрузки: выбор устройства по очереди `--boot`, чтение загрузочного сектора (MBR для HD/floppy, El Torito no-emulation для CD), передача управления загруженному коду.
- Реализовать минимально достаточные BIOS-сервисы для типичных реальных загрузчиков эпохи (GRUB stage1/2, Linux realmode setup, FreeBSD boot2/loader): INT 13h (00h/02h/03h/08h/41h/42h), INT 10h (00h/0Eh как безопасные заглушки), INT 16h (00h/01h как небlокирующие заглушки), INT 15h (E820h карта памяти, включение A20 как no-op).
- Довести реальный режим минимум до момента, когда загруженный код переключает процессор в защищённый режим (CR0.PE=1) — подтверждается тестовым загрузочным сектором (машинный код, аналогично существующим тестам `internal/cpu`).

**Non-Goals:**
- El Torito floppy-emulation/HD-emulation режимы CD — только no-emulation (доминирующий режим у установочных ISO эпохи: isolinux/syslinux, FreeBSD bootonly).
- Полноценный видео-вывод (текстовые/графические режимы VGA) — отдельный этап 5; INT 10h пока не рисует ничего.
- Полноценная клавиатура (реальные скан-коды, PS/2, прерывания) — отдельный этап 6; INT 16h — заглушка.
- Остальные сервисы BIOS, не нужные для загрузки ОС (INT 17h принтер, INT 14h COM-порт и т.п.).
- Эмуляция аппаратного A20 gate (маскирование 21-го адресного бита и его баги) — A20 считается всегда включённой.
- Реальная проверка с GRUB/Linux/FreeBSD — откладывается до этапа 9 (интеграция); здесь приёмка — через синтетические тестовые загрузочные секторы.

## Decisions

### D1: Перехват программных прерываний (native BIOS hooks)

В `internal/cpu` добавляется таблица обработчиков `[256]func(*CPU) bool` и метод `SetSoftIntHook(vector uint8, fn func(*CPU) bool)`. В `execInt()` перед вызовом `raise(vector)` проверяется наличие хука для вектора: если он есть и возвращает `true` (обработано), доставка через IVT не выполняется — CPU продолжает со следующей инструкции (эквивалент мгновенного `IRET`, без реального перехода и без изменения стека). Если хука нет или он вернул `false` — обычная доставка через IVT, поведение не меняется (существующие тесты `execInt`/`raiseReal` продолжают проходить).

**Альтернативы:**
- Настоящий BIOS ROM (исполняемый ассемблерный код по адресу сброса) — отвергнут выбором пользователя: требует 8259/8254/CMOS/8042, которых нет и не планируются в ближайших этапах.
- Перехват на уровне шины/памяти (фиктивный ROM с ловушкой на исполнение) — отвергнут: сложнее хука на INT, не даёт дополнительной корректности.

### D2: Процесс начальной загрузки (Machine bootstrap)

`Machine.Start()` после `cpu.Reset()` вызывает `bios.Bootstrap(cpu, bus, devices, bootOrder)`:
1. Регистрирует нативные хуки (D1) на векторы 0x10, 0x13, 0x15, 0x16.
2. Перебирает устройства из `--boot` по порядку:
   - `hd`/`floppy`: читает сектор 0 через `BlockDevice.ReadSector(0)`, проверяет сигнатуру `0x55AA` на смещении 510–511 512-байтного сектора.
   - `cd`: разбор El Torito (D5) на первом подключённом `--cd` устройстве.
3. При первом успешном устройстве — копирует загруженный код по физическому адресу 0x7C00, устанавливает CS=0x0000, IP=0x7C00, DL=номер BIOS-диска (0x00 — первый floppy, 0x80 — первый HD, 0xE0 — первый CD, по стандартному соглашению BIOS), SS=0x0000, SP=0x7C00 (стек ниже загруженного кода, стандартное соглашение реальных BIOS).
4. Если ни одно устройство не дало валидный загрузочный сектор — `Machine.Start()` возвращает понятную ошибку («нет загружаемого устройства»), не запуская исполнение на неопределённом коде.

**Альтернативы:**
- Загрузка через настоящий `INT 19h`, вызываемый исполняемым BIOS-кодом с адреса сброса — отвергнут вместе с D1 (нет ROM-кода, который мог бы его вызвать).

### D3: INT 13h — дисковые сервисы

Реализуется поверх `storage.BlockDevice` напрямую (без похода через порты IDE/FDC этапа 3 — осознанное упрощение уровня BIOS, см. Risks). Устройства резолвятся по DL (0x00/0x01 floppy, 0x80/0x81 HD, 0xE0+ CD) в те же `BlockDevice`, что подключены к IDE/FDC контроллерам в `Machine`.

- `AH=00h` Reset — no-op, CF=0.
- `AH=02h` Read Sectors (CHS): CH/CL/DH → cylinder/sector/head, преобразуется в LBA по геометрии устройства (HD: 16 heads/63 sectors/track — совпадает с IDENTIFY этапа 3; floppy: 2 heads/18 sectors/track — совпадает с FDC этапа 3); читает AL секторов в ES:BX.
- `AH=03h` Write Sectors (CHS) — аналогично; на read-only устройстве (CD) — CF=1, AH=0x03 (write protected).
- `AH=08h` Get Drive Parameters — возвращает геометрию (CHS) и число дисков данного типа.
- `AH=41h` Check Extensions Present — сообщает поддержку LBA-расширений (CX=version, BX=0xAA55).
- `AH=42h` Extended Read (LBA, Disk Address Packet по DS:SI) — читает сектора напрямую по LBA, размер DAP 16 байт (базовый).
- Неизвестная функция AH — CF=1, AH=0x01 (invalid function).

Ошибки сигнализируются через CF=1 в EFLAGS и код ошибки в AH — как в реальном BIOS, чтобы загрузчики, проверяющие CF, вели себя предсказуемо.

### D4: INT 10h / INT 16h — заглушки видео и клавиатуры

INT 10h: `AH=0Eh` (teletype output) и `AH=00h` (set video mode) — no-op, CF=0/успех, символ «теряется» (нет реального видеовывода до этапа VGA). Остальные функции — тоже no-op с успешным возвратом, чтобы не блокировать загрузчики, которые не проверяют реальный эффект, только код возврата.

INT 16h: `AH=01h` (проверка нажатия без ожидания) — всегда «нет клавиши» (ZF=1), чтобы неблокирующие опросы (типичные в загрузчиках) не занимали процессор бесконечно и не давали ложных срабатываний. `AH=00h` (блокирующее чтение) — возвращает синтетический код клавиши Enter (AH=0x1C, AL=0x0D) немедленно, чтобы автоматическая безынтерактивная загрузка не подвисала в ожидании реального ввода (полноценная клавиатура — этап 6).

### D5: INT 15h — карта памяти и A20

`AX=E820h`: по контракту (курсор в EBX, буфer ES:DI, ECX=размер буфера) возвращает один дескриптор на вызов; для этого этапа — единственный дескриптор `[0, RAMSize)` типа 1 (usable) и EBX=0 (конец перечисления после первого вызова) — минимально достаточно для загрузчиков, которые запрашивают карту памяти и берут суммарный объём.

`AX=2401h` (Enable A20), а также прямые обращения к порту 0x92 (fast A20) и 8042 (0x64/0x60) — обрабатываются как всегда успешные no-op операции: A20 считается постоянно включённой (Non-Goals).

### D6: El Torito (CD boot, только no-emulation)

Применяется к `isoDataStore` (реальный ISO-файл, подключённый через `--cd`) — не к `virtualIsoStore` (`--shared`), который предназначен для обмена файлами, а не для загрузки.

Разбор:
1. Boot Record Volume Descriptor — сектор 17, байт 0 = 0 (Boot Record), байты 1–5 = "CD001", байты 7–37 = "EL TORITO SPECIFICATION" (с паддингом нулями), байты 71–74 (LE) = LBA Boot Catalog.
2. Boot Catalog по этому LBA: Validation Entry (32 байта: байт 0 = 0x01, байт 1 = platform ID 0x00 — x86, байты 30–31 = подпись 0x55AA) → Initial/Default Entry (32 байта: байт 0 = boot indicator, 0x88 — bootable; байт 1 = media type — поддерживается только 0, "no emulation", иначе ошибка «режим не поддерживается» и переход к следующему устройству очереди; байты 2–3 = load segment, LE, 0 означает значение по умолчанию 0x07C0; байты 6–7 = число virtual-секторов по 512 байт; байты 8–11 = LBA образа).
3. Образ читается с указанного LBA (в 2048-байтных секторах ISO) на `sector_count × 512` байт и копируется по адресу `load_segment × 16` (обычно совпадает с 0x7C00).

## Risks / Trade-offs

- [A20 всегда включена — не 100% аутентично] → осознанное упрощение; современные для целевой эпохи ОС сами явно включают A20 и не полагаются на баг wraparound.
- [INT 13h работает через `BlockDevice` напрямую, а не через порты IDE/FDC этапа 3] → так надёжнее и проще на уровне BIOS; порты IDE/FDC остаются нужны и рабочи для доступа гостевой ОС после передачи управления (уже реализовано, этап 3).
- [El Torito floppy/HD-emulation не поддержаны] → большинство установочных ISO эпохи (isolinux/syslinux, FreeBSD) используют no-emulation; при встрече неподдерживаемого режима — понятная ошибка и переход к следующему устройству очереди, а не падение эмулятора.
- [Заглушки INT 10h/16h не устроят загрузчики, которым нужен настоящий вывод/ввод] → зафиксировано как временное состояние до этапов VGA (5)/input (6); критерий приёмки здесь — прохождение синтетического тестового загрузчика, а не полного GRUB/установщика (это — этап 9).
