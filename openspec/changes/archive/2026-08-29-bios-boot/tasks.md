# Tasks: BIOS и ранняя загрузка (этап 4)

> История Go-издания: упоминания Go-команд, путей и цифр ниже относятся к Go-реализации (ai386).

Выполнение — отдельным субагентом в ветке git-flow `feature/bios-boot`. После каждой задачи фиксируется запись (время и токены). Каждая задача сопровождается тестами (testify) и прогоном `go test ./...`, `go vet ./...`.

## 1. Перехват программных прерываний в CPU

- [x] 1.1 `internal/cpu`: таблица обработчиков `[256]func(*CPU) bool` и метод `SetSoftIntHook(vector uint8, fn func(*CPU) bool)`; в `execInt()` перед `raise(vector)` — проверка хука: при `true` доставка через IVT не выполняется, исполнение продолжается со следующей инструкции без изменения стека; при отсутствии хука или `false` — прежнее поведение через IVT (критерий приёмки: тесты на перехваченный и неперехваченный векторы, отсутствие регрессий в существующих тестах `execInt`/`raiseReal`; сценарии «Обработка перехваченного вектора», «Вектор без нативного обработчика»).

## 2. Bootstrap: загрузка с HD/floppy (MBR)

- [x] 2.1 Новый пакет `internal/bios`: `Bootstrap(cpu *cpu.CPU, bus *machine.Bus, boot []BootDevice) error`, где `BootDevice` связывает тип (hd/floppy/cd), `storage.BlockDevice` и номер BIOS-диска (DL); для hd/floppy — чтение сектора 0 через `ReadSector(0)`, проверка сигнатуры `0x55AA` на смещении 510–511, копирование 512 байт в память по 0x7C00, установка CS=0x0000/IP=0x7C00/DL/SS=0x0000/SP=0x7C00 (критерий приёмки: тест с валидным загрузочным сектором — CPU готов исполнять с 0x7C00, регистры выставлены; сценарий «Загрузка с HD или floppy»).
- [x] 2.2 Перебор устройств по порядку очереди `--boot`: пропуск устройства без валидной сигнатуры и переход к следующему; ошибка «нет загружаемого устройства», если ни одно не подошло (критерий приёмки: тесты с несколькими устройствами — валидным вторым при невалидном первом, и полностью невалидным набором → ошибка без исполнения; сценарии «Устройство без валидного загрузочного сектора», «Нет загружаемого устройства»).

## 3. Bootstrap: загрузка с CD (El Torito, no-emulation)

- [x] 3.1 Разбор Boot Record Volume Descriptor (сектор 17: тип 0, "CD001", "EL TORITO SPECIFICATION", LBA Boot Catalog) и Boot Catalog (Validation Entry — платформа x86, подпись 0x55AA; Initial/Default Entry — boot indicator, media type, load segment, число virtual-секторов, LBA образа) поверх `storage.BlockDevice` (критерий приёмки: тест с синтетически собранными секторами El Torito — корректно извлечены LBA образа, load segment, число секторов).
- [x] 3.2 Загрузка no-emulation образа: чтение `sector_count × 512` байт с LBA образа, копирование по адресу `load_segment × 16` (по умолчанию 0x7C00), передача управления аналогично HD/floppy; интеграция в перебор устройств из задачи 2.2 для типа `cd` (критерий приёмки: тест сквозной загрузки с синтетического CD-устройства; сценарий «Загрузка образа no-emulation»).
- [x] 3.3 Обработка неподдерживаемых режимов (floppy-emulation, HD-emulation) и отсутствия El Torito: устройство пропускается, переход к следующему в очереди (критерий приёмки: тесты на media type ≠ 0 и на CD без Boot Record Volume Descriptor; сценарии «Неподдерживаемый режим эмуляции», «CD без El Torito»).

## 4. INT 13h — дисковые сервисы

- [x] 4.1 Резолв устройства по DL (0x00/0x01 floppy, 0x80/0x81 HD, 0xE0+ CD) в подключённые `storage.BlockDevice`; преобразование CHS↔LBA по геометрии устройства (HD: 16 heads/63 sectors/track; floppy: 2 heads/18 sectors/track — согласовано с IDENTIFY/FDC этапа 3) (критерий приёмки: табличные тесты преобразования CHS/LBA на граничных значениях).
- [x] 4.2 `AH=00h` (Reset, no-op/CF=0), `AH=02h` (Read Sectors CHS → ES:BX), `AH=08h` (Get Drive Parameters — геометрия и число дисков) (критерий приёмки: тесты чтения секторов с проверкой содержимого памяти по ES:BX и корректности параметров; сценарий «Чтение секторов по CHS»).
- [x] 4.3 `AH=03h` (Write Sectors CHS) на устройствах с поддержкой записи (HD/floppy); отказ (CF=1, AH=0x03) на устройстве только для чтения (CD) (критерий приёмки: тесты записи на HD/floppy и отказа на CD; сценарий «Запись на устройство только для чтения»).
- [x] 4.4 `AH=41h` (Check Extensions Present — CX=версия, BX=0xAA55) и `AH=42h` (Extended Read по LBA через Disk Address Packet DS:SI, 16 байт) (критерий приёмки: тесты на присутствие расширений и корректное чтение по LBA-пакету; сценарий «Расширенное чтение по LBA»).
- [x] 4.5 Неизвестная функция AH → CF=1, AH=0x01 (invalid function) (критерий приёмки: тест на непокрытое значение AH; сценарий «Неизвестная функция»).

## 5. INT 10h/16h/15h — заглушки и служебные сервисы

- [x] 5.1 INT 10h: `AH=0Eh` (teletype output) и `AH=00h` (set video mode) — no-op, CF=0/успех, без побочных эффектов; прочие функции — тоже успешный no-op (критерий приёмки: тесты на отсутствие паники и корректный код возврата; сценарий «Вывод символа (INT 10h AH=0Eh)»).
- [x] 5.2 INT 16h: `AH=01h` — всегда «нет клавиши» (ZF=1) без блокировки; `AH=00h` — немедленный синтетический код клавиши (AH=0x1C, AL=0x0D) (критерий приёмки: тесты на неблокирующее поведение и значения регистров; сценарии «Проверка нажатия клавиши без ожидания», «Блокирующее чтение клавиши»).
- [x] 5.3 INT 15h `AX=E820h`: один дескриptor `[0, RAMSize)` типа 1 (usable) за вызов, EBX=0 как признак конца перечисления (критерий приёмки: тест на структуру дескриптора и объём, совпадающий с RAM машины; сценарий «Запрос карты памяти»).
- [x] 5.4 INT 15h `AX=2401h` и обращения к портам 0x92/0x64/0x60 — всегда успешный no-op (A20 считается постоянно включённой) (критерий приёмки: тесты на успешный код возврата без побочных эффектов на память; сценарий «Включение линии A20»).

## 6. Интеграция с Machine и приёмка

- [x] 6.1 `Machine.Start()`: после `cpu.Reset()` — регистрация хуков (группа 1) и вызов `bios.Bootstrap` (группы 2–3) с устройствами, уже подключёнными к IDE/FDC контроллерам этапа 3, и очередью `--boot` из конфигурации; ошибка bootstrap прерывает запуск с понятным сообщением (критерий приёмки: тесты `Machine.Start()` с валидной и невалидной конфигурацией загрузки; сценарий «Запуск машины и адрес сброса» спеки `machine-core`).
- [x] 6.2 Тест сквозного сценария: синтетический загрузочный сектор (машинный код, аналогично существующим тестам `internal/cpu`), который читает через INT 13h ещё один сектор, вызывает INT 10h/16h/15h и переключает процессор в защищённый режим (LGDT + MOV CR0, PE=1); проверка через `Machine`, что CR0.PE установлен после выполнения (критерий приёмки: тест проходит от `Machine.Start()` до перехода в защищённый режим включительно — целевой критерий этапа 4).
- [x] 6.3 Полный прогон `go build ./...`, `go test ./...`, `go vet ./...`; сверка покрытия сценариев спек `bios`, `machine-core` тестами; `openspec validate bios-boot --strict`; архивация change; итоговая запись (критерий приёмки: сборка и тесты чисты, все сценарии покрыты, `openspec validate` без ошибок).
