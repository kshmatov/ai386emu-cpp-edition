## Why

Этап 4 довёл реальный режим до перехода в защищённый режим, но у эмулятора до сих пор нет видео-вывода: INT 10h — это no-op заглушка (design.md bios-boot, D4), а обращения к видеопамяти 0xA0000–0xBFFFF ничем не обрабатываются (уходят в «неотображённый адрес» шины). Ни один загрузчик или ОС, показывающий текст или графику пользователю, не может быть по-настоящему проверен — эмулятор либо «слеп», либо полагается на то, что гостевой код не проверяет реальный эффект вывода.

Этап 5 реализует VGA: регистры контроллеров (CRTC, секвенсер, графический, атрибутный, DAC), видеопамять со всеми схемами адресации реального VGA (planar, chained, unchained/Mode X) и все текстовые и графические режимы вплоть до 640×480/256 цветов — то есть полную функциональность реального оборудования VGA, а не только стандартный набор BIOS-режимов. Наблюдаемый пользователем результат этапа — публичный API кадра (framebuffer), который можно программно прочитать и сохранить как изображение для визуальной проверки; собственно окно/дисплей — отдельная будущая задача, вне рамок этого этапа.

## What Changes

- Новая capability `vga`: устройство на шине, реализующее регистры VGA (CRTC 0x3B4–0x3B5/0x3D4–0x3D5, секвенсер 0x3C4–0x3C5, графический контроллер 0x3CE–0x3CF, атрибутный контроллер 0x3C0–0x3C1, DAC/палитра 0x3C6–0x3C9, регистры состояния/Miscellaneous Output 0x3C2/0x3CC/0x3BA/0x3DA) и видеопамять 0xA0000–0xBFFFF с переключением диапазона по регистру Memory Map Select графического контроллера.
- Поддержка всех текстовых режимов VGA (40×25, 80×25, 80×43, 80×50) со сдвигом курсора и прокруткой, и всех графических режимов вплоть до 640×480/16 и 320×200/256, включая планарную 4-битную адресацию с латчами/write-режимами графического контроллера, chained 256-цветную адресацию (mode 13h) и unchained-доступ (Mode X и аналогичные комбинации регистров) — как прямое следствие точной эмуляции регистров, без выделения отдельных «специальных» режимов кодом эмулятора.
- Публичный Go API кадра: получение текущего изображения экрана (RGB-пиксели) исходя из текущего режима, видеопамяти и палитры DAC — используется тестами/инструментами для визуальной проверки (например, сохранение в PNG); реальное окно/отображение пользователю не входит в этот этап.
- Изменение `internal/bios`: INT 10h перестаёт быть заглушкой — установка режима (AH=00h), вывод символа (AH=0Eh, включая прокрутку) и работа с курсором (AH=02h/03h) делегируются устройству `vga` через его публичный Go API, а не эмулируются как отдельный вывод; INT 16h (клавиатура) не меняется.
- Интеграция `internal/machine`: устройство VGA создаётся и регистрируется на шине при создании `Machine`, как и устройства хранения этапа 3.

## Non-Goals

- Реальное окно/GUI и любой вывод на экран хоста (SDL/иная библиотека, зависимости в go.mod) — вне рамок этого этапа; API кадра проектируется так, чтобы будущий фронтенд мог его использовать, но сам фронтенд не реализуется.
- Аппаратные таймингы (вертикальная/горизонтальная развёртка, реальные задержки retrace) — регистры состояния retrace эмулируются функционально (например, как всегда «в retrace» или по счётчику вызовов), без привязки к реальному времени кадра.
- Эталонное сравнение вывода с другим эмулятором (Bochs/DOSBox и т.п.) — верификация этапа: юнит-тесты на регистры и форматы адресации плюс ручная визуальная проверка сохранённого кадра человеком, без автоматического pixel-perfect эталона.
- VESA/SVGA-расширения (режимы за пределами стандартного VGA, отчёт VBE) — не входят в объём «полного VGA» этого этапа.
- Аппаратный курсор мыши (sprite-курсор чипов, совместимых с VGA) — вне рамок; клавиатура/мышь — отдельный этап 6.
- Изменение подсистем этапов 1–4 (CPU, хранение, конфигурация, загрузка), кроме точечной интеграции INT 10h, описанной выше.

## Capabilities

### New Capabilities

- `vga`: регистры и видеопамять VGA, текстовые и графические режимы, публичный API кадра для внешнего наблюдения экрана

### Modified Capabilities

- `bios`: требование «Заглушки видео и клавиатуры BIOS (INT 10h, INT 16h)» — видео-часть (INT 10h) перестаёт быть заглушкой и делегируется устройству `vga`; клавиатурная часть (INT 16h) не меняется

## Impact

- Новый пакет: `internal/vga`
- Изменяемые пакеты: `internal/bios` (реализация INT 10h через `vga`), `internal/machine` (создание и регистрация устройства VGA на шине)
- Новые данные в репозитории: встроенный растровый шрифт для текстового режима (см. design.md, Open Questions — источник/лицензия)
- Зависимости: без новых внешних Go-модулей (кодирование кадра в PNG для визуальной проверки — через стандартную библиотеку `image/png`)
