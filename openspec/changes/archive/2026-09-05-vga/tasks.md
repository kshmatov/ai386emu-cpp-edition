## 1. Устройство VGA: регистры и порты

- [x] 1.1 Новый пакет `internal/vga`: структура `VGA` с внутренним состоянием регистров CRTC (0x3D4/0x3D5 индекс/данные, 18 индексов), секвенсера (0x3C4/0x3C5, 5 индексов), графического контроллера (0x3CE/0x3CF, 9 индексов), атрибутного контроллера (0x3C0/0x3C1 с флип-флопом, 21 индекс) и DAC/misc (0x3C6 pel mask, 0x3C7/0x3C8/0x3C9 палитра, 0x3C2/0x3CC Miscellaneous Output, 0x3BA/0x3DA Input Status — по I/OAS из Miscellaneous Output выбирается адрес CRTC 0x3B4/0x3B5 или 0x3D4/0x3D5); реализация `machine.PortDevice` (критерий приёмки: тесты записи/чтения каждого блока регистров через индекс/данные, включая флип-флоп атрибутного контроллера и автоинкремент DAC после третьего байта; сценарии «Запись и чтение регистра CRTC», «Автоинкремент DAC» спеки `vga`). Выполнено: `internal/vga/vga.go`, `internal/vga/vga_test.go`. Уточнение по ходу реализации: мнемоники портов, совпадающие по адресу для чтения/записи (0x3C2 Input Status 0/Misc Output W, 0x3C7 DAC State/DAC Read Index), объявлены как отдельные именованные константы с одинаковым числовым значением (не как один алиас) — так понятнее назначение в каждом направлении, и Go допускает это без конфликта, пока обе константы не встречаются как case-метки в одном switch. Мнимо-алиасные порты CRTC 0x3B4/0x3B5 (моно) и 0x3D4/0x3D5 (цвет) реализованы как обращение к одним и тем же регистрам независимо от бита I/OAS Miscellaneous Output (упрощение: на реальном железе активен только один алиас, но ни spec, ни tasks не требуют дизейбла неактивного — усложнение не даёт наблюдаемой ценности без реального BIOS/ROM, которое бы на это полагалось).
- [x] 1.2 Видеопамять: реализация `machine.MemoryDevice` на диапазон 0xA0000–0xBFFFF (design.md D1); трансляция физического адреса в активное окно по Memory Map Select графического контроллера (design.md D2), адреса вне активного окна — чтение 0xFF, запись игнорируется (критерий приёмки: тесты на все 4 значения Memory Map Select — запись видна только в соответствующем окне; сценарий «Обращение вне активного окна памяти» спеки `vga`). Выполнено: `internal/vga/memory.go`, `internal/vga/memory_test.go` — единый плоский буфер 128 KiB на весь физический диапазон, окно ограничивает видимость; побайтовое хранение без латчей/планарности — это осознанно оставлено группе 3/4 (design.md D4), эта задача только про адресацию окна.
- [x] 1.3 Регистрация устройства VGA в `Machine.New()` (память + порты); удаление вызова `hookInt10`-заглушки из будущей интеграции не входит в эту задачу — только подключение устройства к шине (критерий приёмки: тест `Machine`, что порты/память VGA доступны и не конфликтуют с уже подключёнными устройствами хранения). Выполнено: `internal/machine/machine.go` (`vga.New()` + `bus.RegisterMemory`/`bus.RegisterPorts` для 0xA0000-0xBFFFF и портов 0x3B4-0x3B5/0x3BA/0x3C0-0x3CF/0x3D4-0x3D5/0x3DA), `internal/machine/machine_vga_test.go`.

## 2. Текстовые режимы

- [x] 2.1 Встроенный растровый шрифт 8×16 (256 глифов, CP437) как Go-данные в `internal/vga` (design.md D7 — решено: подмножество GNU Unifont 17.0.05, см. `internal/vga/testdata/font/README.md`) (критерий приёмки: тест на размер таблицы и корректную индексацию по коду символа). Выполнено на этапе планирования (до старта группы 2) — `internal/vga/font8x16.go` (сгенерирован `tools/cp437font`), `internal/vga/font8x16_test.go`, `go build/vet/test` чисты.
- [x] 2.2 Текстовый рендеринг в `Frame()` (design.md D6): для текстовых режимов — чтение пар (символ, атрибут) из видеопамяти по раскладке, зависящей от ширины CRTC (Horizontal Displayed), рендер глифа шрифтом, применение foreground/background через Attribute Controller → DAC (design.md D5) (критерий приёмки: тест, что известный байт символа+атрибута в видеопамяти даёт ожидаемые пиксели в `Frame()` для одного символа; сценарий «Текстовый вывод символа» спеки `vga`). Выполнено: `internal/vga/frame.go`, `internal/vga/frame_test.go`. Упрощение: бит 7 атрибута (blink/яркий фон) трактуется как яркий фон — `SetMode` всегда отключает Enable Blink, без модели времени кадра мигать нечем (см. design.md/text.go).
- [x] 2.3 Все стандартные текстовые режимы (40×25, 80×25, 80×43, 80×50) через `SetMode` (design.md D3) — набор регистров CRTC/секвенсера на каждый режим, включая символ-высоту (Maximum Scan Line) (критерий приёмки: табличный тест по каждому mode number — ожидаемые Horizontal/Vertical Displayed и высота символа). Выполнено с уточнением: `SetMode` (BIOS video mode number 00h/01h → 40x25, 02h/03h/07h → 80x25) реализует только те геометрии, для которых существует стандартный номер режима 00h-13h; спека vga (Scenario «Неизвестный номер режима») требует отклонять номера ВНЕ 00h-13h, но у 80x43/80x50 на реальном BIOS вообще нет отдельного номера режима в этом диапазоне (они достигаются перезагрузкой знакогенератора поверх уже установленного режима, не через AH=00h) — заводить для них выдуманные номера нарушило бы этот сценарий. Поэтому 80x43/80x50 реализованы отдельным BIOS-удобством `SetTextRows(rows)` (design.md D3, та же категория методов, что `WriteChar`/`CursorPosition`), перепрограммирующим только вертикальную развёртку поверх уже установленного текстового режима. `crtcRegCount` увеличен с 18 до 25 (см. vga.go) — без регистра 0x12 (Vertical Display End) число строк текста невозможно вычислить. Выполнено: `internal/vga/vga.go` (геометрия/CRTC-хелперы), `internal/vga/text.go` (`SetMode`, `SetTextRows`), `internal/vga/text_test.go`. **Вопрос пользователю** (не блокирует дальнейшую работу): согласны ли с этим разделением на `SetMode`+`SetTextRows`, или 80x43/80x50 предполагалось реализовать иначе?
- [x] 2.4 Аппаратный курсор: `CursorPosition`/`SetCursorPosition` (design.md D3) через регистры CRTC 0x0E/0x0F; отображение курсора в `Frame()` (критерий приёмки: тест смены позиции курсора и её отражения в кадре; сценарий «Установка позиции курсора» спеки `vga`). Выполнено: `internal/vga/text.go`, `internal/vga/frame.go` (курсор рисуется как сплошная полоса fg-цвета по скан-линиям Cursor Start/End — без модели времени кадра мигать нечем, курсор всегда «виден», если не установлен бит Cursor Disable), тесты в `internal/vga/text_test.go`/`frame_test.go`.
- [x] 2.5 `WriteChar`/`ScrollUp` (design.md D3) для текстового режима: запись символа+атрибута по (row, col) с учётом текущей ширины, прокрутка на одну строку с очисткой последней (критерий приёмки: тесты записи одиночного символа и прокрутки на границе экрана). Выполнено: `internal/vga/text.go`, `internal/vga/text_test.go`. Упрощение: Start Address (CRTC 0x0C/0x0D) игнорируется — `WriteChar`/`ScrollUp`/`Frame()` последовательно считают от начала окна памяти (см. комментарий `textCellOffset` в text.go); аппаратный сдвиг экрана через Start Address остаётся доступен напрямую через порты, но не через эти BIOS-удобства.
