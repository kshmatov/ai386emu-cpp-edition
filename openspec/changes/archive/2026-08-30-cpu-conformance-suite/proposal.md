> История Go-издания: упоминания Go-команд, путей и цифр ниже относятся к Go-реализации (ai386).

## Why

При работе над этапом 4 (BIOS) был обнаружен и исправлен баг CPU (`0x83`, иммедиат всегда 0 — см. ), который не покрывался юниттестами этапа 2, хотя в репозитории с этапа 2 вендорен эталонный набор SingleStepTests/80386 (~37 640 тестов, `internal/cpu/testdata/80386`) именно для отлова таких случаев. При его использовании он оказался структурно валидным JSON, но **не подключён как реальный conformance-раннер** — только загружается и проверяется на корректность структуры (`testdata_load_test.go`).

При подготовке раннера обнаружилось, что сам вендоренный корпус повреждён: конвертер `tools/moo2json` определяет 32-битный формат регистров условием точного совпадения строки `"386" == cpuName`, тогда как исходные MOO-файлы содержат тип CPU `"386E"` — условие никогда не срабатывает, и все 941 файла декодированы с ошибочной 16-битной раскладкой регистров вместо корректной 32-битной. Подтверждено: пересборка одного файла (`04.MOO.gz`) референсным `moo2json.py` (dbalsom/moo) даёт согласованные результаты (`eax`/`eflags` корректно отражают арифметику ADD), тогда как вендоренный `04.json` показывает одинаковый бессмысленный `final` для всех тестов файла.

Этот change чинит конвертер, перегенерирует эталонный корпус, подключает его как реальный conformance-раннер и по его результатам находит и чинит реальные баги CPU — превращая вендоренный набор из "мёртвого груза" в работающую защиту от регрессий на будущих этапах.

## What Changes

- Фикс `tools/moo2json`: определение 32-битного формата регистров через подстроку (`strings.Contains`), а не точное совпадение
- Перекачка всех 941 `*.MOO.gz` из `github.com/SingleStepTests/80386` (`v1_ex_real_mode`) и перегенерация `internal/cpu/testdata/80386/*.json` исправленным конвертером с тем же сэмплированием (40 тестов/файл), обновление README датасета
- Новый conformance-раннер в `internal/cpu`: для каждого теста — установка полного состояния CPU (регистры, сегменты, CR0/CR3/DR6/DR7, память) из `initial`, один `Step()`, сравнение итогового состояния с `final` (регистры как diff поверх `initial`, память, флаги с учётом `f_umask`/`f_tested` из `80386.csv` для не полностью определённых битов), обработка тестов с ожидаемым исключением (`exception`)
- Разбор и исправление реальных багов CPU, найденных раннером на исправленных данных

## Capabilities

### Modified Capabilities

- `cpu`: добавляется требование о соответствии эталонному набору SingleStepTests/80386 для реализованных инструкций

## Impact

- Изменяемые файлы: `tools/moo2json/main.go`, `internal/cpu/testdata/80386/*.json` (перегенерация), `internal/cpu/testdata/80386/README.md`
- Новые файлы: conformance-раннер в `internal/cpu` (новый `*_test.go` или вспомогательный файл + тест)
- Возможные изменения в остальных файлах `internal/cpu/*.go` — по мере исправления найденных багов
- Сетевой доступ требуется один раз, при перегенерации корпуса (~600 МБ трафика, временно; в репозиторий попадает только сжатый JSON-результат сэмплирования, как и раньше)
- Не реализуется в рамках этого change: полная (100%) проверка всех 2500 тестов на опкод — используется тот же вендоренный сэмпл 40/опкод, что и раньше; расширение сэмпла — отдельная задача при необходимости
