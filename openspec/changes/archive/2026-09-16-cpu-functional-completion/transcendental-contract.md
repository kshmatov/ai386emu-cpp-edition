# Численный контракт шести новых команд x87

> История Go-издания: упоминания Go-команд, путей и цифр ниже относятся к Go-реализации (ai386).

2026-09-11. Контракт задачи1.5 для функционального DX4; реализация команд3.1–3.5 остаётся открытой. Принятые F2XM1/FPATAN сохраняют свои прежние матрицы ≤2ULP.

## Документальные основания

1. [Intel Architecture Software Developer’s Manual Volume1, историческая редакция](https://courses.cs.cornell.edu/cs412/2000SP/resources/Intel%20Architecture%20Vol.%201.PDF), §7.5.10, печатная стр.7-39 (PDF175): для Intel486/387 названы ошибки вплоть до4.5ULP. Это не современная гарантия Pentium ≤1/1.5ULP и не универсальная оценка относительно математического sin при больших аргументах.
2. [Intel SDM Volume1, редакция по ссылке](https://cdrdv2-public.intel.com/671436/253665-sdm-vol-1.pdf), §8.3.8–8.3.10: внутреннее Pi и ограничения точности редукции; новые алгоритмы начиная с Pentium. Содержит точное шестнадцатеричное Pi. Термин «68-битное» относится к ширине представления; два младших бита нулевые, поэтому встречается также «66 significant bits».
3. [Intel: Difference Between x87 Instructions and Mathematical Functions](https://www.intel.com/content/www/us/en/developer/articles/technical/the-difference-between-x87-instructions-and-mathematical-functions.html): основание отдельно сравнивать периодические x87 функции и математическую тригонометрию.
4. [Intel SDM Volume2, FYL2XP1](https://cdrdv2-public.intel.com/868137/325462-089-sdm-vol-1-2abcd-3abcd-4.pdf), статья FYL2XP1, таблица3-51: диапазон ±(1−√2/2), undefined вне него; IEEE-совместимый log1p для всех x>−1 не является обязательным поведением этой команды.
5. [Intel Embedded Intel486 Developer’s Manual273021-001](https://www.ardent-tool.com/CPU/docs/Intel/486/embedded/manuals/273021-001.pdf), §4.5, гл.12 и §9.2.15: состояние, кодировки и FERR. [Реестр x87](x87-inventory.md) связывает остальные формы/исключения с задачами2–4.

## Критерий точности проекта

Для каждой из шести новых команд принимается ошибка **≤4.5ULP от независимого неокруглённого эталона**, при каждом из четырёх RC и всех трёх PC. Для неточного результата этот критерий проверяет функциональную точность; он не требует совпадения последних битов с конкретным stepping физического DX4. Выбранный предел основан на исторической оценке Intel486; для больших аргументов применяется к указанной ниже модели редукции, а не к обычной математической функции от исходного x. Это явное правило приёмки проекта, а не утверждение о доказанном верхнем пределе всех кремниевых реализаций за пределами основного диапазона.

`ULP(t)=2^max(floor(log2(abs(t)))−63,−16445)` для конечного ненулевого эталона t. Binade выбирается **до округления t в raw80**. Для результатов в subnormal-области шаг равен2^-16445. Идеальные нули, единицы, NaN/∞, знаки нуля, состояние и классы исключений проверяются отдельно точно; ULP не разрешает перепутать sign/NaN/∞ или пропустить push/pop. Для overflow и unmasked масштабирования результата действует exception-контракт, а не численное сравнение с ∞.

RC применяется в финальном округлении внутреннего приближения, PC не сокращает точность трансцендентного результата. Нельзя считать C1 современного хоста побитовым эталоном C1 физического486: при различии внутренних приближений направление финального округления может отличаться. Для выбранного алгоритма C1 должен соответствовать его финальному округлению/stack fault; неизменяемые и определённые специальные флаги проверяются точно. Неопределённые C0/C3 и, где применимо, C2 не сравниваются. Во всех точных специальных случаях проверяются также RC-независимость и EFLAGS.

## Функции и диапазоны

Здесь x=исходный ST0, y=исходный ST1. `Pi = 0xC90FDAA22168C234C / 2^66` — точное рациональное число; π в формулах ниже — высокоточная математическая константа.

| Команда | Диапазон численного эталона | Эталон и предел | Состояние при успешном завершении |
|---|---|---|---|
| FYL2X D9F1 | конечный x>0; конечный y; конечный результат | y·log2(x), ≤4.5ULP; около1 без потери малой разности | результат вместо ST1, pop1 |
| FYL2XP1 D9F9 | конечный abs(x)≤1−√2/2; конечный y; конечный результат | y·log2(1+x), ≤4.5ULP; малый x не округляется предварительно через1+x | результат вместо ST1, pop1 |
| FSIN D9FE | конечный abs(x)<2^63 | sin(x·π/Pi), ≤4.5ULP; для abs(x)≤1 также близок к обычному sin(x), но общий эталон един | ST0=result, глубина прежняя; C2=0 |
| FCOS D9FF | тот же | cos(x·π/Pi), ≤4.5ULP | ST0=result, глубина прежняя; C2=0 |
| FSINCOS D9FB | тот же | пара cos(x·π/Pi), sin(x·π/Pi), каждый ≤4.5ULP | новые ST0=cos, ST1=sin, push1; C2=0 |
| FPTAN D9F2 | тот же; соседние значения около полюсов включены | tan(x·π/Pi), ≤4.5ULP; добавляемая1 точно | новые ST0=1, ST1=tan, push1; C2=0 |

Для abs(x)≥2^63 у четырёх тригонометрических команд: C2=1, исходный raw80 и глубина сохранены, push не выполняется. Это проверка состояния без ULP. NaN/unsupported/∞ рассматриваются по классам, а не как обычный конечный range reject. FYL2XP1 вне своего диапазона: математический результат не нормируется, исключение не гарантируется; команды не заменяются #UD лишь потому, что результат undefined.

Независимый расчёт тригонометрии выбирает целое q=nearest-even(x/(2Pi)), затем r=(x−q·2Pi)·π/Pi и вычисляет sin/cos рядами. Целое q и вычитание не проходят через float64. Большие аргументы нельзя проверять как sin(x), cos(x) или tan(x) стандартной библиотеки: такая проверка отвергала бы правильный период x87.

## Конкретный воспроизводимый набор

Генератор `tools/fpu-reference/transcendental.py` записывает **960 исходных пар и11520 native снимков** (каждая пара ×3PC ×4RC). JSON `internal/cpu/testdata/fpu-reference/transcendental-plan.json` содержит raw80 входы, группы, десятичные независимые эталоны и отдельные native FSAVE108 наблюдения. `.input`/`.capture` и SHA256 исходников/данных позволяют повторить захват.

- FYL2X: x=k/16, k=1..64; 2^e для e=−16445,−16382,−100,−64,64,100,16383; y=1,−3,3/2. Отдельно x=1/2,2,3 с y=±2^16000 и±2^-16000. Всего225 пар.
- FYL2XP1: x=k/128, k=−32..32, y=1,−3,3/2; x=±2^e для e=−16445,−16382,−1000,−100,−64,−32 с y=3/2; representable точки непосредственно внутри обеих границ ±(1−√2/2). Отдельно x=±1/8 с y=±2^16000 и±2^-16000. Всего219 пар.
- Каждая тригонометрическая команда: x=k/32, k=−32..32; ±2^e для e=−16445,−16382,−1000,−100,−64. Затем prev/nearest/next raw80 вокруг n·π/2 для n=1,2,3,4,16,1024,2^32,2^60, обоих знаков. И prev(2^63),2^63,next(2^63), обоих знаков. Всего129 входов на команду.
- Все target-значения пересчитаны с180 и240 десятичными знаками; сохранённые91 значащая цифра совпали. Малый log1p считается через ряд atanh(x/(2+x)), поэтому min-subnormal не исчезает в1+x. Это проверка численной устойчивости генератора, а не формальное доказательство ошибки каждой операции Decimal.

Нативные наблюдения современного хоста — дополнительная проверка независимого расчёта. Их измеренные максимумы по текущему набору: FYL2X1.002, FYL2XP1 1.060, FSIN1.018, FCOS/FSINCOS1.021, FPTAN1.129ULP (значения округлены вверх). Ни один допуск не выбирался по падающему случаю эмулятора; шесть команд в эмуляторе пока не исполнялись. Точные числа и модель хоста находятся в metadata.

## Точные специальные и exception проверки для реализации

Эти пункты дополняют численный корпус и являются обязательной приёмкой3.1–3.5, совместно с матрицей X реестра. Наличие контракта не означает, что проверки уже проходят на CPU.

| Входы | Требование |
|---|---|
| Тригонометрия ±0 | FSIN сохраняет знак0, FCOS=+1; FSINCOS даёт +1 и исходный signed0; FPTAN даёт +1 и signed0. C2=0, глубина по команде |
| FYL2X x=2,y=3; x=1,y=±конечное | точно3; для x=1 нулевой результат с архитектурным знаком; pop1 |
| FYL2XP1 x=±0,y=±конечное | знак нуля произведения y·x; pop1; ±∞·0 вызывает IE |
| FYL2X x=±0,y=±ненулевое конечное | ZE, знак бесконечности противоположен знаку y; masked/unmasked и сохранение/pop согласно pre-computation |
| FYL2X x<0; x=1,y=±∞; x=0,y=0 | IE и masked indefinite, unmasked подавление результата; не численное сравнение |
| Trig x=±∞; SNaN/unsupported в любом источнике | IE, quieting/indefinite и stack effect по классу; ∞ не конечный range-reject |
| QNaN обоих знаков с разными payload, QNaN/SNaN перестановки бинарных команд | приоритет/selection/quieting/payload по общему raw80-контракту2.1; undefined не сравниваются |
| raw80 min subnormal, min normal, их соседи | DE входа и UE/PE результата по соответствующим маскам; не путать tiny с автоматически возникшей UE |
| FYL2X x=4,y=max finite; FYL2XP1 x=1/8,y=min subnormal | конкретные overflow/underflow стимулы, все RC, OE/UE/PE, masked finite/∞/zero/subnormal и permitted unmasked result update |
| TOP0–7, пустой ST0/ST1, полный стек перед FPTAN/FSINCOS, range-reject при полном стеке | IE/SF/C1, masked/unmasked, приоритет range/stack, неизменяемые raw и tags по документации |

Фиксированные raw80 для этих тестов: +0=`00000000000000000000`, −0=`00000000000000000080`, +1=`0000000000000080ff3f`, +∞=`0000000000000080ff7f`, QNaN=`34120000000000c0ff7f`, SNaN=`3412000000000080ff7f`, unsupported=`0100000000000000ff3f`, min subnormal=`01000000000000000000`, min normal=`00000000000000800100`, max finite=`fffffffffffffffffe7f`; отрицательный знак задаётся bit15 последнего16-битного слова. Дополнительный payload5678 обязателен для перестановок.

На каждом этапе реализации фиксируются точные ожидаемые exception кадры/статусы из соответствующей статьи Intel и bare-metal/native probes; неоднозначное поколенческое поведение не выбирается по самому эмулятору. Полная доставка #NM/#MF/IRQ13 остаётся4.7–4.8; память/окружение2.7. Историческая промежуточная оговорка #UD удаляется при итоговой синхронизации5.4, после реализации всех форм.
