# Паспорт CPU: результаты сверки и решение для приёмки

> История Go-издания: упоминания Go-команд, путей и цифр ниже относятся к Go-реализации (ai386).

2026-09-11. Статус: пользователь согласовал следование документации обычного IntelDX4; конфликт CPUID/4 МиБ разрешён изменением cpu-dx4-profile. Архитектурные различия нельзя разрешать исходя из того, что сейчас реализовано.

## Источники

1. [Intel AP-485, 241618-004](https://www.ardent-tool.com/CPU/docs/Intel/CPUID/241618-004.pdf), §3.2, таблица 3; §3.3 и таблица 5. IntelDX4 соответствует family 4/model 8; таблица не исключает для него CPUID. Stepping и feature flags нельзя получать из одного названия семейства.
2. [Intel Embedded Intel486 Developer’s Manual, 273021-001](https://www.ardent-tool.com/CPU/docs/Intel/486/embedded/manuals/273021-001.pdf), §4, §6.4.2, приложения B–D. Документ охватывает разные модели: обычные страницы 4 КиБ и отдельно расширения CR4/PSE. §4 требует проверять наличие расширений через CPUID. Таблица D-2 отличает обычный DX4 model 8 и Write-Back Enhanced model 9; текст §8 содержит другую подпись модели, поэтому не используется вместо таблицы/AP-485.

## Исходные расхождения (до cpu-dx4-profile)

| Область | Текущий код/спецификация | Что требуется до приёмки |
|---|---|---|
| CPUID/ID | i486.go: CPUID не объявлена, ID фиксирован | Для DX4 реализовать документированную идентификацию; связать ID и доступность CPUID |
| Reset signature | reset.go обнуляет GPR, включая EDX | EDX должен соответствовать выбранной документированной signature, совпадать с CPUID(1).EAX |
| Paging | базовая спека требует 4 КиБ и 4 МиБ; paging.go выбирает 4 МиБ по PDE.PS | Согласовать профиль и наличие PSE; нельзя объявлять архитектурную поддержку больших страниц только по существующему обработчику |
| CR0/CR2/CR3 | Есть реализация | Сверить определённые и зарезервированные биты, fault semantics; reset CR0 сейчас 60000010h |
| CR4 | Расширения в руководстве зависят от модели | Связать доступность с профилем, не переносить все расширения семейства автоматически |
| DR | Есть хранение и MOV | Реестр debug semantics, defined/reserved bits, GD/TF/RF и breakpoints остаётся открытым |
| TR3–TR7 | Требуется реестр | Документ содержит cache/TLB test registers; функциональная совместимость включает наблюдаемое поведение, отсутствие моделирования задержек не отменяет регистры |
| x87 | Частичная реализация | Сохранить архитектурные CW/SW/tag/TOP и исключения; полный реестр и эталоны — 1.3–1.5 |

## Согласованный профиль

Пользователь поручил следовать документации реального IntelDX4: family 4/model 8, CPUID, FPU и страницы 4 КиБ. Поддержка 4 МиБ не сохраняется как расширение. Конкретный контракт и ссылки: [cpu-dx4-profile](../archive/2026-09-11-cpu-dx4-profile/specs/cpu/spec.md).

Профиль эмулятора фиксирует signature 00000480h: family/model документированы; stepping 0 — воспроизводимый номер виртуальной ревизии, не обещание физических errata. Feature mask=1: FPU, без PSE, VME, TSC и позднейших расширений. CPUID(0) возвращает GenuineIntel/max=1, (1) — signature/features; выходы для функций вне max обнуляются как политика эмулятора, без требований к гостю использовать неопределённые функции.

## Карта регистров и системных механизмов для реестра

| Область | Контракт целевого профиля | Первичный документ и раздел |
|---|---|---|
| EAX–EDI, EIP | 32-битное состояние и 8/16-битные представления; reset EDX — signature | 273021-001, §4; AP-485 §3.2 |
| EFLAGS | Арифметика, TF/IF/DF/IOPL/NT/RF/VM/AC; ID изменяем и отражает CPUID. VIF/VIP не объявлены; зарезервированные биты не превращаются в features | 273021-001, §4, рисунки EFLAGS; AP-485, проверка ID |
| CR0 | PE/MP/EM/TS/ET/NE/WP/AM/NW/CD/PG и соответствующие переходы/исключения; остальные биты обрабатываются по reserved-bit правилам целевой модели | 273021-001, §4, Control Register 0 и таблицы 4-2–4-6 |
| CR2/CR3 | Адрес #PF; база каталога 4 КиБ, PWT/PCD; права и A/D по двухуровневым таблицам | 273021-001, §4, Control Registers 2/3; §6.4.2 |
| CR1/CR4 | CR1 зарезервирован; профиль без VME/PVI/PSE не объявляет CR4 extensions. Проверки недопустимых MOV CR — в реестре системных команд | 273021-001, §4 и примечание о model-dependent extensions |
| DR0–DR3/DR6/DR7 | Адреса точек останова, статус и управление; зарезервированные биты, GD/TF/RF и доступ CPL0 подлежат отдельным тестам. DR4/DR5 остаются принятыми i486 aliases без DE | 273021-001, §4.6 и глава 11; принятая базовая CPU-спека |
| TR3–TR5 | Cache test data/status/control для DX4; функциональные результаты тестовых операций, без моделирования задержек | 273021-001, §4.6.2, приложение B.2, рисунок B-2 |
| TR6/TR7 | TLB test command/data; права CPL0, lookup/write и результаты | 273021-001, приложение B.3.2 |
| GDTR/IDTR/LDTR/TR | Таблицы, selector/cache, ограничения и task transitions | 273021-001, §4 и глава 6 |
| x87 | ST0–ST7 extended80, CW/SW/tag/FIP/FDP/FOP; PC/RC/masks и #NM/#MF/FERR | 273021-001, §4.5, Numeric Processing и §9.2.15 |

Паспорт задаёт область проверки и не утверждает завершение реализации перечисленных механизмов. Реестр 1.2/1.3 обязан фиксировать точные маски и тесты для каждой команды, включая CR/TR/debug. Поддержка этих механизмов остаётся в задачах 4.x. Ссылки на исходные документы сохраняются в базовой CPU-спеке при синхронизации cpu-dx4-profile.
