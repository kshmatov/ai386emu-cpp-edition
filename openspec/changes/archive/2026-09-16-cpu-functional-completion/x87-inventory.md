# Реестр x87 DX4

> История Go-издания: упоминания Go-команд, путей и цифр ниже относятся к Go-реализации (ai386).

Срез 2026-09-11. Шаг 1.3 — инвентаризация форм; полнота реализации остаётся открытой. Пути Go-файлов относятся к `internal/cpu/`. Каждая строка наследует матрицу X ниже. Тесты в колонке доказательств подтверждают свои случаи, не всю строку.

## Источники

- [Intel 273021-001](https://www.ardent-tool.com/CPU/docs/Intel/486/embedded/manuals/273021-001.pdf), §12.2.4 и таблицы гл.12: кодировки x87; §4.5: состояние FPU. Ограничения модели — [паспорт DX4](cpu-profile.md).
- [Intel SDM, Volume1](https://www.intel.com/content/dam/support/us/en/documents/processors/pentium4/sb/25366521.pdf), гл.8: управляющее слово, классы, исключения, condition codes. По каждой мнемонике — [официальный указатель Volume2A/2B](https://www.intel.com/content/www/us/en/developer/articles/technical/intel-sdm.html). Поздние расширения не включаются в DX4.
- [Intel SDM, системная совместимость](https://www.intel.com/content/dam/support/us/en/documents/processors/pentium4/sb/25366821.pdf): исторические FENI/FDISI/FSETPM сохраняются как no-op в 32-битных x87; DB E0/E1 добавлены в dispatcher и проверены отдельно.
- [Intel о редукции x87](https://www.intel.com/content/www/us/en/developer/articles/technical/the-difference-between-x87-instructions-and-mathematical-functions.html): численный контракт тригонометрии отдельно устанавливается в1.5; текущий реестр не назначает универсальные ULP.

## Матрица X и маски

Каждый перечисленный opcode, размер памяти, направление, индекс i=0..7, waiting/no-wait вариант — отдельная форма. Memory формы имеют Mod=0/1/2, register формы Mod=3. Для memory форм применимы R/P/V, A16/A32, segment overrides, memory limits/#GP/#SS/#PF/#AC, fetch faults и LOCK #UD. Для register-only ESC форм 66h/67h не имеют применимого размера операнда или адреса и по Intel являются reserved; они исключены из обязательного X-oracle. Существующие decoded тесты с 66h/67h для таких форм сохраняются как проверки стабильности поведения эмулятора. O16/O32 изменяет environment/context размер, а не m32/m64/m80 ESC-операнд. [Intel REP/F3](https://www.intel.com/content/dam/www/public/us/en/documents/manuals/64-ia-32-architectures-software-developers-manual.pdf) определяет F3 только для перечисленных команд, ESC туда не входит; результат F2/F3 перед ESC архитектурно не определён и не считается допустимой формой X. Текущий #UD эмулятора остаётся допустимым вариантом. Повторные префиксы и зарезервированные формы требуют отдельной проверки поколения.

**K (входные классы):** оба знака zero/normal/subnormal/infinity/QNaN/SNaN, разные payload; min/max normal, min subnormal, raw80 unsupported и pseudo-denormal. Для бинарных форм — перестановки, cancellation, invalid pairs, переполнение и границы rounding. Integer — границы каждого signed размера и половинные значения перед округлением. BCD — 18 цифр и знак; поведение недопустимых цифр нельзя назначать по предположению.

**X (состояние/исключения):** PC24/53/64 × RC nearest-even/down/up/truncate, даже когда команда игнорирует PC/RC (проверяется независимость). PC=01B отдельно помечен [Intel Vol.1 Table 8-2](https://www.intel.com/content/dam/support/us/en/documents/processors/pentium4/sb/25366521.pdf) как reserved: это не допустимое архитектурное значение для обязательного oracle; текущее поведение эмулятора на таком входе допустимо и не засчитывается в X. TOP0–7, каждый tag, пустые источники/полный стек, destination alias ST0/STi, raw80 и guard bytes. Каждая применимая IE/DE/ZE/OE/UE/PE маска и сочетания; SF вместе с IE, C1 overflow/underflow. Проверяются ES/B, разрешённый destination update, pop/push и restart. Pre-computation и post-computation unmasked исключения не имеют единого правила rollback. Перечень исключений в строке — применимые классы, а точный приоритет/маска результата связываются с эталоном1.4/1.5 и приёмкой2.x.

Все ESC-команды дополнительно проходят #NM/#MF/legacy FERR матрицу4.7–4.8. `FN*` control варианты не ждут pending error; обычные команды ждут. **FNOP является waiting**, несмотря на N. Ассемблерные FSTCW/FSTSW/FSTENV/FSAVE/FCLEX/FINIT — отдельная 9B перед no-wait ESC: возможен fault на первой инструкции без исполнения второй. Исторические FNENI/FNDISI/FNSETPM проверены как no-op поколения; общая матрица X остаётся открытой.

EFLAGS не изменяются x87-командами этого профиля. C0=0100, C1=0200, C2=0400, C3=4000; TOP=3800. `R`: C1 rounding/stack indication в определённых случаях, C0/C2/C3 undefined, кроме отдельно указанных C2 range/remainder. `S`: C1 stack overflow/underflow indication или0 при успешной точной операции, прочие condition codes undefined. Маска сравнения C3/C2/C0 —4500; FXAM полная4700. Undefined исключены из сравнения, preserved обязательно сравниваются. Control restore/reset имеют свои явные маски. Для unmasked exceptions маски берутся из конкретного pre/post сценария, не из строки успешного результата.

## Зарезервированные и дополнительные кодировки

- D8/DC memory /0–/7 и DA/DE memory /0–/7 полностью перечислены в арифметических строках. D9 memory /0,/2–/7; DB /0,/2,/3,/5,/7; DD /0,/2,/3,/4,/6,/7; DF /0,/2–/7 покрыты соответствующими строками. Остальные memory слоты не превращаются в поздний FISTTP.
- Register D8 C0–FF — обычная арифметика/compare. DC C0–CF/E0–FF — обратные назначения; DC D0–DF принимаются текущим basicFPU как недокументированные алиасы FCOM/FCOMP. Таблица форм Intel DX4 их не перечисляет и не устанавливает обязательный #UD, поэтому они не входят в множество допустимых форм X. DE C0–CF/E0–FF — pop арифметика, DE D9 — FCOMPP; остальные reserved.
- D9 C0–CF/D0/E0/E1/E4/E5/E8–EE/F0–FF перечислены; D9 D1–DF/E2/E3/E6/E7/EF — reserved или алиасы, отдельно от основного контракта. Все шесть ранее отсутствовавших форм F0–FF реализованы и имеют scoped тесты.
- DD C0–C7/D0–EF — FFREE/FST/FSTP/FUCOM/FUCOMP; DD C8–CF сейчас исполняет FXCH как алиас. DA E9 — FUCOMPP; DA C0–DF поздние FCMOV. DB E0–E4 — исторические control/no-op, DB C0–DF поздние FCMOV, DB E8–F7 поздние FUCOMI/FCOMI. DF E0 — FNSTSW AX; DF C0–C7 FFREEP и другие алиасы требуют сверки, DF E8–F7 поздние FUCOMIP/FCOMIP. Отсутствующий алиас не объявляется документированной обязательной формой без источника, а реализованный не считается автоматически правильным.
- Отрицательная матрица включает все остальные D8–DF ModRM, приоритет #UD/#NM/pending/fetch и отсутствие side effect. `basicFPU == true` не доказывает правильность семантики или принадлежность DX4.

## Сохранённые доказательства и открытые места

- `fpu_exponential_test.go:TestF2XM1NativeMatrix` + `testdata/f2xm1-native.txt`: 396 записей, прежний допуск ≤2ULP. `fpu_atan_test.go:TestFPATANNativeMatrix` + `testdata/fpatan-native.txt`: 1452 записи, ≤2ULP. Эти допуски не распространяются на остальные команды.
- FPATAN дополнительно проверяет NaN selection/payload, unsupported, pre/post unmasked effects; [архив](../archive/2026-09-11-fpu-arctangent/acceptance.md) сохраняет приёмку. FPREM/FPREM1/FXTRACT и BCD сохраняют собственные targeted тесты.
- Context/environment тесты сохраняют проверки форматов, raw80 и атомарности памяти. Полные FIP/FDP/FOP правила, включая команды без memory operand и подавленный результат, остаются2.7.
- `binary`, `compare`, преобразования store и `FXAM` пока не имеют единого raw80 контракта. Например, nil объединяет различные NaN/unsupported классы; существование case не закрывает2.1–2.6.
- Legacy DB E0/E1 реализованы как no-wait no-op с регрессиями. Недокументированные register aliases не принимаются как обязательные формы без источника. Полнота FPU не может быть закрыта после одних scoped проверок.

Scoped задачи 2–4 завершены, но их тесты подтверждают только свои условия. Общая матрица X по всем допустимым формам остаётся открытой до 5.4; статус каждой строки не расширяется автоматически до полного X.
