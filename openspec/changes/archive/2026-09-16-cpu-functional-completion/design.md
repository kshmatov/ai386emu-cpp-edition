## Context

Мотивация — proposal.md. Объём соответствует roadmap 2.2/2.7/2.8/2.5 и согласованной функциональной совместимости. Кодирование в ходе подготовки этих документов не выполняется.

На 2026-09-11 basicFPU не принимает D9 F1/F2/F9/FB/FE/FF. Общие binary/compare/store пути ещё не покрывают всю матрицу исключений и raw NaN. В stubs.go guard delivering глобальный. В io.go обращения используют общий checkIOPL; разрешения отдельных портов TSS требуют продолжения. Наличие реализации task gate не доказывает полноту переключений.

## Goals / Non-Goals

**Goals:** закрыть конкретные пробелы через небольшие изменения внутри существующего CPU и воспроизводимые эталоны; сохранить принятые проверки.

**Non-Goals:** переносить эмуляцию на хостовую FPU, добавлять runtime-зависимость от QEMU или нативного x87, менять контракт виртуального времени. Хостовый x87 используется для генерации данных, которые затем читаются обычными Go-тестами на любой платформе.

## Decisions

### 1. Сначала реестр покрытия

Единица реестра: mnemonic + encoding/group + register/memory + размер операнда/адреса + режим. Для каждой строки указываются источник, реализация, тест, исключения, маска определённых флагов и статус: принято / частично / отсутствует / требуется сверка. Неопределённые и недопустимые кодировки обозначаются отдельно с основанием; они не считаются пропущенными допустимыми инструкциями.

Альтернатива — считать opcode handler достаточным — отвергнута: один обработчик обслуживает формы с разной семантикой и fault-поведением. 37640 conformance случаев сохраняются целиком, но не заменяют реестр.

| Группа | Уже есть подтверждение | Остаток проверки |
|---|---|---|
| Целочисленная арифметика, BCD, bit/shift, перемещения, строки, flow | Conformance и отдельные регрессии | Все формы, префиксы, LOCK/REP, границы, fault/restart и определённые флаги |
| Сегменты, paging, privilege | OS и targeted тесты | #AC, системные обращения, task switch, вложенные faults, все privilege/limit случаи |
| IRQ, NMI, debug | IRQ и STI/SS shadow | NMI blocking/IRET, TF/RF, DR breakpoints/GD, приоритеты |
| Системные команды и модель | SMSW, selectors, DR, AC и другие scoped changes | CPUID/ID/reset signature, ICEBP, CR/TR, cache/TLB semantics и принадлежность модели |
| x87 load/store, arithmetic, compare, stack, constants | Частичные матрицы и ОС | Исключения, raw-классы, PC/RC, pop/rollback каждой формы |
| x87 context/control | Форматы environment/save, #NM/#MF | Полная матрица waiting/no-wait, указатели, приоритеты, legacy IRQ13 |
| x87 F2XM1/FPATAN/FPREM/FPREM1/FXTRACT | Принятые scoped тесты | Включение в общий реестр, совместимость общих исправлений |
| x87 FYL2X/FYL2XP1/FPTAN/FSINCOS/FSIN/FCOS | Отсутствуют | Реализация и полная приёмка |

Проверка оставшейся системной матрицы после task switch разбита на пять
последовательных шагов: (a) #AC и приоритет #PF; (b) paging и сегментные
права; (c) системные команды и модель DX4, включая MOV TR; (d) reserved
кодировки, ModRM и префиксы; (e) итоговая сверка результатов (a)–(d) с
относящимися строками реестра. Шаг (e) принимает только системные пробелы,
выявленные в этих шагах: у каждого должно быть исправление и регрессия либо
документированное исключение профиля. Полная матрица M всех допустимых форм
не сокращается и принимается отдельной итоговой задачей 5.4.

### 2. Системная совместимость проверяется по документам целевого поколения

До изменения model-specific поведения составляется паспорт DX4: источник, допустимые команды, reset signature, CPUID/ID, reserved bits, paging и доступные системные механизмы. Название i486 не выводится из того, как Linux распознал текущую реализацию.

Отдельно разрешить обнаруженные несоответствия: i486.go не объявляет CPUID, а базовая спека обещает 4 МиБ paging. Это пока результаты аудита, не разрешение молча удалить существующее требование или включить новые возможности. Точная дельта по подтверждённому паспорту оформляется до соответствующего изменения поведения; если источники допускают несколько несовместимых профилей, выбор предъявляется пользователю вместе с конкретными различиями. Работы над общими инструкциями и FPU от этого не зависят.

### 2a. SMM/RSM отложены отдельным изменением

Пользователь выбрал не реализовывать SMM в текущей версии. Физический
IntelDX4 поддерживает SMM; это ограничение области текущего изменения, а не
изменение паспортной модели. До отдельной спецификации CPU не принимает SMI,
не создаёт SMRAM и сохраняет `RSM` (0F AA) как #UD вне SMM. Следующее
изменение должно определить источник SMI, расположение/защиту SMRAM,
save-state DX4, вход/выход и взаимодействие с paging и прерываниями.

### 3. Общая обработка x87 вместо отдельных исключений для каждой новой команды

Сохранить internal/cpu; вынести общие операции классификации extended80, выбора NaN, округления и завершения исключения в небольшие внутренние функции. Команда задаёт операнды, требуемую точность, допустимые исключения и изменение стека. Окружение и указатели остаются ответственностью общего декодирования/исполнения FPU.

Сначала формируется результат операции, затем фиксируются разрешённые изменения. Не использовать общий откат при любом unmasked exception: pre-computation и post-computation исключения имеют разное поведение. Атомарность памяти и отдельное обновление SW проверяются явно. Альтернатива копирования специальных обработчиков в каждую команду создаёт различия в NaN/rounding и усложняет регрессии.

### 4. Матрица эталонов

| Ось | Обязательные случаи |
|---|---|
| Управление | PC 24/53/64; RC nearest-even/down/up/truncate; каждая mask отдельно и совместные исключения |
| Классы | ±0, ±1, normal, min/max normal, subnormal, min subnormal, ±infinity, QNaN/SNaN обоих знаков с разными payload, unsupported encodings |
| Стек | TOP 0–7, свободный/полный/пустой стек, pop/no-pop, теги, stale raw values |
| Память | real32/64/80, int16/32/64, BCD, 14/28 и 94/108 байт; границы страниц, сегментов, read-only и missing |
| Состояние | CW/SW/tag/TOP, определённые C0–C3, FIP/FDP/FOP, destination, неизменяемые регистры и guard-байты |
| Исключения | IE/DE/ZE/OE/UE/PE/SF; #NM/#MF; NE=0 IRQ13; приоритет памяти/доступности/ожидающей ошибки |
| Численные границы | Половина ULP, cancellation, ±1 и область FYL2XP1, квадранты/полюса, ближайшие representable значения по обе стороны границ редукции |

Точный результат и определённые статусы сравниваются побитово для обычной арифметики, преобразований и контекста. Эталон включает исходные 80-битные байты; float64 не используется как промежуточный формат проверки extended.

Для трансцендентных функций перед реализацией фиксируется эталон отдельно для каждого диапазона: входы, точность, rounding, допустимое отклонение в ULP и документированное основание. Уже принятые F2XM1/FPATAN сохраняют свои матрицы ≤2 ULP; переносить этот допуск на все инструкции и весь диапазон без обоснования нельзя. Для тригонометрии проверяется архитектурная редукция с приближением π, а не только близость к математическому sin/cos/tan. Неопределённые флаги не сравниваются; маска имеет ссылку на источник. Увеличивать допуск после обнаруженного падения без анализа причины запрещено.

Native x87 генератор сохраняет исходник, модель CPU хоста, CW, вход/выход/SW, команду и hash данных. Для системных режимов используются маленькие гостевые тесты и QEMU с записанной версией/моделью. При расхождении первичен контракт Intel нужного поколения; QEMU и современный хост не определяют автоматически DX4. Независимый высокоточный численный расчёт проверяет выбранный допуск и редукцию.

### 5. Доставка исключений и гостевая приёмка

Guard вложенности принадлежит CPU. Тесты нескольких экземпляров исполняют faults одновременно под race. NMI и legacy FPU error подключаются через явные сигналы CPU/Machine к существующему PIC, с тестами очистки, масок и повторной доставки; архитектуру SB16/DMA это не затрагивает.

Гостевая программа для Linux DSL и FreeBSD проверяет арифметику, шесть новых команд, сохранение/восстановление окружения и сигналы ошибок, записывает результат на HD. Bare-metal тест проверяет privileged NE=0/#NM/#MF и системные переходы, которые пользовательская программа не может настроить. Итоговый прогон повторяет обе HD-загрузки, команду и сохранность файла на финальной сборке.

## Risks / Trade-offs

### Уточнение FreeBSD-приёмки после диагностических запусков

Подпункты 5.1a–d и 5.2a–b фиксируют проблемы наблюдаемости длительного
прогона, достоверности guest ABI/отчёта и повторного использования рабочих HD.
Проверка сначала подтверждает write/exit без x87, затем согласованность
текста отчёта с кодом завершения и только после этого локализует возможный
сбой CPU. Код `1` без корректного отчёта не является доказательством отказа
FYL2X. Прохождение коротких CPU-тестов не заменяет исходный гостевой сценарий.
Для длительных команд сохраняются идентификатор сессии и конечный статус;
выход инструмента из ожидания не считается завершением процесса.
Постоянный отчёт читается повторно после штатной остановки и загрузки того
же рабочего HD. Причина fsck-предупреждений проверяется отдельно; базовый
образ и полная копия идентифицируются до запуска. Это уточнение способа
приёмки, без изменения CPU-контракта proposal/spec и объёма обеих ОС.

- [Современный x87 отличается от DX4] → фиксировать модель эталона, сверяться с Intel и не требовать совпадения неопределённого поведения.
- [Планирование принято за полноту] → все задачи реализации остаются открыты; roadmap 2.7 закрывается только после реестра, численных критериев и согласованного полного контракта.
- [Исторические дельты CPU пересекаются] → перед синхронизацией объединить уже принятые scoped requirements, заменить промежуточные исключения FPU и не потерять регрессии.
- [Аудит обнаружит дополнительные допустимые команды] → включить их в реестр и явные задачи до приёмки; отсутствие теста не считать исключением из объёма.

## Migration Plan

Последовательные изменения в текущей feature-ветке, без автоматических коммитов. Каждый шаг: регрессия, реализация, тесты, vet, исправление, приёмка, журнал. Образы принятых ОС сохраняются; новые прогоны используют рабочие копии. При ошибке исправляется текущий шаг без разрушительного отката общей рабочей ветки.

- [Intel Embedded Intel486 Developer’s Manual, копия документа Intel 273021-001](https://www.ardent-tool.com/CPU/docs/Intel/486/embedded/manuals/273021-001.pdf): первичный документ для предстоящей сверки профиля; паспорт модели должен указывать конкретные разделы и вариант DX4.
- Локальные доказательства: internal/cpu/testdata/80386/README.md, f2xm1-native.txt, fpatan-native.txt и отчёты принятых fpu-* changes. Они подтверждают только перечисленные случаи.
