## Context

См. proposal.md. Machine.Run владеет CPU и устройствами; прямое чтение VGA из GUI создало бы data race. GUI должен работать на главном потоке ОС.

## Goals / Non-Goals

Цель — окно и физический ввод поверх существующих устройств. Новые видеорежимы и эмуляция мониторных таймингов сюда не входят.

## Decisions

- Ebitengine v2.10.1: окно, масштабирование nearest-neighbor и ввод в одном Go backend. SDL потребовал бы отсутствующий SDL2 SDK. Предпочтение Ebitengine предложено пользователю; при отсутствии альтернативного ответа используется этот вариант.
- Backend собирается с `-tags desktop`; обычная сборка сохраняет headless без зависимости от DISPLAY при инициализации. Запрос окна без тега возвращает понятную ошибку до создания дисков. `display` = headless (default) / window, `display_scale` = 1..4 (default 1), `display_fps` = 1..120 (default 30); CLI имеет приоритет над TOML, пустые значения недопустимы.
- Machine.RunInteractive обслуживает ограниченную очередь запросов ввода и кадров между порциями CPU. GUI запрашивает новый снимок, владелец VM вычисляет Frame и передаёт отдельный RGBA буфер. Отмена и Stop освобождают ожидающих; прямые устройства не становятся concurrent-safe.
- `internal/frontend` содержит независимые от окна управление сеансом и преобразование скан-кодов. Desktop-файл содержит только Ebitengine adapter, без CPU-доступа. GUI запускает RunInteractive в worker, завершает контекст и дожидается worker при закрытии окна.
- Физические позиции клавиш передаются как set-1 make/break, включая E0, Pause и PrintScreen. Повтор удержания реализует frontend (500 мс, затем 30 Гц), переключатели не повторяются. Потеря фокуса освобождает клавиши/кнопки; возврат фокуса не переигрывает уже удерживаемые клавиши до отпускания.
- Клик захватывает относительную мышь; правый Ctrl — зарезервированная клавиша освобождения (в гостя не передаётся). Потеря фокуса снимает захват; движения Y инвертируются для PS/2, большие приращения разбиваются на пакеты без потери расстояния.
- Оконная приёмка использует короткую гостевую программу: текст, графика, чтение клавиатуры/мыши и запись результата на диск. Длительная загрузка DSL уже принята отдельно; полноценная HD-сессия остаётся roadmap 9.1.

### Дефект, выявленный при приёмке

INT 10h AH=00h очищал текстовые атрибуты в 00h; последующий AH=0Eh сохранял их и рисовал чёрным по чёрному. Исправление находится в BIOS: заполнение видимой текстовой области пробелами/07h после SetMode. Низкоуровневый VGA API очистки остаётся прежним. Проверки: отдельная BIOS-регрессия, видимые пиксели гостевого кадра, реальное окно. Основание: SeaBIOS clear_screen использует 0x0720 для текста (https://qemu.googlesource.com/seabios-hppa/+/refs/tags/rel-1.6.3.1/vgasrc/vgafb.c).

## Risks / Trade-offs

- Linux требует X11/OpenGL → документировать зависимости и отдельную desktop-сборку; проверить реальное окно.
- Частая генерация кадра замедляет CPU → ограничить частоту настройки, обрабатывать CPU порциями, без mutex на каждую инструкцию.
- Polling GUI может пропустить нажатие короче одного tick → частота ввода 120 Гц независимо от обновления VGA.
- Утеря отпускания при смене фокуса → тесты сброса состояния и повторного входа, ручная оконная проверка.
