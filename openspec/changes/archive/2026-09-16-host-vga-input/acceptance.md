# Приёмка окна VGA и ввода хоста — 2026-09-11

> История Go-издания: упоминания Go-команд, путей и цифр ниже относятся к Go-реализации (ai386).

Реализован оконный frontend Ebitengine v2.10.1 (`-tags desktop`), конфигурация display/scale/fps, безопасный Console/RunInteractive, клавиатура set 1 и относительная трёхкнопочная PS/2-мышь. Правый Ctrl освобождает захват; потеря фокуса отпускает клавиши и кнопки. Закрытие окна завершает VM и закрывает диски.

## Результат

**PASS** — короткая гостевая программа, загруженная с HD, показывает текст, переключается в mode 13h и обратно, читает порты PS/2 и записывает принятые байты во второй сектор HD. После закрытия окна тест проверяет сохранённый сектор.

- Обычные клавиши: make/break A и T достигли гостя.
- Shift удерживался при переводе фокуса в отдельное тестовое окно; гость получил break, модификатор не залип.
- Клик захватил мышь; три кнопки доставлены как PS/2-биты 1/2/4.
- Движение XTest (+40,+20) доставлено как X=40,Y=-20 без потери расстояния.
- Правый Ctrl освободил захват при удерживаемой левой кнопке и передал её отпускание; сам Ctrl в гостя не попал.
- Изменение окна на 900x500 сохранило пропорции и добавило боковые поля; текст и графика проверены визуально по PNG.
- WM_DELETE_WINDOW завершил процесс с кодом 0; записи гостя прочитаны из файла после завершения.

## Проверки

Успешны `go test ./... -count=1`, `go test -race ./...`, `go vet ./...`, `go build ./...`, desktop build/vet и тесты frontend/main с тегом desktop, в том числе race. OpenSpec strict: 24/24. Обычные тесты включают сквозной запуск того же гостя без GUI, независимость снимков, порядок ввода, отмену/Stop, фокус, повтор, специальные клавиши и конфигурацию. Pause/PrintScreen проверены точными последовательностями PS/2. Недоступный backend отклоняется до создания диска.

```sh
go build -tags desktop -o /tmp/ai386-desktop ./cmd/ai386
DISPLAY=:99 python3 tools/frontend-smoke/check.py /tmp/ai386-desktop /tmp/ai386-window-report
DISPLAY=:99 go test -race -tags desktop ./internal/frontend ./cmd/ai386
```

Оконная приёмка выполнена автоматически через X11/XTest в отдельном Xvfb :99 (1280x800x24); снимки проверены визуально. Это события оконной системы хоста, не вызовы Machine.KeyEvent из теста. Ручное нажатие физических устройств человеком не выполнялось. В исходном WSLg DISPLAY=:0 окно показывало текст, но отсутствовал X11 keycode для A, поэтому полный ввод проверялся в Xvfb. Системные пакеты не установлены: Xvfb/XKB и две библиотеки распакованы в /tmp и запущены в bubblewrap с временным /usr/bin.

## Исправленные дефекты

Оконный прогон обнаружил чёрный текст после INT 10h AX=0003h: BIOS сохранял обнулённые атрибуты VGA, и AH=0Eh рисовал чёрным по чёрному. BIOS теперь заполняет текстовую область пробелами/07h. Регрессионный BIOS-тест и проверка видимых пикселей гостевого кадра сначала падали, после исправления проходят. Низкоуровневый VGA.SetMode по-прежнему очищает VRAM.

У теста скорректирована частота опроса кадра: запросы каждую миллисекунду под race отнимали время у гостевой отрисовки; теперь проверяется результат с разумным интервалом и пределом ожидания. Обнаружение окна использует ASCII-заголовок.

## Граница приёмки

Приняты roadmap 5.6 и 6.6. Не заявляются полнота всех VGA-режимов, новые SVGA-режимы, колесо мыши, аппаратная точность таймингов, рабочая Linux/FreeBSD-сессия с HD или ручная интерактивная сессия DSL в новом окне. Предыдущая загрузка DSL до shell остаётся отдельной приёмкой.
