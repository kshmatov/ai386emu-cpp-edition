# Proposal: Input — интерактивный ввод в виртуальном времени

> История Go-издания: упоминания Go-команд, путей и цифр ниже относятся к Go-реализации (ai386).

Объединение работ по системе `input`. Исходный scoped change:
`interactive-input-virtual-hold`.

---

## Why

Пользователь: после `Esc → Quit → Y` в Doom чёрный экран и «всё виснет»
при `ai386-desktop` (конфиг `freedos-ready.toml`, `clock_hz` по умолчанию
100 МГц).

Headless-воспроизведение (2026-10-15, копия HD):

| clock_hz | Навигация | Результат |
|---|---|---|
| 1 МГц | Esc, 5×Down, Enter, Y | **PASS**: BDA449=03, 720×400, ENDOOM, `C:\DOOM>` |
| 100 МГц (default) | те же scancode, 3×10⁶ шагов/клавишу | **FAIL**: BDA449=13, 320×200, EIP в игровом цикле, «чёрный» текстовый дамп |

Замер производительности (2026-10-15, 12 ядер):

| Цикл | steps/s | cycles/s | virtual/real при 100 МГц |
|---|---|---|---|
| mem RMW loop + STI | ~4.2×10⁶ | ~8.5×10⁶ | **0.085×** |
| INT 1A poll | ~5.6×10⁶ | ~0 (hook без bus cycles) | ~0× |

Вывод: эмулятор даёт ~8.5 MIPS. При `clock_hz=100 МГц` виртуальное время
идёт ~12× медленнее wall-clock. Нажатие клавиши 100–200 мс wall — это
8–16 мс виртуального времени; игровой тик Doom (35 Гц ≈ 28 мс) **не
успевает** считать make/break. Часть Down/Enter/Y «теряется», меню
уходит не в Quit, гость остаётся в mode 13h — пользователь видит чёрный
экран и «зависание».

Это также объясняет ~48 с «зависания» FreeDOS-MBR (54 тика INT 1Ah):
3 с виртуального времени при 0.085× real ≈ 35–48 с wall.

Демо/таймдемо при 1 МГц проходят: там нет «человеческих» пауз, бюджет
задаётся шагами. Оконная приёмка Doom (`tools/doom/window.py`) держит
клавиши XTest на wall-clock — при 1 МГц хватает, при 100 МГц тот же
эффект потери нажатий.

## What Changes

- Make/break PS/2 SHALL наблюдаться гостем не короче согласованного
  минимума **виртуального** времени (или пока гость не прочитал байт и
  не прошёл минимум), а не только в пределах wall-удержания хоста.
- Регрессия интерактивного выхода Doom (Esc→Quit→Y) при `clock_hz=100 МГц`
  и `1 МГц`: текстовый режим, BDA449=03, DOS prompt.
- Замер производительности фиксируется в отчёте; рекомендации `clock_hz`
  для интерактивной игры — в README (не обязательное изменение default).

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `ps2` (или `input`): удержание скан-кода в виртуальном времени.
- `machine-core`: продвижение/лечение ввода относительно виртуального
  времени так же, как PIT/SB16.

## Impact

`internal/ps2`, `internal/frontend` (длительность событий), регрессии
`tools/doom`, возможно `internal/machine`. Гостевой ABI Doom не меняется.
Производительность интерпретатора — см. отчёт; JIT не входит.

## Non-goals

- JIT/динамическая трансляция и «честный» 100 MIPS.
- Изменение default `clock_hz` (можно отдельным change после замеров).
- Патчинг гостевого Doom или пропуск меню.
- Синхронизация wall-clock с виртуальным временем.
