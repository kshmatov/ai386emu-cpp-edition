## Context

См. proposal.md. Код имеет opcode CPUID без dispatch, PUSHFD маскирует ID, POPFD/IRETD его не восстанавливают; paging включает неподдержанный путь 4 МиБ.

## Goals / Non-Goals

**Goals:** согласовать идентификацию и трансляцию целевого CPU без новых зависимостей.
**Non-Goals:** завершать весь реестр CPU либо моделировать физический cache timing.

## Decisions

Фиксированный паспорт в internal/cpu: family/model и FPU-only features, общая signature reset/CPUID. Stepping 0 обозначает виртуальный профиль. Альтернатива произвольной конфигурации feature bits отвергнута: она позволяет объявить отсутствующие инструкции.

Изменить только бит ID в существующих путях EFLAGS, сохранив остальную семантику. Удалить 4 МиБ ветку; зарезервированный PDE bit7 не выбирает большой размер, обход остаётся двухуровневым. Тесты старой большой страницы заменить проверками обхода PTE, прав и A/D при установленном bit7; не удалять матрицы разрешений.

## Risks / Trade-offs

- [Корпус 386 проверяет другой ID] → различие профилей отражается в раннере только для EFLAGS.ID с документированным основанием, если корпус затронут; остальные флаги неизменны.
- [Изменение идентификации меняет гостевые ветви] → тест реального цикла определения CPU, общий machine-прогон, затем гостевая проверка в итоговой приёмке CPU.
