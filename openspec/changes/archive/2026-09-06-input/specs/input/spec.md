# input Specification

## Purpose

Ввод клавиатуры и мыши в гостевую операционную систему: программный API подачи событий от хоста, устройство PS/2 (контроллер, клавиатура, мышь) и прерывания ввода IRQ1/IRQ12 через контроллер 8259.

## ADDED Requirements

### Requirement: Подача событий ввода (программный API)

Эмулятор SHALL предоставлять публичный программный API виртуальной машины, через который источник (тест или внешний фронтенд) передаёт события клавиатуры и мыши, и SHALL помещать эти события в очередь отправки контроллеру PS/2, откуда их забирает гостевая операционная система.

#### Scenario: Подача нажатия клавиши
- **WHEN** через программный API машины подаётся событие нажатия клавиши (скан-код набора 1)
- **THEN** гостевая ОС получает make-скан-код этой клавиши: байт становится доступен чтением порта контроллера PS/2, и генерируется прерывание IRQ1

#### Scenario: Подача события мыши
- **WHEN** через программный API машины подаются приращение координат и/или нажатия кнопок мыши
- **THEN** гостевая ОС получает пакет PS/2 с соответствующим приращением и битами кнопок через порт контроллера PS/2, и генерируется прерывание IRQ12

### Requirement: Контроллер PS/2 (8042)

Эмулятор SHALL предоставлять контроллер PS/2 с регистрами данных (порт 0x60) и статуса/команд (порт 0x64), буфером вывода, байтом команды контроллера, поддержкой двух портов (клавиатурного и мышиного) с переключением через команду 0xD4, как на стандартной PC-системе.

#### Scenario: Чтение байта из буфера вывода
- **WHEN** буфер вывода контроллера не пуст
- **THEN** чтение порта 0x60 возвращает следующий байт буфера, статусный бит «output buffer full» снимается, а чтение порта 0x64 возвращает статус с установленным битом «output buffer full»

#### Scenario: Запись байта команды
- **WHEN** гостевая ОС пишет команду в порт 0x64 и, для команд с параметром (например, запись байта команды 0x60), параметр в порт 0x60
- **THEN** контроллер выполняет команду и изменяет своё состояние в соответствии с реальным контроллером (байт команды, перевод скан-кодов, разрешение/запрет мышиного порта)

#### Scenario: Переключение на мышиный порт
- **WHEN** гостевая ОС отправляет команду 0xD4 в порт 0x64
- **THEN** следующий байт, записанный в порт 0x60, адресуется мышиному порту, и статус помечает данные мыши

#### Scenario: Данные от мышиного порта
- **WHEN** данные буфера вывода получены от мышиного порта
- **THEN** статусный байт отмечает эти данные как мышиные (bit 5), позволяя гостевой ОС отличить их от клавиатурных

### Requirement: Клавиатура PS/2

Эмулятор SHALL передавать гостевой ОС нажатия и отпускания клавиш в виде скан-кодов набора 1 через контроллер PS/2, включая make/break-коды и модуляцию залипающих модификаторов.

#### Scenario: Передача нажатия клавиши
- **WHEN** событие нажатия клавиши подано через программный API
- **THEN** контроллер PS/2 выдаёт make-скан-код клавиши из набора 1, генерируя прерывание IRQ1

#### Scenario: Передача отпускания клавиши
- **WHEN** событие отпускания ранее нажатой клавиши подано через программный API
- **THEN** контроллер PS/2 выдаёт break-скан-код (старший бит установлен), генерируя прерывание IRQ1

#### Scenario: Залипающие модификаторы
- **WHEN** подано нажатие клавиши-модификатора (Shift, Ctrl, Alt) и в период, пока она удерживается, подаются нажатия других клавиш, а после — её отпускание
- **THEN** модификатор считается активным от make до break-скан-кода, и состояние активных модификаторов отражается в BIOS-сервисе состояния клавиатуры

#### Scenario: Переключающие модификаторы
- **WHEN** подаётся нажатие переключающей клавиши (Caps Lock, Num Lock, Scroll Lock)
- **THEN** её состояние залипает и переключается при каждом нажатии, не требуя отпускания для смены состояния

### Requirement: Мышь PS/2

Эмулятор SHALL передавать гостевой ОС движение и нажатия кнопок мыши через контроллер PS/2 в виде потоковых пакетов PS/2 с приращением координат по осям и битами кнопок.

#### Scenario: Передача движения
- **WHEN** событие движения мыши подано через программный API
- **THEN** гостевая ОС получает пакет PS/2 с приращением координат по осям X и Y со знаком и корректными битами переполнения

#### Scenario: Передача нажатия кнопки
- **WHEN** событие нажатия кнопки мыши подано через программный API
- **THEN** гостевая ОС получает пакет PS/2 с установленным битом этой кнопки

### Requirement: Прерывания ввода (контроллер 8259)

Эмулятор SHALL уведомлять гостевую ОС о событиях ввода через контроллер прерываний 8259, как на реальной машине: IRQ1 — клавиатура, IRQ12 — мышь, с программируемой базой векторов, маскированием и подтверждением конца прерывания (EOI). Контроллер SHALL программироваться гостевой ОС через порты 0x20/0x21 (master) и 0xA0/0xA1 (slave).

#### Scenario: Доставка прерывания с программируемым вектором
- **WHEN** гостевая ОС запрограммировала контроллер на базу векторов и подано событие ввода
- **THEN** CPU получает запрос прерывания с вектором, равным базе плюс номер линии (IRQ1 — база+1, IRQ12 — база+12), и при открытых прерываниях доставляет его обработчику ОС

#### Scenario: Маскирование линии прерывания
- **WHEN** гостевая ОС установила маску запрета на линию (IRQ1 или IRQ12)
- **THEN** прерывание по этой линии не доставляется CPU до снятия маски, при этом само событие ввода не теряется и может быть доставлено после снятия маски

#### Scenario: Подтверждение конца прерывания (EOI)
- **WHEN** обработчик гостевой ОС завершил обработку прерывания и отправил подтверждение EOI в порт контроллера
- **THEN** контроллер снимает линию из обслуживания и вновь позволяет доставку последующих событий ввода по этой линии

#### Scenario: Каскадирование slave-контроллера
- **WHEN** событие мыши подано на линию IRQ12 slave-контроллера
- **THEN** прерывание доставляется через каскадную линию IRQ2 master-контроллера с учётом приоритета и маскирования обоих контроллеров
