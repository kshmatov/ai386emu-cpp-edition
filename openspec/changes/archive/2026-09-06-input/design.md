# Design: input

> История Go-издания: упоминания Go-команд, путей и цифр ниже относятся к Go-реализации (ai386).

## Context

Этап 6 роадмапа. Гостевая ОС (Linux/FreeBSD) потребляет ввод тремя путями: (1) после загрузки — собственные обработчики IRQ1/IRQ12, которые читают порты 0x60/0x64 и зависят от корректной эмуляции 8042 и 8259; (2) в реальном режиме — сервисы INT 16h. Текущее состояние: CPU имеет интерфейс аппаратных прерываний `RequestInterrupt(v uint8)` с доставкой между инструкциями в `Run()` (IF-гейтинг, снятие HLT, доставка по IVT/IDT) — менять CPU не нужно. Нет ни PIC, ни 8042, ни пути ввода с хоста; INT 16h — синтетическая заглушка без реальных данных. Фронтенда (GUI) в роадмапе нет — ввод подаётся программно (решение пользователя).

## Goals / Non-Goals

**Goals:**
- Гостевая ОС получает ввод так же, как на реальной PC: клавиатура и мышь через PS/2 (8042), прерывания через 8259 (IRQ1/IRQ12), с программной базой векторов и EOI.
- Программный API подачи событий на `internal/machine` для тестов и будущего фронтенда.
- INT 16h работает на реальных данных устройства.

**Non-Goals:**
- Реальный ввод с клавиатуры/мыши хоста (GUI-фронтенд вне роадмапа).
- Наборы скан-кодов 3 и переключение наборов ПО; поддержка только набора 1 (с опциональным «translation», как у реального 8042).
- APIC/ACPI, joystick, сенсорный ввод.
- DMA (этап SoundBlaster16), влияние на порядок IRQ3–7/10–15 вне ввода.

## Decisions

### D1: Контроллер 8259 — `internal/pic`, master+slave в каскаде
Полноценная эмуляция 8259 как двух устройств в каскаде (IRQ2 — линия каскада):
- Порты: master 0x20 (команды/OCW2/OCW3) и 0x21 (ICW1/OCW1), slave 0xA0/0xA1.
- Программирование ICW1–ICW4: база векторов (ICW2), каскад (ICW3), режимы (ICW4). OCW1 — маска, OCW2 — EOI/ROI, OCW3 — чтение ISR/IRR, спецмаска.
- Эмуляция IRR/ISR, разрешающая логика приоритета (сравнение уровней + маска + каскад).
- Внешний интерфейс: линии `RaiseIRQ(level)`; при решении «доставить» вызывает `cpu.RequestInterrupt(base+level)`.
- Модель edge-триггера: подъём линии ставит IRR-бит; снятие ISR (EOI) само по себе не порождает доставку — новая доставка возможна только при новом событии второй линии, «событие не теряется» реализовано через IRR: замаскированный edge остаётся в IRR и доставляется после снятия маски (OCW1) или EOI вышестоящей линии.

Обоснование: Linux ремапит PIC (IRQ1→0x21), программирует маски и шлёт EOI; без честного 8259 их обработчики не получат прерывания корректно. Альтернатива (прямой вызов `RequestInterrupt` без устройства) отвергнута: несовместима с реальной ОС и была бы тупиком для будущих IRQ (SB16, сеть).

### D2: Контроллер PS/2 (8042) — `internal/ps2`
- Порты 0x60 (данные) и 0x64 (статус/команды).
- Буфер вывода, статус-байт: bit0 output buffer full, bit1 input buffer full, bit3 самотест пройден, bit5 — данные от мышиного порта, bit6 timeout, bit7 parity.
- Байт команды контроллера (кэш): bit0 keyboard IRQ enable, bit1 mouse IRQ enable, bit6 перевод скан-кодов.
- Реализуемые команды порта 0x64: 0x20 (читать байт команды), 0x60 (писать байт команды), 0xAA (самотест), 0xA7/0xA8 (запретить/разрешить мышиный порт), 0xA9/0xAB (тест портов), 0xD4 (следующая запись в 0x60 — мышиному порту), 0xFE (сброс). Неподдерживаемые команды возвращают стандартный ответ, не ломая драйвер.
- Перевод скан-кодов ACK: контроллер отвечает 0xFA на приём команд/данных устройств.

### D3: Клавиатура PS/2, набор 1 — часть `internal/ps2`
- Подача события нажатия → make-скан-код набора 1 в буфер вывода + `RaiseIRQ(1)`; отпускание → break-код (0x80|make) + IRQ1.
- Таблица скан-кодов набора 1: однобайтовые и двухбайтовые (префикс E0). Схема транслитерации вводного API → скан-код — на уровне `internal/input` (см. D5).
- Залипающие (Shift/Ctrl/Alt) и переключающие (Caps/Num/Scroll) модификаторы отслеживаются устройством и отдаются BIOS-сервису INT 16h AH=02h.
- Клавиши Caps/Num/Scroll: генерация make и break; состояние переключается по make.

### D4: Мышь PS/2 — часть `internal/ps2`
- Команды мыши через 0xD4: 0xFF (сброс), 0xF4 (enable data reporting), 0xF6/0xF7 (disable), 0xE8 (разрешение). Драйвер Linux шлёт 0xF4.
- После enable — потоковый режим: пакет из 3 байт (`flags | dx | dy`): bit0-2 кнопки, bit4 Y-знак, bit5 X-знак, bit6 Y-overflow, bit7 X-overflow. Приращения 8-битные знаковые, обрезаются по 255.
- Событие движения/кнопки → пакет в буфер вывода (через мышиный порт, статус bit5) + `RaiseIRQ(12)` на slave → каскад.

### D5: Очередь событий и программный API — `internal/ps2` + уровень машины
- API располагается на `machine` (как и `Display()`): `machine.Input()` возвращает интерфейс с методами `KeyEvent(scancode uint8, pressed bool)` и `MouseEvent(dx, dy int8, buttons MouseButtons)`. Спека input (требование «Программный API подачи событий») приоритетна: метод принимает уже готовый скан-код набора 1, отдельного маппинга «логическая клавиша → скан-код» на этом этапе нет.
- Очередь событий живёт в контроллере PS/2 (`internal/ps2`): каждое событие порождает байтовый поток (make/break, E0-префиксы) в выходную очередь контроллера (для драйвера через порт 0x60/IRQ) и, для клавиатуры, дублируется в очередь событий нажатий (для INT 16h — см. D6).
- Контроллер имеет один буфер вывода: драйвер получает байты по одному (после в Чтении 0x60 следующим выдаётся следующий байт очереди), на каждый «буфер из пустого → непустой» поднимается IRQ-линия EDGE (как у реального 8042).
- Тесты e2e пишутся в терминах «подать событие → гость получил данные через 0x60 × N», где N берётся из дизайна, а не из спеки (деталь реализации).

### D6: INT 16h — чтение реального устройства (модификация `internal/bios`)
- INT 16h AH=01h (проверка): непустая очередь событий нажатий → ZF=0, AX=(скан, ASCII) без извлечения; пустая → ZF=1.
- AH=00h (чтение): извлечение следующего события нажатия из очереди; блокирующая семантика: при пустой очереди обработчик не завершается — EIP откатывается на длину инструкции INT (2 байта), и при следующем шаге Run гость повторно исполняет INT 16h, пока не поступит событие (механизм «блокировки», безопасный для эмулятора: исполнение остаётся за гостем).
- AH=02h (новое): возвращает состояние залипающих модификаторов из агрегатора устройства (D3).
- Буфер клавиатуры XT (0x400:0x1A) не реализуется: Linux/FreeBSD в реальном режиме не полагаются на него; INT 16h работает с очередью событий нажатий устройства. ASCI-код строится по таблице «скан-код → ASCII» с учётом Shift (раскладка US), E0-клавиши без ASCII дают AL=0.

### D7: Каскад slave на master и сама топология машины
- `internal/pic` эмулирует две микросхемы; slave при программ-ке каскада (ICW3) привязан к master-IRQ2. Приоритет master: IRQ0>IRQ1>IRQ2(cascade)>IRQ3…; slave: IRQ8>…>IRQ15.
- В машине: `pic.RaiseIRQ(1)` — клавиатура; `pic.RaiseIRQ(12)` — мышь. CPU связывается с PIC одним интерфейсом `cpu.RequestInterrupt(vector)`.

## Open Questions

1. Нужна ли эмуляция светодиодов клавиатуры (команда 0xED, LED-статус) на этом этапе? Влияет на объём тестов, но Linux шлёт 0xED при инициализации. Разумный ответ: команда принимается и ACKяется, состояние игнорируется (в Non-goals не попадает, влияние нулевое).
2. Полная таблица скан-кодов набора 1 (все 104+ клавиши) или подмножество для загрузки и тестов ОС? Влияет на объём. Разумный ответ: полная клавиатура US (включая E0-клавиши), т.к. это табличный код с уже готовой эталонной схемой.

## Risks / Trade-offs

- **Сложность 8259**: ошибки в эмуляции приоритетов/EOI приводят к «висящим» прерываниям при загрузке Linux. Смягчение: битовые тесты ICW/OCW-последовательностей, e2e с реальным перехватчиком векторов в гостевом коде.
- **Расхождение с реальным 8042**: неполная поддержка команд может застопорить инициализацию драйвера PS/2 Linux. Смягчение: команды из реального протокола инициализации (читают байт команды 0x20, тесты 0xAA/0xA9/0xAB, D4) реализованы и покрыты тестами.
- **Блокирующее INT 16h AH=00h**: если гость вызывает его без события ввода, эмулятор не зависает (исполнение остаётся за гостем), но цикл поллинга потенциально бесконечен — соответствует поведению реального BIOS.
- **Каскадный EOI**: забытая передача EOI от slave на master даёт потерю мышиных прерываний; покрывается сценарием каскада в тестах.

## Тесты

- Юнит `internal/pic`: ICW1–4 (база, каскад), OCW1 маскирование, OCW2 EOI (специфичный/неспецифичный), приоритет линии (IRQ1>IRQ3 и slave), доставка вектора через CPU по программируемой базе; порты/slave.
- Юнит `internal/ps2`: буфер вывода/статус, команды 0x20/0x60/0xAA/0xA7/0xA8/0xA9/0xAB/0xD4/0xFE, ACK, translation, make/break keyboard, mouse пакетов (dx/dy/кнопки/переполнение), IRQ-линии поднимаются.
- Юнит `internal/input`: приём событий API, маппинг клавиш → скан-коды набора 1, модификаторы.
- Юнит `internal/bios`: INT 16h AH=00h/01h/02h на реальном устройстве.
- e2e `internal/machine`: гостевой код ставит обработчики IVT векторов (база+1 и база+12), программирует PIC (ICW2=база), включает IF; подача клавиши/мыши через `machine.Input()`; проверка, что обработчик прочитал скан-код/пакет из порта 0x60 и записал маркер в память. e2e INT 16h: AH=01h/00h в реальном режиме.
