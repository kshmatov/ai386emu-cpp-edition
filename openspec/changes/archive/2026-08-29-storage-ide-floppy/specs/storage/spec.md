## Purpose

Подсистема хранения эмулятора: block device, образ жёсткого диска (raw), CD-ROM (ISO9660), дисковод (1.44M), контроллеры IDE (PIO) и floppy, а также генератор ISO9660 из каталога хоста для обмена файлами.

## ADDED Requirements

### Requirement: Block device — абстракция устройства хранения

Эмулятор SHALL предоставлять абстракцию block device для устройств хранения: HD, CD, floppy. Каждое устройство имеет размер сектора, количество секторов и поддерживает чтение/запись секторов.

#### Scenario: Чтение сектора
- **WHEN** контроллер запрашивает чтение сектора N с block device
- **THEN** возвращаются данные сектора размером, равным размеру сектора устройства

#### Scenario: Запись сектора на read/write устройство
- **WHEN** контроллер выполняет запись сектора N на устройство с поддержкой записи (HD, floppy)
- **THEN** данные записываются в файл образа и доступны при последующем чтении

#### Scenario: Запись на read-only устройство
- **WHEN** контроллер пытается записать сектор на устройство только для чтения (CD-ROM)
- **THEN** запись отклоняется без изменения данных

### Requirement: Образ жёсткого диска (raw)

Эмулятор SHALL предоставлять гостевой ОС жёсткий диск, реализованный raw-файлом хоста фиксированного размера. Файл создаётся при создании виртуальной машины, если его нет; размер файла соответствует указанному размеру диска и не увеличивается.

#### Scenario: Создание нового образа HD
- **WHEN** пользователь указывает путь HD, по которому файла нет, и размер диска
- **THEN** создаётся raw-файл указанного размера, заполненный нулями

#### Scenario: Использование существующего образа
- **WHEN** пользователь указывает путь к существующему файлу HD
- **THEN** эмулятор использует этот файл, не изменяя его размер

#### Scenario: Запись данных на HD
- **WHEN** гостевая ОС записывает данные на жёсткий диск через контроллер
- **THEN** данные сохраняются в файл образа и доступны после перезапуска эмулятора

#### Scenario: Чтение данных с HD
- **WHEN** гостевая ОС читает данные с жёсткого диска через контроллер
- **THEN** возвращаются данные из файла образа по указанному сектору

### Requirement: CD-ROM (ISO9660 image)

Эмулятор SHALL предоставлять гостевой ОС CD-ROM, реализованный ISO9660-файлом хоста. Устройство доступно только для чтения. Размер сектора ISO9660 — 2048 байт.

#### Scenario: Подключение ISO-файла как CD
- **WHEN** пользователь указывает путь к ISO9660-файлу через --cd
- **THEN** файл подключается как CD-ROM только для чтения на Primary Slave

#### Scenario: Чтение сектора с CD
- **WHEN** гостевая ОС читает сектор с CD-ROM
- **THEN** возвращаются данные из ISO-файла по указанному сектору (с учётом размера сектора 2048 байт)

#### Scenario: Запись на CD отклоняется
- **WHEN** гостевая ОС пытается записать данные на CD-ROM
- **THEN** запись отклоняется без изменения данных

### Requirement: CD-ROM из каталога хоста (shared)

Эмулятор SHALL предоставлять гостевой ОС CD-ROM, содержимое которого соответствует указанному каталогу файловой системы хоста, в режиме только для чтения. Устройство реализуется как виртуальное ISO9660-представление: метаданные (Volume Descriptor, дерево каталогов) строятся в памяти при старте виртуальной машины, а данные файлов читаются напрямую из каталога хоста по запросу — без создания промежуточного .iso-файла на диске.

#### Scenario: Подключение каталога как CD
- **WHEN** пользователь указывает путь каталога через --shared
- **THEN** при старте VM по каталогу строится виртуальное ISO9660-представление в памяти (без записи .iso-файла) и подключается как CD-ROM на Secondary Master

#### Scenario: Чтение файлов с shared CD
- **WHEN** гостевая ОС читает файл с shared CD
- **THEN** возвращается содержимое соответствующего файла из каталога хоста

#### Scenario: Запись на shared CD отклоняется
- **WHEN** гостевая ОС пытается записать данные на shared CD
- **THEN** запись отклоняется (устройство только для чтения)

#### Scenario: Статичность снимка
- **WHEN** виртуальная машина запущена и shared CD подключён
- **THEN** изменения в каталоге хоста не отражаются на подключённом CD (снимок при старте)

### Requirement: Дисковод 1.44M (floppy)

Эмулятор SHALL предоставлять гостевой ОС дисковод 3.5" HD (1.44M, 512 байт/сектор), реализованный raw-файлом хоста. Устройство поддерживает чтение и запись.

#### Scenario: Подключение floppy-образа
- **WHEN** пользователь указывает путь к файлу floppy через --floppy
- **THEN** файл подключается как дисковод A: (primary floppy controller)

#### Scenario: Чтение сектора с floppy
- **WHEN** гостевая ОС читает сектор с дисковода
- **THEN** возвращаются данные из файла floppy-образа по указанному сектору

#### Scenario: Запись сектора на floppy
- **WHEN** гостевая ОС записывает данные на дисковод
- **THEN** данные записываются в файл floppy-образа

#### Scenario: Неверный размер файла
- **WHEN** размер файла floppy не соответствует 1474560 байт (1.44M)
- **THEN** запуск отклоняется с понятной ошибкой

### Requirement: Контроллер IDE (PIO)

Эмулятор SHALL реализовывать контроллер IDE в PIO-режиме на двух каналах (primary и secondary) с двумя устройствами на канале (master/slave).

#### Scenario: Порты primary канала
- **WHEN** гостевая ОС обращается к портам 0x1F0-0x1F7 или 0x3F6
- **THEN** обращение обрабатывается контроллером IDE primary канала

#### Scenario: Порты secondary канала
- **WHEN** гостевая ОС обращается к портам 0x170-0x177 или 0x376
- **THEN** обращение обрабатывается контроллером IDE secondary канала

#### Scenario: Команда IDENTIFY DEVICE
- **WHEN** гостевая ОС отправляет команду IDENTIFY DEVICE (0xEC) на устройство
- **THEN** возвращаются данные идентификации устройства (размер, модель, поддерживаемые команды)

#### Scenario: Команда READ SECTORS
- **WHEN** гостевая ОС отправляет команду READ SECTORS (0x20) с указанием начального сектора и количества
- **THEN** запрашиваемые секторы читаются с устройства и передаются гостевой ОС

#### Scenario: Команда WRITE SECTORS
- **WHEN** гостевая ОС отправляет команду WRITE SECTORS (0x30) на устройство с поддержкой записи
- **THEN** данные записываются в соответствующие секторы устройства

#### Scenario: Обращение к несуществующему устройству
- **WHEN** гостевая ОС обращается к устройству, которое не подключено (например, Secondary Slave)
- **THEN** команда возвращает ошибку (status register = 0x00, BSY=0, DRQ=0)

#### Scenario: IRQ14 для primary
- **WHEN** операция чтения/записи на primary канале завершена
- **THEN** генерируется IRQ14

#### Scenario: IRQ15 для secondary
- **WHEN** операция чтения/записи на secondary канале завершена
- **THEN** генерируется IRQ15

### Requirement: Контроллер floppy

Эмулятор SHALL реализовывать контроллер дисковода с поддержкой формата 1.44M (80 треков, 2 головки, 18 секторов/трек, 512 байт/сектор).

#### Scenario: Порты контроллера floppy
- **WHEN** гостевая ОС обращается к портам 0x3F0-0x3F7
- **THEN** обращение обрабатывается контроллером floppy

#### Scenario: Команда READ SECTOR
- **WHEN** контроллер floppy получает команду чтения сектора
- **THEN** указанный сектор читается с дисковода и передаётся гостевой ОС

#### Scenario: Команда WRITE SECTOR
- **WHEN** контроллер floppy получает команду записи сектора на устройство с поддержкой записи
- **THEN** данные записываются в указанный сектор дисковода

#### Scenario: Команда RECALIBRATE
- **WHEN** контроллер floppy получает команду RECALIBRATE
- **THEN** головка дисковода перемещается на дорожку 0

#### Scenario: Команда SENSE INTERRUPT STATUS
- **WHEN** гостевая ОС запрашивает SENSE INTERRUPT STATUS
- **THEN** возвращается текущий статус контроллера floppy

#### Scenario: IRQ6
- **WHEN** операция floppy завершена
- **THEN** генерируется IRQ6
