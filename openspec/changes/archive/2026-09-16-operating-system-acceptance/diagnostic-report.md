## Повтор FreeBSD после исправлений

Команда: `go test ./internal/machine -run TestFreeBSDDiagnostic -v -count=1 -args -freebsd-image=/tmp/ai386-freebsd-4.11-miniinst.iso`.

После eltorito-floppy загрузчик включает PE после 551 инструкции. Исправление bios-callable-vectors устраняет нулевой адрес INT15 в IVT; cpu-v86-monitor устраняет #UD на 850-й инструкции, вызванный неверным кадром и сохранением VM при входе в обработчик #GP.

Повтор с 100 млн инструкций завершился по диагностическому лимиту через 122.712 с: экран содержит только индикатор `-`, ядро не достигнуто. Для быстрой репродукции добавить `-freebsd-steps=1000000`: около 0.74 с, EIP=923F, CR0=60000011, обработчик монитора v86. Причина дальнейшего отсутствия прогресса ещё исследуется; область — взаимодействие BIOS и загрузчика через v86. Успешная загрузка или установка FreeBSD не заявляется.

Общие `go test ./...`, `go vet ./...`, `go build ./...`, CPU race и BIOS race прошли. Локальная диагностическая проверка с ISO намеренно остаётся FAIL до достижения ядра; стандартный набор без ISO её пропускает.

После bios-timer-ticks FreeBSD выходит из ожидания BDA 0040:006C и печатает FreeBSD/i386 bootstrap loader Revision 0.8, BIOS drive A: disk0, 65536kB/64512kB available memory. Следующая остановка через 68357032 инструкции — нулевой v86-вход при AX=0200; проверяется недостающий сервис RTC. Длинный прогон до #UD занимал 11.396 с. Повтор DSL: PASS12.056 с, прежняя точка ядра C010005E после 92418411 инструкций.

После bios-rtc-services подтверждён и устранён INT1A/AH02; FreeBSD читает `/kernel text=0x289d91 data=0x30170+0x32d04` и показывает `Booting [kernel] in 7 seconds...`. Прогон 300 млн инструкций завершился по лимиту через 47.702 с без прежнего #UD; ядро ещё не исполнялось. Диагностический сценарий теперь нажимает Enter через PS/2 при появлении обратного отсчёта и по умолчанию допускает 1 млрд инструкций.

После Enter FreeBSD включает paging. Регрессия RETF теряла CS.D и вызывала #UD внутри immediate по C030CB4A; исправлена в cpu-retf-segment-width. Повтор через 265933012 инструкций достигает RDMSR 1002h по C030989A, обработчик C0309840. Это штатная проба identblue(), подтверждённая [исходником FreeBSD 4.11](https://github.com/freebsd/freebsd-src/blob/releng/4.11/sys/i386/i386/identcpu.c). Диагностика позволяет ядру исполнять собственный обработчик вместо остановки на любом #UD. CPU не изменён для обхода этой пробы.

Уточнение диагностики: LastException хранит последнее событие; повторное чтение в следующей инструкции не означает повторный #UD. Старый FAIL на IRETD по C0307A7C был ложной остановкой наблюдателя при переходе ядра в v86. Наблюдатель теперь логирует #UD, позволяет гостевому обработчику исполняться и проверяет достижение точки ядра, остановку CPU с IF=0 либо лимит инструкций.
