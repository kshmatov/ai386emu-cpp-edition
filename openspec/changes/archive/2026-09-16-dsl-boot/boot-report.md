# Загрузка DSL 4.4.10 — проверка 2026-09-10–11

> История Go-издания: упоминания Go-команд, путей и цифр ниже относятся к Go-реализации (ai386).

Образ пользователя: `dsl-4.4.10.iso`, 52328448 байт, SHA256 `6d9369c7b8fb0f23880c5ec44f5a4a2d9d628d7a1407ea83bf0b3249eda33537`.

Текущая конфигурация: RAM 64 МиБ, CD ISO, очередь `cd`, штатный пункт ISOLINUX `dsl-txt 2` (textmode/runlevel 2). Первоначальный диагностический прогон ниже использовал `dsl-txt` без номера runlevel. Пункт вводится тестом через события PS/2 после появления `boot:`. ISO не изменён. По умолчанию ISO выбирает VESA vga=791; текстовый пункт выбирает vga=normal.

Команда проверки только входа в ядро:

```sh
go test ./internal/machine -run TestDSLDiagnostic -v -count=1 -args -dsl-image="$PWD/dsl-4.4.10.iso"
```

Результат: после 92418216 инструкций EIP=0xC010005E, CSbase=0, CR0=0xE0000011 (PE и PG включены). Тест сверяет также байты распакованного ядра по физическому адресу 0x10005E и текст `Uncompressing Linux... Ok, booting the kernel.` Это вход в настоящее ядро Linux после распаковки, а не промежуточный protected-mode переход ISOLINUX для копирования данных.

Диагностика следующих инструкций:

```sh
go test ./internal/machine -run TestDSLDiagnostic -v -count=1 -args -dsl-image="$PWD/dsl-4.4.10.iso" -dsl-extra-steps=1000000
```

Первый исторический блокер (впоследствии исправлен): FNINIT по 0xC01001D5 вызывает #UD, поскольку FPU ещё не реализован. Рабочее приглашение Linux, rootfs и работа с дисками этим этапом не подтверждены. Образ FreeBSD не выбран и загрузка не проверялась. Задачи 4.5–4.6 roadmap для обеих ОС целиком не закрыты.

Исправлены: INT 11h/12h, legacy INT 15h E801h/AH=88h и ошибка неподдерживаемых функций, начальная настройка текстового VGA и функции вывода, LMSW, ширина дальнего JMP и RET. Полные обычные и race-тесты, go vet, go build успешны. Локальный ISO-тест запускается отдельно указанной командой.

Источники семантики BIOS: [SeaBIOS system.c](https://github.com/coreboot/seabios/blob/master/src/system.c), [VGA BIOS](https://github.com/coreboot/seabios/blob/master/vgasrc/vgabios.c). Проверяемые инструкции и пункты меню прочитаны из оригинального ISO.

## Продолжение после входа в ядро

Первоначальные блокеры выше устранены следующими изменениями: управляющие FNINIT/FNSTSW/FNSETPM, стабильная запись собственного PDE, CALL r/m32, POPFD AC и MOV DR. Полная арифметика x87 остаётся отдельной задачей.

После подключения PIT при clock_hz=100000000 журнал настоящего ядра содержит:

```text
Calibrating delay loop... 19.81 BogoMIPS
Memory: 61444k/65536k available (1386k kernel code, 3704k reserved, 567k data, 144k init, 0k highmem)
Checking if this processor honours the WP bit even in supervisor mode...
```

BogoMIPS относится к приближённой модели виртуального времени, не к точной производительности DX4. #PF при записи в C0000000 — штатная проверка WP, продолжение после доставленного исключения включается флагом `-dsl-continue-faults`. Приёмка калибровки: дополнительно `-dsl-extra-steps=100000000 -dsl-continue-faults -dsl-require-calibration`. Вход в пользовательское окружение ещё не подтверждён.

После арифметики x87 проверка FDIV завершена, HLT/POPAD — OK. После FNSAVE ядро создаёт процессы и печатает `Starting kswapd`, инициализирует подсистемы VFS и драйверы. Следующий диагностический прогон увеличен до 500 млн шагов после входа в ядро; обязательный рубеж проверяется через `-dsl-require-log=kswapd`. Это ещё не приёмка пользовательского shell.

## Пользовательское окружение и последовательные регрессии

Текущий тест по умолчанию вводит `dsl-txt 2`: runlevel 2 документирован оригинальной справкой F2 ISO как textmode only. Вход в ядро для этой строки: 92418411 инструкций.

Подтверждены EXT2 initrd, пользовательский INT80 с supervisor IDT/GDT/TSS, ATAPI hdb на IRQ14, ide-scsi/sr0, ISO9660 и cloop `/cdrom/KNOPPIX/KNOPPIX` (1961 блок по 65536 байт). Видимый текст VGA учитывает CRTC Start Address.

Последующие исправления CPU: real/integer x87 пользовательских утилит, #PF до проверки неполной кодировки инструкции, сохранение ESP при неуспешном PUSH. После этих исправлений исчезли прежние #UD при Setting paths. Прогон 600 млн дополнительных шагов выявил lost interrupt CD; подтверждение PIC перенесено на момент принятия прерывания процессором. Повторная приёмка продолжается.

Строгая проверка рабочего shell доступна через `-dsl-require-shell`: тест вводит через PS/2 `echo ai386ready` и требует отдельную строку `ai386ready`, а не только эхо набранной команды. Пока этот сценарий не прошёл, PASS диагностического теста означает лишь подтверждённый вход в ядро и дополнительные явно запрошенные рубежи.

## Строгая приёмка shell

Первый прогон с лимитом 2 млрд дополнительных шагов завершился за 735.99 с с FAIL: ядро, init, hwsetup, fstab и unionfs запустились, но распаковка пользовательского окружения ещё не завершилась. Это не успешная приёмка shell. Критерий не изменён; успешный повтор выполнен с лимитом 4 млрд шагов и таймаутом 35 минут:

```sh
go test ./internal/machine -run TestDSLDiagnostic -v -count=1 -timeout=35m \
  -dsl-image="$PWD/dsl-4.4.10.iso" \
  -dsl-extra-steps=4000000000 -dsl-continue-faults -dsl-stop-vector=6 \
  -dsl-require-shell -dsl-screen=/tmp/ai386-dsl-shell.png
```

Неисправленные ограничения платформы: RTC/CMOS отсутствует (предупреждения tar о датах), PCI отсутствует (сообщение lspci), CPU определяется Linux как Cyrix Cx486DLC. Приближённое виртуальное время не подтверждает точную скорость DX4-100. Окно и клавиатура хоста пока не подключены; проверка использует API Machine. Загрузка с установленного HD, FreeBSD, X, звук и сеть этим прогоном не принимаются.

## Итог приёмки 2026-09-11

Строгий прогон **PASS**, 1062.67 с (около 17 мин 43 с). После более 2,8 млрд дополнительных шагов появился root-shell. Тест подал скан-коды команды через PS/2 и наблюдал на VGA:

```text
root@tty1[/]# echo ai386ready
ai386ready
root@tty1[/]#
```

[Снимок итогового экрана](../dsl-shell/shell.png) проверен визуально. ISO не изменялся. Паники ядра, прежних #UD и lost interrupt в итоговом прогоне нет. Таким образом подтверждена загрузка DSL с CD до пользовательского shell и выполнение команды с клавиатуры VM. Ограничения платформы, перечисленные выше, сохраняются.

Проверки реализации: полный `go test ./...`, полный `go test -race ./...`, `go vet ./...`, `go build ./...` успешны. Отдельный ISO-прогон обязателен для воспроизведения приёмки ОС; обычный запуск без образа не заменяет его.

## Продолжение RTC/CMOS — 2026-09-11

Отсутствие RTC/CMOS из списка ограничений выше устранено изменением [rtc-cmos](../archive/2026-09-11-rtc-cmos/acceptance.md). Повторная загрузка с фиксированным UTC 2026-09-11T12:00:00Z: PASS за 1046.79 с, echo и date +%Y=2026 через PS/2. Предупреждения tar о будущих датах исчезли; CMOS больше не сообщает floppy типа 15. Остальные перечисленные ограничения сохраняются.
