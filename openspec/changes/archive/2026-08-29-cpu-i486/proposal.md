> История Go-издания: упоминания Go-команд, путей и цифр ниже относятся к Go-реализации (ai386).

## Why

Эмулятор на этапе 1 представляет собой только каркас: у машины есть шина, память и жизненный цикл, но нет исполнителя кода. Без CPU невозможно ни загрузить BIOS и операционную систему (этап 4), ни подключить какие-либо реальные устройства. Нужен работающий интерпретатор ядра i386/i486 как фундамент для всех следующих этапов.

## What Changes

- Новый пакет `internal/cpu` — интерпретатор процессора i486DX4: регистры, флаги, полный набор команд i386/i486.
- Поддержка всех режимов: реальный, защищённый (сегментация, привилегии, GDT/LDT/TSS), страничная трансляция (paging, 4K/4M), виртуальный 8086.
- Прерывания и исключения на стороне процессора: IDT/IVT, доставка аппаратных прерываний по запросу, генерация #UD/#GP/#PF/#DE и других исключений.
- Шина расширяется широкими доступами (16/32 бита) с байтовой согласованностью для эффективного исполнения кода.
- Машина создаёт CPU, связывает его с памятью и шиной; запуск машины начинает исполнение инструкций с адреса сброса.
- Метод запроса аппаратных прерываний у CPU, который будут вызывать будущие устройства (PIC, таймеры).
- FPU-опкоды (0xD8–0xDF) на этом этапе генерируют #UD; поддержка x87 реализуется отдельным change.
- Тесты: гибрид — импорт таблиц SingleStepTests/80386 (real mode, MIT) в `testdata/` и собственные табличные тесты для защищённого режима, paging, v86 и 486-дополнений.

## Capabilities

### New Capabilities
- `cpu`: Ядро процессора i386/i486 — регистры, флаги, набор команд, режимы, paging, прерывания и исключения, исполнение гостевого кода.

### Modified Capabilities
- `machine-core`: Модель памяти и шина дополняются широкими доступами (16/32 бита); жизненный цикл машины включает CPU и начало его исполнения при запуске.

## Non-goals

- FPU (полный x87) — выносится в отдельный change.
- Контроллер прерываний (PIC/8259) и внешняя доставка IRQ через него — позже, на этом этапе только интерфейс запросов к CPU.
- Точность по циклам и микроархитектуре (prefetch, pipeline, timings) — исполнение семантически корректное, а не циклически точное.
- Оптимизация производительности интерпретатора (JIT, динамическая трансляция) — интерпретатор достаточен по целям проекта.
- 486-специфичные «причуды» пайплайна, не влияющие на видимый результат исполнения.

## Impact

- Новый пакет `internal/cpu` (файлы: decode, alu, move, control, string, system, paging, exception).
- Изменение `internal/machine`: расширение шины широкими доступами, интеграция CPU в машину.
- `go.mod`: новых зависимостей не требуется (классические доступы и встроенный JSON для загрузки тест-векторов).
- Тестовые данные SingleStepTests/80386 добавляются в `testdata/` (лицензия MIT, автономно для запуска без сети).
- Изменяется и расширяется `openspec/specs/machine-core`, добавляется `openspec/specs/cpu`.
