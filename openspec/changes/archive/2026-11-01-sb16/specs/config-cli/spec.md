## ADDED Requirements

### Requirement: Параметры SoundBlaster16


Конфигурация SHALL поддерживать параметры SB16 в TOML: sb16 (включение, по умолчанию false), sb16_base (база портов, по умолчанию 0x220, кратна 16), sb16_irq (по умолчанию 5, допустимы 5/7/9/10), sb16_dma8 (по умолчанию 1, допустимы 0/1/3), sb16_dma16 (по умолчанию 5, допустимы 5/6/7), sb_backend (auto|file|off, по умолчанию auto), sb_backend_play и sb_backend_rec (устройство или путь файла бэкенда). CLI SHALL предоставлять флаги --sb16 on|off и --sb-backend auto|file|off с приоритетом CLI > TOML > значения по умолчанию. Недопустимые значения SHALL отклоняться понятной ошибкой до создания ВМ; при sb_backend=file путь sb_backend_play SHALL быть обязательным.

#### Scenario: Включение через CLI
- **WHEN** пользователь запускает эмулятор с --sb16=on без секции sb16 в TOML
- **THEN** создаётся ВМ с SB16 на базе 0x220, IRQ 5, DMA 1/5 и бэкендом auto

#### Scenario: Параметры из TOML
- **WHEN** TOML задаёт sb16=true, sb16_base=0x240, sb16_irq=7, sb16_dma8=3, sb16_dma16=6
- **THEN** SB16 создаётся с указанными базой, IRQ и каналами DMA

#### Scenario: Недопустимый 16-битный канал
- **WHEN** задано sb16_dma16=3
- **THEN** запуск отклоняется с понятной ошибкой о допустимых каналах {5,6,7}

#### Scenario: Файловый бэкенд без пути дампа
- **WHEN** задано sb_backend=file, а sb_backend_play пуст
- **THEN** запуск отклоняется с понятной ошибкой до создания ВМ

#### Scenario: Приоритет CLI
- **WHEN** TOML содержит sb16=false, а CLI содержит --sb16=on
- **THEN** SB16 включён; при TOML sb_backend="off" и CLI --sb-backend=file с заданным sb_backend_play используется файловый бэкенд

### Requirement: Выбор аудио-бэкенда


Бэкенд auto SHALL выбирать платформенный вывод/ввод: на Linux — aplay/arecord (при их наличии; иначе эмулятор запускается с предупреждением и бэкендом off), на Windows — winmm, на прочих платформах — off. Бэкенд file SHALL писать воспроизводимый PCM-поток в файл sb_backend_play и подавать на вход записи данные из файла sb_backend_rec (при отсутствии файла или исчерпании — тишину). Бэкенд off SHALL поглощать воспроизведение и подавать тишину на запись. Выбор бэкенда SHALL применяться только при включённом sb16 и не влиять на поведение гостя (DSP/DMA/IRQ работают при любом бэкенде).

#### Scenario: Детерминированный дамп для тестов
- **WHEN** sb_backend=file, sb_backend_play=/tmp/out.pcm и гость воспроизводит известный поток
- **THEN** файл /tmp/out.pcm содержит байты потока в исходном формате гостя без преобразований

#### Scenario: Отключённый звук не ломает гостя
- **WHEN** sb_backend=off и гость выполняет полный цикл воспроизведения с DMA
- **THEN** передача по DMA, IRQ и подтверждения работают штатно, звук никуда не выводится
