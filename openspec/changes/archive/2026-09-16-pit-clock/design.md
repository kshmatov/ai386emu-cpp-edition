## Context

Linux программирует канал 0 PIT и ожидает IRQ0 для калибровки. CPU.Cycles считает обращения к шине; точной модели тактов инструкции ещё нет.

## Goals / Non-Goals

Дать воспроизводимые тики без зависимости от скорости хоста. Не заявлять точную производительность реального DX4.

## Decisions

- Опорная частота PIT 1193182 Гц — аппаратная константа. clock_hz/--clock-hz задаёт частоту условных тактов CPU, по умолчанию 100000000. На инструкцию расходуется не меньше одного условного такта; обращения к шине берутся из CPU.Cycles. Это явно приближённая модель времени.
- Machine.Step исполняет CPU и продвигает PIT через целочисленный аккумулятор дробной части. При HLT виртуальное время продвигается на 1 мс за шаг ожидания; Run дополнительно ждёт до 1 мс на хосте и допускает отмену контекста.
- PIT хранит состояние трёх каналов, reload, режим, доступ к байтам и защёлки count/status. Канал 0 поднимает IRQ0 через существующий PIC. Канал 2 управляется gate через порт 61h, его OUT читается в бите 5.
- RTC/CMOS отсутствует и остаётся отдельной потребностью; звук speaker не воспроизводится этим change.

## Risks / Trade-offs

Калибровка показывает скорость выбранной модели виртуального времени, а не benchmark реального i486. Источник аппаратной семантики: [Intel 8254 datasheet](https://www.scs.stanford.edu/25sp-cs212/pintos/specs/8254.pdf).
