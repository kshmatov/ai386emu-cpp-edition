# Основания

> История Go-издания: упоминания Go-команд, путей и цифр ниже относятся к Go-реализации (ai386).

Исходная задача — проверить реальный DHCP/DNS/HTTP/HTTPS двух гостей и
устранить подтверждённые отказы. После RX boundary fix остаётся зависание
FreeBSD HTTP 32768 байт; точный payload 8457 байт уже проходит.

- `internal/usernat/tcp.go`: до изменения Advance сканирует все outstanding
  и повторяет каждый просроченный сегмент за один вызов.
- `tcp_recovery_test.go`: полный handshake и host net.Pipe дают три data
  сегмента и FIN; один timeout повторяет все четыре. RED воспроизведён 3/3.
- [RFC 6298 §5](https://www.rfc-editor.org/rfc/rfc6298.html#section-5): пункт 5.4
  выбирает первый неподтверждённый сегмент. Пункты о динамическом RTO,
  backoff и перезапуске общего таймера в этот узкий scope не включены;
  прежний настраиваемый per-segment sentAt сохраняется.
- Связь повторного burst с FreeBSD OVW пока гипотеза: unit test доказывает
  конкретное поведение таймера, не причину guest зависания. Требуются
  NIC-level loop либо успешная повторная передача с единственной правкой.

Артефакты и точное время — `verification.md`, гостевой журнал
`/tmp/ai386-network-20261014/freebsd-tcp-fixed.log`.
