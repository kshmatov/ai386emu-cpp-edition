## 1. Контракт и конфигурация сети  <!-- source: ne2000-usernat -->

- [x] 1.1 Добавить поля TOML конфигурации сети, валидацию базы/IRQ/MAC/IPv4-подсети и CLI `--network on|off` с приоритетом CLI. Тесты testify покрывают default, TOML, приоритет и все ошибки. Критерий приёмки: отключённая сеть сохраняет прежнее поведение; некорректная конфигурация отклоняется до создания VM. (было 1.1)
- [x] 1.2 Определить интерфейс Ethernet-кадров и безопасный генератор уникальных локально администрируемых MAC для VM. Тесты testify проверяют свойства MAC и уникальность параллельного создания. Критерий приёмки: два экземпляра VM без явного MAC получают разные unicast адреса. (было 1.2)

## 2. Эмуляция NE2000  <!-- source: ne2000-usernat -->

- [x] 2.1 Реализовать `internal/ne2000`: reset, регистры DP8390 и ASIC, PROM с MAC, удалённый DMA и память пакетов. Тесты testify покрывают чтение PROM, remote DMA, границы и reset. Критерий приёмки: драйвер может обнаружить карту, прочитать MAC и программировать память пакетов. (было 2.1)
- [x] 2.2 Реализовать TX, RX-кольцо, фильтрацию MAC/broadcast, ISR/IMR и IRQ-колбэк. Тесты testify покрывают передачу кадра, приём кадра, переполнение, маску и подтверждение IRQ. Критерий приёмки: кадр проходит через FramePort и принятый кадр доставляется в RX с корректным прерывением. (было 2.2)

## 3. Встроенный user-mode NAT  <!-- source: ne2000-usernat -->

- [x] 3.1 Реализовать разбор/сборку Ethernet, ARP, IPv4, ICMP и DHCP с локальными ответами маршрутизатора. Тесты testify покрывают ARP, DHCP lease/options, IPv4 checksum и игнорирование неверных кадров. Критерий приёмки: гость получает адрес, шлюз и DNS из настроенной подсети. (было 3.1)
- [x] 3.2 Реализовать DNS-прокси и UDP NAT через инъецируемые resolver/dialer и таблицу потоков. Тесты testify с локальным сервером покрывают DNS, UDP request/response, timeout и отбрасывание незатребованных пакетов. Критерий приёмки: ответ приходит только в поток, созданный гостем. (было 3.2)
- [x] 3.3 Реализовать TCP NAT: handshake, номера последовательности, окно, payload, FIN/RST, timeout и retransmit по Advance. Тесты testify с локальным TCP-сервером покрывают соединение, двусторонние данные, закрытие, timeout и запрет незатребованного входящего потока. Критерий приёмки: гостевой TCP-клиент получает ответ локального и внешнего сервера без входящего listener. (было 3.3)
- [x] 3.4 Реализовать ограниченную concurrent-очередь кадров, отмену контекста и Close NAT. Тесты testify и `-race` покрывают остановку при активных TCP/UDP потоках и повторный Close. Критерий приёмки: нет утечек goroutine, deadlock и race. (было 3.4)

## 4. Интеграция машины и приёмка  <!-- source: ne2000-usernat -->

- [x] 4.1 Подключить NE2000/NAT к `machine.New`, шине, PIC, виртуальному времени и Stop через `WithNetwork`. Тесты testify покрывают занятые порты только при network=true, configured IRQ, продвижение ответов и безопасный Stop. Критерий приёмки: сетевые порты и IRQ отсутствуют в VM без сети. (было 4.1)
- [x] 4.2 Добавить сквозной тест: настройка NE2000 через шину, DHCP, DNS, UDP и TCP к локальным тестовым серверам без реальной сети. Критерий приёмки: `go test -race` подтверждает полный путь Ethernet→NAT→сокет→Ethernet. (было 4.2)
- [x] 4.3 Выполнить e2e-приёмку DSL 4.4.10 и FreeBSD 4.11 с включённой картой: драйвер, DHCP, DNS и исходящий HTTP/HTTPS к заранее определённому узлу; задокументировать команды и результаты. Критерий приёмки: обе ОС получают ответы; незапрошенный входящий трафик не доставляется. (было 4.3) **Закрыто как приёмка Go-издания:** критерий (включая неподтверждённый HTTPS обеих ОС) перенесён в roadmap 8.2/9.3 C++-издания.
- [x] 4.4 Выполнить `go test ./...`, `go test -race ./...`, `go vet ./...`, `go build ./...` и `openspec validate ne2000-usernat --strict`; зафиксировать результаты и ограничения приёмки. Критерий приёмки: все автоматические проверки зелёные, гостевые результаты приложены к change. Результаты: `network-verification-2026-09-22.md`. (было 4.4)
