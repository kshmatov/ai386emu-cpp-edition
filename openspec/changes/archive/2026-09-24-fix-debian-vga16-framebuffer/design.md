## Context

См. мотивацию в `proposal.md`. Диагностический запуск Debian Sarge подтверждает ядро 2.4.27, успешную загрузку `vga16fb`, создание `fb0` типа VGA planes и переход в 640×480. Без обходного параметра текущий кадр содержит лишь несколько сотен тёмно-серых пикселей, затем становится полностью чёрным.

Linux `vga16fb` программирует стандартные VGA-регистры напрямую. Kernel framebuffer console использует write modes 1–3 и латчи, а BOGL рисует через Set/Reset, Bit Mask, Read Map Select и read-modify-write в окне A0000. Текущая реализация проверяет отдельные write modes, но не реальные составные последовательности; Read Mode 1 отсутствует. Рендеринг графического кадра вычисляет шаг как `width/8` и не учитывает CRTC Start Address и Offset.

## Goals / Non-Goals

**Goals:**

- Сделать VGA-память совместимой с последовательностями Linux VGA16 на уровне регистров и плоскостей.
- Отделить корректность записи VRAM от корректности извлечения видимого кадра тестами обоих уровней.
- Получить воспроизводимую приёмку стандартной framebuffer-загрузки Debian.

**Non-Goals:**

- Эмулировать точные временные характеристики VGA-развёртки.
- Менять VBE BIOS или добавлять новый framebuffer.
- Специально распознавать Debian, Linux либо BOGL в production-коде.

## Decisions

### D1. Эталоном служат операции VGA, а не конкретный гость

В модульных тестах воспроизводятся последовательности портов и памяти из `vga16fb`, `fbcon-vga-planes` и BOGL, но production-код остаётся универсальной моделью регистров VGA. Это предотвращает guest-specific обходы.

Альтернатива — исправлять только наблюдаемый кадр Debian — отвергнута: она не доказывает корректность плоскостей и легко ломает другие VGA-программы.

### D2. Планарное чтение выбирается битом Read Mode

Read Mode 0 сохраняет существующее поведение Read Map Select. Read Mode 1 после загрузки четырёх латчей вычисляет восьмибитную маску совпадения с Color Compare только по плоскостям, разрешённым Color Don't Care. Оба режима используют одну операцию загрузки латчей.

Это завершает модель Graphics Controller и позволяет тестировать чтение независимо от write modes. Неиспользуемые биты регистров продолжают храниться без специального поведения.

### D3. Адрес видимого пикселя вычисляется из CRTC

Для графических кадров вводится единое вычисление базового адреса и шага строки. Start Address интерпретируется в адресных единицах VGA, а CRTC Offset — в словах согласно стандартному byte-mode VGA16; режимные различия локализуются в функциях planar/chained/unchained. Адрес замыкается на размер соответствующей плоскости.

BIOS-режимы продолжают программировать значения, дающие прежнюю геометрию и раскладку, поэтому существующие тесты стандартных режимов не меняют ожидаемый результат.

Альтернатива — оставить `width/8` и исправить только VRAM-запись — отвергнута, поскольку гость имеет право независимо программировать виртуальную ширину и начало видимой области.

### D4. Приёмка проверяет содержимое графического кадра

Текстовое извлечение экрана неприменимо к framebuffer. Диагностический тест сохраняет либо анализирует RGBA-кадр: проверяет 640×480, наличие нескольких значимых цветов и достаточную долю пикселей не фонового цвета. Переходы между экранами подтверждаются различием кадров после PS/2 Enter и сохранёнными эталонными снимками/отчётом.

ISO остаётся внешним opt-in fixture с обязательной проверкой SHA256. Быстрый набор тестов не зависит от наличия образа.

## Risks / Trade-offs

- **[Неверная интерпретация адресных единиц CRTC в разных режимах]** → покрыть planar, chained и unchained отдельными таблицами тестов и сохранить существующие BIOS-mode тесты.
- **[Исправление VRAM не устранит чёрный экран из-за второго дефекта]** → сначала добавить точный replay-тест операций BOGL и при необходимости трассировать только порты VGA/окно A0000; не расширять scope на VBE без нового факта.
- **[E2E Debian выполняется долго]** → оставить его opt-in, а обязательную семантику VGA проверять быстрыми модульными тестами.
- **[Хрупкая проверка по цветам]** → сочетать структурные признаки кадра, изменение после ввода и сохранённые диагностические снимки, не сравнивать PNG побайтово.

## Migration Plan

1. Добавить падающие модульные replay-тесты VGA16 и тесты адресации кадра.
2. Исправить модель Graphics Controller и графический рендеринг без изменения публичных интерфейсов.
3. Выполнить быстрые тесты, race detector и линтеры.
4. Запустить opt-in приёмку Debian со штатной командой `linux`, зафиксировать параметры и снимки.
5. После успешной приёмки удалить workaround из README. Откат состоит в возврате внутренних изменений VGA; форматы дисков и конфигурации не затрагиваются.
