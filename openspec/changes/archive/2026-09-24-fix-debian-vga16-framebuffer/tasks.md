## 1. Планарная VGA

- [x] 1.1 Добавить на `testify` регрессионные replay-тесты последовательностей BOGL и `fbcon-vga-planes`: mode 0 read-modify-write с Set/Reset и Bit Mask, заполнение фона в mode 2, загрузка латчей и вывод глифа в mode 3, копирование в mode 1 и выбор плоскости чтения. Критерий приёмки: тесты проверяют итоговые байты всех четырёх плоскостей и до исправления выявляют конкретное расхождение с VGA16. После завершения записать затраченное время, токены и результат тестов.

- [x] 1.2 Реализовать недостающую семантику планарных операций, выявленную replay-тестами, не добавляя специальных ветвей для Linux или Debian. Критерий приёмки: все replay-тесты и существующие тесты write modes проходят, а поведение Map Mask, Set/Reset, Bit Mask и латчей соответствует тестовым векторам. После завершения записать затраченное время, токены и результат тестов.

- [x] 1.3 Добавить регистры Color Compare и Color Don't Care и реализовать Read Mode 1 с общей загрузкой четырёх латчей; покрыть `testify`-тестами полное совпадение, частичную don't-care маску, несовпадение и последующую запись из латчей. Критерий приёмки: Read Mode 0 сохраняет Read Map Select, Read Mode 1 возвращает ожидаемую восьмибитную маску, существующие режимы не регрессируют. После завершения записать затраченное время, токены и результат тестов.

## 2. Графический кадр VGA

- [x] 2.1 Добавить на `testify` табличные тесты Start Address и CRTC Offset для planar, chained и unchained кадров, включая padding строки и замыкание адреса плоскости. Критерий приёмки: тесты различают нулевую и программируемую адресацию и сохраняют ожидаемые кадры стандартных BIOS-режимов. После завершения записать затраченное время, токены и результат тестов.

- [x] 2.2 Реализовать единое вычисление начального адреса и шага графической строки из регистров CRTC с учётом адресного режима, применить его во всех трёх графических рендерах. Критерий приёмки: новые и существующие VGA-тесты проходят, кадр Linux VGA16 использует 80 байт на строку при 640 пикселях и корректно следует CRTC Start Address. После завершения записать затраченное время, токены и результат тестов.

## 3. Диагностика и приёмка Debian

- [x] 3.1 Расширить opt-in диагностический тест Debian проверкой framebuffer-кадра 640×480 без текстового OCR: геометрия, несколько значимых цветов, минимальная заполненность интерфейса и изменение кадра после PS/2-ввода; сохранить понятную диагностику и PNG при отказе. Критерий приёмки: прежний кадр только с заголовком или полностью чёрный отвергается, полноценный экран выбора языка принимается. Критерий приёмки: три последовательных экрана остаются читаемыми и принимают ввод; обходной параметр не используется. После завершения записать затраченное время, токены и результат приёмки.

После завершения записать затраченное время, токены и результат проверки документации.
