# vga Specification

## Purpose
Устройство VGA эмулятора: регистры контроллеров (CRTC, секвенсер, графический, атрибутный, DAC), видеопамять со всеми схемами адресации реального VGA (planar, chained, unchained) и все текстовые и графические режимы, а также публичный API получения текущего кадра для внешнего наблюдения экрана.

## Requirements

### Requirement: Регистры контроллеров VGA

Эмулятор SHALL предоставлять доступ по портам ввода-вывода ко всем регистрам CRTC, секвенсера, графического контроллера, атрибутного контроллера и DAC, с сохранением состояния между обращениями.

#### Scenario: Запись и чтение регистра CRTC
- **WHEN** в порт индекса CRTC записывается номер регистра, а в порт данных — значение
- **THEN** последующее чтение того же регистра (через тот же индекс) возвращает записанное значение

#### Scenario: Флип-флоп атрибутного контроллера
- **WHEN** выполняется последовательность из двух записей в порт 0x3C0 (индекс, затем данные)
- **THEN** первая запись выбирает индекс регистра атрибутного контроллера, вторая — записывает в него значение; последующая пара запросов работает независимо от предыдущей

#### Scenario: Автоинкремент DAC
- **WHEN** записан индекс DAC (порт 0x3C8), затем последовательно записаны три байта (R, G, B) в порт данных 0x3C9
- **THEN** записанная запись палитры соответствует этим трём байтам, и следующая запись данных без повторной записи индекса начинает запись **следующей** по порядку записи палитры

### Requirement: Видеопамять и переключение окна

Эмулятор SHALL предоставлять доступ к видеопамяти в диапазоне 0xA0000–0xBFFFF, ограничивая видимость активным окном согласно регистру Memory Map Select графического контроллера.

#### Scenario: Обращение в пределах активного окна
- **WHEN** выполняется запись байта по адресу внутри окна, соответствующего текущему значению Memory Map Select
- **THEN** значение сохраняется, и последующее чтение того же адреса возвращает записанное значение

#### Scenario: Обращение вне активного окна памяти
- **WHEN** выполняется обращение по адресу диапазона 0xA0000–0xBFFFF, не входящему в окно текущего Memory Map Select
- **THEN** чтение возвращает 0xFF, а запись не имеет эффекта — устройство не падает

### Requirement: Планарная запись с латчами и write-режимами

Эмулятор SHALL реализовывать запись в видеопамять в планарном режиме через латчи (защёлкнутые байты всех 4 плоскостей), Set/Reset, Function Select, Data Rotate и Bit Mask графического контроллера, а также выбор активных плоскостей записи через Map Mask секвенсера.

#### Scenario: Планарная запись байта
- **WHEN** выполняется запись байта в видеопамять при заданных значениях write mode, Function Select, Bit Mask и Map Mask графического контроллера/секвенсера
- **THEN** результат в каждой из 4 плоскостей соответствует документированной формуле VGA для этого write mode (пример: write mode 0, Function Select = replace, Bit Mask = 0xFF, Map Mask = 0b0011 — записываемый байт помещается в плоскости 0 и 1 без изменений, плоскости 2 и 3 не изменяются)

#### Scenario: Чтение через Read Map Select
- **WHEN** для чтения выбрана конкретная плоскость через Read Map Select графического контроллера
- **THEN** чтение байта видеопамяти возвращает содержимое именно этой плоскости, независимо от значения Map Mask (которое влияет только на запись)

### Requirement: Совместимость с планарным framebuffer VGA16

VGA SHALL корректно выполнять планарные чтения, записи и read-modify-write для всех четырёх плоскостей при настройках Graphics Controller и Sequencer, используемых Linux `vga16fb`, framebuffer console и приложениями, работающими через `FB_TYPE_VGA_PLANES`.

#### Scenario: BOGL рисует цветную область через Set/Reset

- **WHEN** гость включает четыре плоскости, разрешает Set/Reset, выбирает write mode 0 и выполняет read-modify-write с неполной Bit Mask
- **THEN** выбранные пиксели каждой плоскости получают заданный четырёхбитный цвет, а пиксели вне маски сохраняют прежнее значение
- **AND** пример с последовательностью BOGL даёт тот же набор байтов плоскостей, что и VGA

#### Scenario: Framebuffer console выводит глиф через write mode 3

- **WHEN** гость записывает фон в write mode 2, загружает латчи чтением, затем записывает маску глифа в write mode 3
- **THEN** фон и передний план глифа формируются во всех четырёх плоскостях согласно Set/Reset, Bit Mask и данным CPU
- **AND** пример с последовательностью `fbcon-vga-planes` оставляет пиксели вне маски без изменений

#### Scenario: Чтение в режиме сравнения цвета

- **WHEN** Read Mode регистра Graphics Mode равен 1 и заданы Color Compare и Color Don't Care
- **THEN** чтение возвращает битовую маску пикселей, чьи учитываемые плоскости совпадают с Color Compare
- **AND** чтение одновременно загружает латчи всех четырёх плоскостей для последующей записи

### Requirement: Chained и unchained адресация

Эмулятор SHALL поддерживать линейную 8-бит-на-пиксель адресацию видеопамяти при включённом Chain-4 секвенсера (chained-режим, например BIOS-режим 13h) и прямой доступ к отдельным плоскостям по общему линейному адресу при выключенном Chain-4 (unchained-режим, например Mode X), без специальной обработки конкретных номеров режимов — поведение определяется только текущими значениями регистров Chain-4/Odd-Even/Map Mask/Read Map Select.

#### Scenario: Графический вывод в chained-режиме
- **WHEN** Chain-4 секвенсера включён, и выполняется запись байта по линейному адресу видеопамяти
- **THEN** байт сохраняется по адресу `(addr div 4)` в плоскости `(addr mod 4)`, и чтение того же линейного адреса возвращает записанное значение

#### Scenario: Unchained-доступ (Mode X)
- **WHEN** Chain-4 секвенсера выключен, Map Mask выбирает конкретную плоскость, и по некоторому линейному адресу записывается байт; затем Map Mask последовательно выбирает остальные плоскости с записью других байт по тому же линейному адресу
- **THEN** каждая плоскость хранит независимое значение по этому адресу, и чтение с соответствующим Read Map Select возвращает байт именно этой плоскости

### Requirement: Установка видеорежима

Эмулятор SHALL предоставлять программный (не через порты) способ установить один из стандартных BIOS video mode number (00h–13h), приводящий регистры CRTC/секвенсера/графического/атрибутного контроллеров и видеопамять в состояние, соответствующее этому режиму.

#### Scenario: Установка текстового режима
- **WHEN** запрошена установка текстового BIOS-режима (например, 80×25, mode number 03h)
- **THEN** после установки геометрия CRTC (Horizontal/Vertical Displayed, высота символа) соответствует заявленному разрешению в символах, и видеопамять очищена

#### Scenario: Установка графического режима
- **WHEN** запрошена установка графического BIOS-режима (например, 320×200/256 цветов, mode number 13h)
- **THEN** после установки разрешение и битность на пиксель, вычисляемые из регистров, соответствуют заявленным для этого режима, и видеопамять очищена

#### Scenario: Неизвестный номер режима
- **WHEN** запрошена установка mode number вне поддерживаемого набора 00h–13h
- **THEN** запрос завершается ошибкой, состояние регистров не изменяется

### Requirement: Текстовый вывод и курсор

Эмулятор SHALL отображать в видеопамяти текстового режима пары (символ, атрибут) как читаемый пользователем текст с учётом позиции аппаратного курсора, и SHALL предоставлять запись символа по позиции (строка, столбец) и прокрутку экрана на одну строку.

#### Scenario: Текстовый вывод символа
- **WHEN** в видеопамять текстового режима по адресу, соответствующему позиции (строка, столбец), записана пара байт (код символа, атрибут)
- **THEN** в кадре (см. Requirement «Получение кадра») в этой позиции отображается глиф символа встроенным шрифтом, окрашенный по атрибуту через Attribute Controller и DAC

#### Scenario: Установка позиции курсора
- **WHEN** запрошена установка позиции аппаратного курсора на (строка, столбец)
- **THEN** последующий запрос текущей позиции курсора возвращает установленные значения, и кадр отражает курсор в этой позиции

#### Scenario: Прокрутка на одну строку
- **WHEN** запрошена прокрутка текстового экрана на одну строку с заданным атрибутом заполнения
- **THEN** содержимое каждой строки видеопамяти заменяется содержимым следующей строки, последняя строка заполняется пробелами с заданным атрибутом

### Requirement: Получение кадра

Эмулятор SHALL предоставлять программный доступ к текущему изображению экрана в виде RGB-пикселей, вычисленному из текущего режима, содержимого видеопамяти и палитры DAC, без сохранения истории кадров.

#### Scenario: Получение кадра текстового режима
- **WHEN** запрошен текущий кадр при установленном текстовом режиме
- **THEN** возвращается изображение размером, соответствующим разрешению режима в пикселях (символы × размер глифа), с содержимым, отражающим текущую видеопамять

#### Scenario: Получение кадра графического режима
- **WHEN** запрошен текущий кадр при установленном графическом режиме (planar, chained или unchained)
- **THEN** возвращается изображение размером, соответствующим разрешению режима, с цветом каждого пикселя, вычисленным через Attribute Controller и DAC из текущего содержимого видеопамяти

#### Scenario: Кадр отражает изменения немедленно
- **WHEN** видеопамять или регистры изменяются между двумя последовательными запросами кадра
- **THEN** второй запрос возвращает кадр, отражающий изменения, без необходимости дополнительного вызова обновления

### Requirement: Начало видимого текстового экрана

VGA SHALL учитывать CRTC Start Address при формировании текстового кадра и координат видимого курсора, с замыканием адреса в активном окне видеопамяти.

#### Scenario: Аппаратная прокрутка
- **WHEN** гость сдвигает Start Address на 80 клеток в режиме 80 колонок
- **THEN** первая строка кадра содержит бывшую вторую строку без копирования VRAM

#### Scenario: Курсор после сдвига
- **WHEN** Cursor Location равен Start Address плюс 81
- **THEN** видимый курсор находится в строке 1, колонке 1

### Requirement: Программируемая адресация графического кадра

VGA SHALL формировать видимый planar, chained и unchained графический кадр с начального адреса CRTC и с шагом строки, заданным CRTC Offset, включая замыкание адресов в доступной видеопамяти.

#### Scenario: Графический кадр с ненулевым Start Address

- **WHEN** гость записывает различимые пиксели до и после адреса, выбранного CRTC Start Address
- **THEN** левый верхний пиксель кадра берётся с выбранного начального адреса
- **AND** пример со Start Address, равным одной строке, показывает прежнюю вторую строку как первую

#### Scenario: Шаг строки превышает видимую ширину

- **WHEN** CRTC Offset задаёт шаг строки больше числа байтов видимой строки
- **THEN** начало следующей строки кадра вычисляется по CRTC Offset, а невидимый промежуток не отображается
- **AND** пример с различимыми байтами в padding подтверждает, что они пропущены

### Requirement: Окно VGA хоста

При выборе оконного режима эмулятор SHALL показывать актуальные RGBA-кадры VGA в изменяемом окне, сохранять пропорции и масштабировать без сглаживания. Изменение разрешения гостем SHALL обновлять изображение без перезапуска. Закрытие окна SHALL без дополнительных действий пользователя инициировать тот же штатный останов VM, что и Ctrl+C: прекратить исполнение гостя, освободить ресурсы машины, сохранить выполненные дисковые записи и завершить CLI-процесс с успешным статусом, если при остановке не возникло ошибок.

#### Scenario: Текст и графика
- **WHEN** гость выводит текст и затем переключается в mode 13h
- **THEN** окно показывает соответствующие кадры 640x400 и 320x200 без остатка старого изображения

#### Scenario: Закрытие окна
- **WHEN** пользователь нажимает кнопку закрытия окна после того, как гость записал данные на HD
- **THEN** исполнение гостя прекращается, открытые ресурсы VM закрываются и запись сохраняется в файле HD
- **AND** CLI-процесс самостоятельно завершается с успешным статусом, не ожидая Ctrl+C или другого внешнего сигнала

#### Scenario: Закрытие окна во время активного исполнения
- **WHEN** пользователь закрывает окно, пока VM исполняет гостевой код и фронтенд ожидает обмена кадром или вводом
- **THEN** ожидающий обмен разблокируется, оконный цикл завершается без deadlock, а VM останавливается тем же идемпотентным путём, что и при внешней отмене

### Requirement: Банковый расширенный кадр
VGA SHALL поддерживать 640×480 с 256 индексами DAC, доступом к 512 КиБ видеопамяти через окно A0000h размером 64 КиБ и переключением банков без потери данных.

#### Scenario: Переход между банками
- **WHEN** гость записывает разные данные в одинаковое смещение банков0 и1 и переключается обратно
- **THEN** чтение возвращает соответствующие данные, а кадр содержит оба участка

#### Scenario: Виртуальная строка и начало изображения
- **WHEN** гость увеличивает логическую строку и выбирает допустимое начало изображения
- **THEN** видимый кадр имеет размер640×480 и соответствует выбранной области видеопамяти; недопустимые параметры отклоняются без изменения состояния

#### Scenario: Очистка и сохранение
- **WHEN** гость устанавливает mode101h с флагом сохранения или без него
- **THEN** видеопамять соответственно сохраняется или очищается; переход в стандартный режим отключает банковое окно

### Requirement: Режимы совместимости CGA
VGA SHALL поддерживать BIOS 04h/05h (320×200, 4 цвета) и 06h (640×200, 2 цвета) с окном B8000h, чередованием банков строк через 2000h и палитрой VGA BIOS.

#### Scenario: Чётная и нечётная строки
- **WHEN** гость записывает разные пиксели в B8000h и BA000h
- **THEN** они отображаются соответственно в первой и второй строках без смешения банков

#### Scenario: Чтение и переход режима
- **WHEN** гость записывает и читает байты обоих банков, затем переключается в режим 12h
- **THEN** чтение возвращает записанные данные, новый режим имеет чистый кадр 640×480 и штатную planar-адресацию

### Requirement: Преобразование DAC для эталонного кадра
VGA SHALL преобразовывать шестибитный компонент x в RGB888 как `(x << 2) | ((x & 1) * 3)`, одинаково для прямого DAC и палитры AC, в соответствии с выбранным эталоном QEMU8.2.2.

#### Scenario: Все значения компонента
- **WHEN** гость задаёт любое значение компонента DAC от0 до63
- **THEN** кадр содержит указанное преобразование с alpha255; чтение DAC возвращает исходный шестибитный компонент

### Requirement: Начальные палитры графических режимов
VGA SHALL устанавливать начальную палитру стандартных режимов04–06/0D–13 и VBE101 в соответствии с выбранным эталоном SeaBIOS1.16.3. Mode13 и VBE101 SHALL инициализировать все256 цветов, включая16 EGA,16 серых и216 оттенков.

#### Scenario: Рисунок без настройки DAC
- **WHEN** гость устанавливает режим и пишет пиксели, не изменяя AC/DAC
- **THEN** RGB-кадр совпадает с общим рисунком QEMU/SeaBIOS

### Requirement: Маска отображаемых плоскостей
VGA SHALL применять младшие четыре бита Color Plane Enable (AC12h) к индексу planar-пикселя до обращения к палитре. Маска вывода не изменяет содержимое VRAM.

#### Scenario: Отключённая плоскость
- **WHEN** гость выключает бит плоскости через AC12h
- **THEN** соответствующий бит индекса пикселя равен нулю; повторное включение восстанавливает прежний цвет без перезаписи видеопамяти

#### Scenario: BIOS mode 0Fh
- **WHEN** установлен режим 0Fh
- **THEN** маска Color Plane Enable равна 01h, как в эталонном SeaBIOS

### Requirement: Мигание текстового атрибута
VGA SHALL при установленном AC10 bit3 и attr bit7 чередовать глиф и фон каждые16 виртуальных кадров. Выключение blink SHALL возвращать яркий фон. Frame SHALL не изменять фазу. Machine SHALL продвигать номинальные текстовые кадры70Гц от виртуального времени, включая HLT.

#### Scenario: Скрытая фаза
- **WHEN** прошло16 кадров с начала видимой фазы
- **THEN** мигающий символ скрыт, обычный символ остаётся, память не меняется; ещё16 кадров возвращают глиф

#### Scenario: Аппаратный курсор
- **WHEN** CRTC разрешает курсор
- **THEN** курсор чередует видимую и скрытую фазы; CRTC disable скрывает его в обеих фазах

### Requirement: Стандартный текстовый кадр VGA
VGA SHALL использовать стандартный шрифт VGA8×16 с происхождением из public-domain набора SeaBIOS и учитывать SR01 при выборе8/9 точек клетки. Девятая точка SHALL дублировать восьмую только для B0h–DFh при Line Graphics Enable; иначе отображается фон.

#### Scenario: 80 колонок
- **WHEN** выбран режим03h
- **THEN** стандартный кадр имеет720×400 пикселей; установка SR01 bit0 даёт640×400

#### Scenario: Монохромный режим
- **WHEN** выбран режим07h
- **THEN** текст читается изB000, а атрибуты отображаются монохромной палитрой

### Requirement: Продолжение обновления кадров после смены режима

После гостевой смены видеорежима (например, mode 13h → текстовый 720×400
при выходе из игры) окно хоста SHALL продолжать обновлять кадры из
VGA-потока, а не замораживаться на первом кадре нового режима.

#### Scenario: Выход из игры в текстовый режим

- **WHEN** гость переключается из mode 13h в текстовый режим 720×400,
  выводит ENDOOM и prompt `C:\DOOM>`
- **THEN** окно показывает ENDOOM и prompt; последующие кадры (ввод,
  `dir`) отображаются без перезапуска и без остатка изображения игры

### Requirement: Ожидание вертикального обратного хода

VGA SHALL продвигать сигнал вертикального обратного хода по
виртуальному времени независимо от разрешения прерываний CPU, чтений
портов и вызовов получения кадра.

#### Scenario: Цикл ожидания обратного хода при CLI
- **WHEN** гость запрещает прерывания и последовательно ждёт сброса и установки бита 3 Input Status 1 на порту 3DAh или 3BAh
- **THEN** виртуальное время позволяет завершить ожидание нескольких последовательных обратных ходов
- **AND** повторные чтения порта без продвижения времени не изменяют фазу
- **AND** чтение каждого из этих портов продолжает сбрасывать flip-flop атрибутного контроллера
