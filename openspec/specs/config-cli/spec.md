# config-cli Specification

## Purpose

Настройка запуска эмулятора: параметры командной строки в стиле GNU-флагов и файл конфигурации (TOML) — путь HD, подключение CD, объём RAM и очередь загрузки, с приоритетом командной строки над файлом конфигурации.

## Requirements

### Requirement: Указание пути HD

Эмулятор SHALL принимать путь файла образа жёсткого диска как параметр командной строки (`--hd <path>`) или значение в файле конфигурации; размер диска задаётся параметром `--hd-size` (по умолчанию 1G).

#### Scenario: Использование существующего файла
- **WHEN** пользователь запускает эмулятор с путём к существующему файлу образа HD
- **THEN** эмулятор использует этот файл как жёсткий диск и не изменяет его размер

#### Scenario: Создание нового образа
- **WHEN** пользователь запускает эмулятор с путём, по которому файла нет
- **THEN** эмулятор создаёт raw-файл указанного размера (по умолчанию 1G), заполненный нулями

#### Scenario: Указание размера HD
- **WHEN** пользователь задаёт размер HD через --hd-size (например, 2G)
- **THEN** при создании нового образа файл создаётся указанного размера

### Requirement: Подключение CD

Эмулятор SHALL поддерживать подключение CD-устройств: ISO9660-файлов через `--cd <path>` (повторяемый) и каталогов хоста через `--shared <path>` (повторяемый). Допускается до трёх CD суммарно. ISO занимают свободные слоты в порядке Primary Slave, Secondary Master, Secondary Slave; каталоги — оставшиеся в порядке Secondary Master, Secondary Slave, Primary Slave. Порядок путей внутри каждого списка сохраняется.

#### Scenario: Подключение ISO-файла
- **WHEN** пользователь указывает путь к ISO9660-файлу через --cd
- **THEN** файл подключается как CD-ROM только для чтения на Primary Slave

#### Scenario: Подключение нескольких CD
- **WHEN** пользователь указывает несколько --cd или --shared
- **THEN** каждый путь становится отдельным CD-устройством, доступным гостевой ОС

#### Scenario: CD-путь без файла
- **WHEN** путь к ISO-файлу задан через --cd, но такого файла на хосте нет
- **THEN** запуск отклоняется с понятной ошибкой, указывающей на отсутствующий путь

#### Scenario: CD-путь без каталога
- **WHEN** путь задан через --shared, но такого каталога на хосте нет
- **THEN** запуск отклоняется с понятной ошибкой, указывающей на отсутствующий путь

#### Scenario: Превышение лимита
- **WHEN** суммарно задано более трёх ISO и каталогов
- **THEN** эмулятор SHALL вернуть явную ошибку с лимитом до создания HD и запуска ВМ, включая прямое создание Machine через API

### Requirement: Объём RAM
Эмулятор SHALL принимать объём оперативной памяти как параметр командной строки (`--ram <size>`) или значение файла конфигурации.

#### Scenario: Изменение объёма памяти
- **WHEN** пользователь задаёт объём RAM, отличный от значения по умолчанию
- **THEN** созданная виртуальная машина предоставляет запрошенный объём памяти

#### Scenario: Значение по умолчанию
- **WHEN** объём RAM не задан ни в командной строке, ни в файле конфигурации
- **THEN** применяется значение по умолчанию, заданное конфигурацией эмулятора

### Requirement: Очередь загрузки

Эмулятор SHALL принимать настройку очерёдности загрузки (`--boot <devices>`), задающую порядок устройств, с которых выполняется загрузка операционной системы. Поддерживаются устройства: hd, cd, floppy.

#### Scenario: Изменение порядка загрузки
- **WHEN** пользователь меняет порядок устройств в очереди загрузки
- **THEN** эмулятор сохраняет заданный порядок и применяет его при запуске виртуальной машины

#### Scenario: Недопустимое устройство в очереди
- **WHEN** в очереди загрузки указано устройство, которого нет в конфигурации эмулятора
- **THEN** запуск отклоняется с понятной ошибкой

### Requirement: Файл конфигурации
Эмулятор SHALL принимать файл конфигурации по пути, заданному параметром командной строки (`--config <path>`), из которого читаются параметры запуска; значения командной строки SHALL иметь приоритет над значениями файла конфигурации.

#### Scenario: Запуск с файлом конфигурации
- **WHEN** пользователь запускает эмулятор, передав путь к файлу конфигурации
- **THEN** параметры загружаются из файла и применяются при запуске виртуальной машины

#### Scenario: Приоритет командной строки
- **WHEN** один и тот же параметр задан и в командной строке, и в файле конфигурации
- **THEN** используется значение из командной строки

#### Scenario: Недопустимый файл конфигурации
- **WHEN** переданный файл конфигурации отсутствует или содержит недопустимый TOML
- **THEN** запуск отклоняется с понятной ошибкой, указывающей на источник проблемы

### Requirement: Подключение floppy

Эмулятор SHALL принимать путь к файлу floppy-образа (1.44M) как параметр командной строки (`--floppy <path>`) или значение файла конфигурации.

#### Scenario: Подключение floppy-образа
- **WHEN** пользователь указывает путь к файлу floppy через --floppy
- **THEN** файл подключается как дисковод A: на контроллере floppy

#### Scenario: Неверный размер файла floppy
- **WHEN** размер файла floppy не соответствует 1474560 байт (1.44M)
- **THEN** запуск отклоняется с понятной ошибкой

#### Scenario: Floppy без файла
- **WHEN** параметр --floppy не задан
- **THEN** дисковод не подключается, контроллер floppy не активен

### Requirement: Частота модели времени

Эмулятор SHALL принимать clock_hz в TOML и --clock-hz в CLI как целую частоту от 1 до 1000000000 Гц; значение по умолчанию SHALL быть 100000000, CLI SHALL иметь приоритет.

#### Scenario: Настройка частоты
- **WHEN** в TOML задано clock_hz=50000000, а в CLI --clock-hz=100000000
- **THEN** используется частота 100000000 Гц

#### Scenario: Недопустимая частота
- **WHEN** задан ноль, отрицательное значение или частота выше 1000000000
- **THEN** запуск отклоняется с понятной ошибкой конфигурации

### Requirement: Начальное время RTC
Конфигурация SHALL поддерживать `rtc_start`, CLI — `--rtc-start`, с приоритетом CLI > TOML > default. Значение по умолчанию `host` SHALL брать время хоста при создании VM и представлять его в UTC. Значение RFC3339 с годом 1900..2099 после перевода в UTC SHALL задавать фиксированное начало. Некорректные значения SHALL отклоняться до запуска.

#### Scenario: Воспроизводимое начало
- **WHEN** задано `rtc_start="2024-02-28T23:59:59Z"`
- **THEN** каждая новая VM начинает с указанного времени независимо от текущей даты хоста

#### Scenario: Переопределение CLI
- **WHEN** TOML содержит фиксированную дату, а CLI содержит `--rtc-start=host`
- **THEN** используется время хоста

### Requirement: Настройки оконного фронтенда
Конфигурация SHALL поддерживать display=headless/window (default headless), display_scale=1..4 (default 1), display_fps=1..120 (default 30). CLI SHALL предоставлять --display, --display-scale, --display-fps с приоритетом CLI > TOML > default. Неверные и пустые значения SHALL отклоняться до создания VM. Сборка без оконного backend SHALL явно отклонять display=window до создания дисков.

#### Scenario: Переопределение режима
- **WHEN** TOML задаёт display="window", а CLI задаёт --display=headless
- **THEN** VM запускается без окна

#### Scenario: Неверная частота
- **WHEN** задано --display-fps=0 или --display-fps=
- **THEN** запуск завершается ошибкой конфигурации до создания дисков

### Requirement: Предупреждение о незагрузочном HD в очереди `--boot`

Если после слияния конфигурации и CLI очередь `--boot` содержит HD, и
сектор 0 этого HD не пригоден для загрузки (нет сигнатуры 0x55AA или
нет активного раздела 0x80 при наличии таблицы разделов), эмулятор SHALL
вывести предупреждение с подсказкой (`--boot=cd,hd` для установки,
`freedos-ready.toml` для установленной FreeDOS). Запуск SHALL продолжаться:
сценарий boot failure диагностически валиден.

#### Scenario: Install-образ с `--boot=hd`

- **WHEN** указан install-конфиг (`freedos.img`, раздел 0x00) и `--boot=hd`
- **THEN** до старта ВМ выводится предупреждение; после загрузки MBR
  наблюдается штатный путь boot failure (не молчаливое зависание без текста)

#### Scenario: Загрузочный HD без предупреждений

- **WHEN** HD содержит активный раздел и 0x55AA (например `freedos-ready.img`)
- **THEN** предупреждение о незагрузочном HD не выводится

### Requirement: Параметры SoundBlaster16

Конфигурация SHALL поддерживать параметры SB16 в TOML: sb16 (включение, по умолчанию false), sb16_base (база портов, по умолчанию 0x220, кратна 16), sb16_irq (по умолчанию 5, допустимы 5/7/9/10), sb16_dma8 (по умолчанию 1, допустимы 0/1/3), sb16_dma16 (по умолчанию 5, допустимы 5/6/7), sb_backend (auto|file|off, по умолчанию auto), sb_backend_play и sb_backend_rec (устройство или путь файла бэкенда). CLI SHALL предоставлять флаги --sb16 on|off и --sb-backend auto|file|off с приоритетом CLI > TOML > значения по умолчанию. Недопустимые значения SHALL отклоняться понятной ошибкой до создания ВМ; при sb_backend=file путь sb_backend_play SHALL быть обязательным.

#### Scenario: Включение через CLI
- **WHEN** пользователь запускает эмулятор с --sb16=on без секции sb16 в TOML
- **THEN** создаётся ВМ с SB16 на базе 0x220, IRQ 5, DMA 1/5 и бэкендом auto

#### Scenario: Параметры из TOML
- **WHEN** TOML задаёт sb16=true, sb16_base=0x240, sb16_irq=7, sb16_dma8=3, sb16_dma16=6
- **THEN** SB16 создаётся с указанными базой, IRQ и каналами DMA

#### Scenario: Недопустимый 16-битный канал
- **WHEN** задано sb16_dma16=3
- **THEN** запуск отклоняется с понятной ошибкой о допустимых каналах {5,6,7}

#### Scenario: Файловый бэкенд без пути дампа
- **WHEN** задано sb_backend=file, а sb_backend_play пуст
- **THEN** запуск отклоняется с понятной ошибкой до создания ВМ

#### Scenario: Приоритет CLI
- **WHEN** TOML содержит sb16=false, а CLI содержит --sb16=on
- **THEN** SB16 включён; при TOML sb_backend="off" и CLI --sb-backend=file с заданным sb_backend_play используется файловый бэкенд

### Requirement: Выбор аудио-бэкенда

Бэкенд auto SHALL выбирать платформенный вывод/ввод: на Linux — aplay/arecord (при их наличии; иначе эмулятор запускается с предупреждением и бэкендом off), на Windows — winmm, на прочих платформах — off. Бэкенд file SHALL писать воспроизводимый PCM-поток в файл sb_backend_play и подавать на вход записи данные из файла sb_backend_rec (при отсутствии файла или исчерпании — тишину). Бэкенд off SHALL поглощать воспроизведение и подавать тишину на запись. Выбор бэкенда SHALL применяться только при включённом sb16 и не влиять на поведение гостя (DSP/DMA/IRQ работают при любом бэкенде).

#### Scenario: Детерминированный дамп для тестов
- **WHEN** sb_backend=file, sb_backend_play=/tmp/out.pcm и гость воспроизводит известный поток
- **THEN** файл /tmp/out.pcm содержит байты потока в исходном формате гостя без преобразований

#### Scenario: Отключённый звук не ломает гостя
- **WHEN** sb_backend=off и гость выполняет полный цикл воспроизведения с DMA
- **THEN** передача по DMA, IRQ и подтверждения работают штатно, звук никуда не выводится

### Requirement: Параметры сети

Конфигурация TOML SHALL поддерживать `network`, `network_base`, `network_irq`,
`network_mac` и параметры IPv4-подсети NAT. CLI SHALL предоставлять `--network`
 со значениями on/off; его значение SHALL иметь приоритет над TOML. Некорректные
 значения SHALL отклоняться до создания VM.

#### Scenario: Приоритет CLI
- **WHEN** TOML включает сеть, а CLI содержит `--network=off`
- **THEN** VM создаётся без сетевого адаптера
