# bios Specification

## Purpose
Минимальный BIOS реального режима эмулятора: нативные обработчики программных прерываний INT 10h/13h/15h/16h и процесс начальной загрузки операционной системы с устройства из очереди `--boot`, включая загрузку с CD в режиме El Torito no-emulation.

## Requirements

### Requirement: Перехват программных прерываний

Эмулятор SHALL предоставлять механизм, позволяющий нативно (кодом эмулятора) обрабатывать программные прерывания заданного вектора вместо доставки через таблицу векторов прерываний реального режима.

#### Scenario: Обработка перехваченного вектора
- **WHEN** гостевой код выполняет `INT n`, для вектора `n` зарегистрирован нативный обработчик
- **THEN** обработчик выполняется, изменяя регистры/память/флаги результата, и исполнение продолжается со следующей инструкции без перехода через таблицу векторов прерываний

#### Scenario: Вектор без нативного обработчика
- **WHEN** гостевой код выполняет `INT n`, для вектора `n` нативный обработчик не зарегистрирован
- **THEN** прерывание доставляется обычным образом через таблицу векторов прерываний реального режима

### Requirement: Процесс начальной загрузки

Эмулятор SHALL при запуске виртуальной машины перебирать устройства в порядке очереди загрузки (`--boot`), находить первое устройство с валидным загрузочным сектором и передавать ему управление.

#### Scenario: Загрузка с HD или floppy
- **WHEN** первое устройство очереди загрузки — HD или floppy, и сектор 0 устройства оканчивается сигнатурой 0x55AA (байты 510–511)
- **THEN** содержимое сектора копируется в память по адресу 0x7C00, и управление передаётся коду по адресу CS=0x0000, IP=0x7C00 с DL, равным номеру загрузочного диска

#### Scenario: Устройство без валидного загрузочного сектора
- **WHEN** сектор 0 устройства не оканчивается сигнатурой 0x55AA
- **THEN** это устройство пропускается, и проверяется следующее устройство очереди загрузки

#### Scenario: Нет загружаемого устройства
- **WHEN** ни одно устройство очереди загрузки не содержит валидного загрузочного сектора
- **THEN** запуск виртуальной машины завершается понятной ошибкой, а не исполнением неопределённого кода

### Requirement: Продолжение загрузки по INT 18h

Эмулятор SHALL обрабатывать INT 18h (boot failure) гостевого загрузчика как
запрос «перейти к следующему устройству очереди `--boot`». Если очередь
исчерпана, CPU SHALL остановиться с сообщением на экране, а не исполнять
неопределённый код.

Путь boot failure SHALL быть наблюдаемым для регрессии: сообщения
гостевого MBR («No active partition… Trying next boot device…») и BIOS
(«No bootable device found. System halted.») достижимы за ограниченный
бюджет шагов/циклов на install-образе с `--boot=hd`. Wall-clock время
не является критерием приёмки; контракт очереди `--boot` и запрет
roster-only CD не меняются.

#### Scenario: Гостевой MBR отказывается от текущего устройства

- **WHEN** загруженный сектор (например, FreeDOS MBR без активного раздела) выполняет INT 18h, и в очереди `--boot` после него есть ещё устройства
- **THEN** BIOS перебирает оставшиеся устройства очереди, загружает первый валидный загрузочный сектор и передаёт ему управление; устройства вне очереди `--boot` (roster-only, например CD при `--boot=hd`) не используются

#### Scenario: Очередь загрузки исчерпана

- **WHEN** гостевой код выполняет INT 18h, и следующих устройств очереди `--boot` нет
- **THEN** на экран выводится сообщение об отсутствии загрузочного устройства, CPU останавливается (HLT) в коде BIOS, а не переходит по нулевому вектору

#### Scenario: Вектор INT 18h установлен в BIOS ROM

- **WHEN** Bootstrap передал управление загрузочному сектору
- **THEN** IVT[18h] указывает на сервис BIOS, и вызовы INT 18h и far-call через IVT обрабатываются одинаково

#### Scenario: FreeDOS MBR без активного раздела на HD

- **WHEN** в очереди только HD с MBR FreeDOS и разделом без флага 0x80
- **THEN** MBR выводит сообщение о next boot device, после своего ожидания
  таймера вызывает INT 18h; BIOS печатает boot failure и паркует CPU;
  бюджет шагов до этого пути фиксируется регрессией

### Requirement: Загрузка с CD (El Torito, no-emulation)

Эмулятор SHALL поддерживать загрузку с CD-устройства, содержащего El Torito boot catalog в режиме "no emulation".

#### Scenario: Загрузка образа no-emulation
- **WHEN** первое устройство очереди загрузки — CD, и на нём присутствует El Torito Boot Record Volume Descriptor со ссылкой на Boot Catalog с Initial/Default Entry режима "no emulation"
- **THEN** загрузочный образ копируется в память по указанному в записи load segment (по умолчанию 0x7C00), и управление передаётся ему аналогично загрузке с HD/floppy

#### Scenario: Неподдерживаемый режим эмуляции
- **WHEN** Initial/Default Entry El Torito указывает режим floppy-emulation или HD-emulation
- **THEN** это устройство пропускается как непригодное, и проверяется следующее устройство очереди загрузки

#### Scenario: CD без El Torito
- **WHEN** CD-устройство не содержит корректного El Torito Boot Record Volume Descriptor
- **THEN** это устройство пропускается, и проверяется следующее устройство очереди загрузки

### Requirement: Дисковые сервисы BIOS (INT 13h)

Эмулятор SHALL предоставлять сервисы INT 13h, достаточные для чтения секторов загрузчиками реального режима: сброс (00h), чтение (02h) и запись (03h) секторов по CHS-адресации, получение параметров диска (08h), проверку поддержки LBA-расширений (41h) и расширенное чтение по LBA (42h).

#### Scenario: Чтение секторов по CHS
- **WHEN** гостевой код вызывает INT 13h AH=02h с указанием диска (DL), CHS-адреса и количества секторов
- **THEN** запрошенные секторы читаются с соответствующего устройства и помещаются по адресу ES:BX, CF=0

#### Scenario: Расширенное чтение по LBA
- **WHEN** гостевой код вызывает INT 13h AH=42h с Disk Address Packet по DS:SI
- **THEN** запрошенные секторы читаются по LBA-адресу из пакета и помещаются по указанному в пакете адресу, CF=0

#### Scenario: Запись на устройство только для чтения
- **WHEN** гостевой код вызывает INT 13h AH=03h для CD-устройства
- **THEN** запись отклоняется: CF=1, AH содержит код ошибки записи

#### Scenario: Неизвестная функция
- **WHEN** гостевой код вызывает INT 13h с неподдерживаемым значением AH
- **THEN** CF=1, AH=0x01 (invalid function)

### Requirement: Заглушки видео и клавиатуры BIOS (INT 10h, INT 16h)

Эмулятор SHALL реализовывать INT 10h (вывод текста, установка режима) через устройство VGA (capability `vga`), делегируя ему установку режима, вывод символов и позицию курсора, и SHALL предоставлять сервисы INT 16h (проверка/чтение клавиши, состояние модификаторов), основанные на реальном буфере скан-кодов устройства ввода (capability `input`).

#### Scenario: Установка видеорежима (INT 10h AH=00h)
- **WHEN** гостевой код вызывает INT 10h AH=00h с номером видеорежима в AL
- **THEN** устройству VGA передаётся запрос установки этого режима, и вызов завершается успешно при поддерживаемом номере режима

#### Scenario: Вывод символа (INT 10h AH=0Eh)
- **WHEN** гостевой код вызывает INT 10h AH=0Eh с кодом символа в AL
- **THEN** символ записывается устройству VGA по текущей позиции курсора с текущим атрибутом, позиция курсора продвигается, при достижении конца строки выполняется перенос, а по достижении конца экрана — прокрутка на одну строку

#### Scenario: Позиция курсора (INT 10h AH=02h/03h)
- **WHEN** гостевой код вызывает INT 10h AH=02h (установить позицию курсора) или AH=03h (получить позицию курсора)
- **THEN** запрос передаётся устройству VGA, и значения строки/столбца соответственно устанавливаются или возвращаются в DH/DL

#### Scenario: Проверка нажатия клавиши без ожидания (INT 16h AH=01h)
- **WHEN** гостевой код вызывает INT 16h AH=01h
- **THEN** при наличии нажатой клавиши в буфере клавиатуры возвращается ZF=0 и код клавиши в AX, не извлекая её из буфера; при пустом буфере возвращается ZF=1

#### Scenario: Блокирующее чтение клавиши (INT 16h AH=00h)
- **WHEN** гостевой код вызывает INT 16h AH=00h
- **THEN** из буфера клавиатуры извлекается следующий код клавиши (скан-код и ASCII-код) и возвращается в AX; при пустом буфере вызов не возвращается, пока в буфер не поступит событие клавиатуры

#### Scenario: Состояние модификаторов (INT 16h AH=02h)
- **WHEN** гостевой код вызывает INT 16h AH=02h
- **THEN** возвращается в AL текущее состояние залипающих модификаторов (Shift, Ctrl, Alt, Caps Lock, Num Lock, Scroll Lock), отражающее события клавиатуры, переданные устройством ввода

### Requirement: BDA-курсор страницы 0

При изменении текстового курсора через INT 10h BIOS SHALL сохранять экранные
координаты (строка, столбец) в BDA страницы 0: 0040:0050 — столбец,
0040:0051 — строка. Гости (COMMAND.COM, DOS) читают эти слова напрямую при
редактировании строки (в т.ч. backspace), минуя INT 10h AH=03h; рассинхрон
BDA и курсора VGA уводит курсор в row=255/col=79 и «вешает» ввод.

#### Scenario: Установка курсора (AH=02h)
- **WHEN** гостевой код вызывает INT 10h AH=02h с DH=строка, DL=столбец
- **THEN** BDA 0040:0051 содержит строку, 0040:0050 — столбец, в согласии с курсором VGA

#### Scenario: Teletype (AH=0Eh)
- **WHEN** гостевой код вызывает INT 10h AH=0Eh, и курсор продвигается (включая перенос и прокрутку)
- **THEN** BDA 0040:0050/0040:0051 обновляются итоговой позицией курсора

#### Scenario: Смена режима (AH=00h)
- **WHEN** гостевой код вызывает INT 10h AH=00h с поддерживаемым режимом
- **THEN** BDA-курсор страницы 0 сбрасывается в (0,0)

#### Scenario: Backspace из BDA не уходит за экран
- **WHEN** после вывода на последнюю строку (например, prompt `C:\>` + символ) гость читает BDA-курсор и выполняет backspace через AH=02h
- **THEN** позиция остаётся в пределах текстового экрана (строка < числа строк), без row=255/col=79 и CRTC-адреса за пределами видимой геометрии

### Requirement: Расширенные функции клавиатуры BIOS INT 16h

Эмулятор SHALL предоставлять расширенные функции клавиатуры INT 16h AH=10h/11h на основе того же буфера клавиш, что и стандартные функции AH=00h/01h.

#### Scenario: Проверка и чтение клавиши расширенной клавиатуры

- **WHEN** загрузчик вызывает INT 16h AH=11h, а затем AH=10h при наличии клавиши в буфере
- **THEN** AH=11h возвращает код клавиши без её извлечения и сбрасывает ZF, а AH=10h возвращает и извлекает ту же клавишу

#### Scenario: Пустой буфер расширенной клавиатуры

- **WHEN** загрузчик вызывает INT 16h AH=11h при пустом буфере
- **THEN** устанавливается ZF; вызов AH=10h ожидает клавишу

### Requirement: Служебные сервисы BIOS (INT 15h)

Эмулятор SHALL предоставлять сервис карты памяти (E820h) и обработку запросов включения линии A20 как всегда успешную операцию.

#### Scenario: Запрос карты памяти
- **WHEN** гостевой код вызывает INT 15h AX=E820h
- **THEN** возвращается дескриптор памяти, охватывающий весь объём RAM виртуальной машины как доступный (тип 1), и признак конца перечисления

#### Scenario: Включение линии A20
- **WHEN** гостевой код запрашивает включение линии A20 (INT 15h AX=2401h, порт 0x92 или контроллер 0x64/0x60)
- **THEN** запрос завершается успешно

### Requirement: Сервисы BIOS для загрузки DSL

BIOS SHALL обеспечивать загрузчику DSL 4.4.10 получение объёма обычной памяти через INT 12h и вывод текста через используемые функции INT 10h.

#### Scenario: Запрос обычной памяти
- **WHEN** загрузчик вызывает INT 12h
- **THEN** AX содержит число КиБ обычной памяти, ограниченное настроенной RAM и границей 640 КиБ; управление возвращается загрузчику

#### Scenario: Вывод загрузчика
- **WHEN** ISOLINUX выводит символы через AH=09h и управляет курсором через AH=02h/03h
- **THEN** символы с атрибутами появляются в текстовом кадре, повторная запись символа не сдвигает курсор

### Requirement: Воспроизводимая загрузка DSL

Эмулятор SHALL загружать выбранный пользователем образ DSL 4.4.10 через его штатный загрузчик. Приёмка SHALL различать запуск ISOLINUX, передачу управления Linux в protected mode и дальнейшую загрузку ядра.

#### Scenario: Переход реального Linux в protected mode
- **WHEN** выполняется загрузка выбранного ISO с зафиксированной конфигурацией
- **THEN** исполнение достигает protected-mode кода Linux; результат подтверждается адресом и состоянием CPU, а не только наличием boot signature или кодом завершения теста

#### Scenario: Определение оборудования и legacy-памяти
- **WHEN** Linux запрашивает INT 11h, INT 15h AX=E801h или AH=88h
- **THEN** BIOS возвращает конфигурацию оборудования и размеры памяти согласно настроенной RAM; неподдерживаемые функции INT 15h возвращают CF=1 и AH=86h

### Requirement: Видимый текст после установки режима BIOS
После установки текстового режима INT 10h AH=00h BIOS SHALL заполнять экран пробелами с атрибутом 07h, чтобы последующий teletype-вывод был видимым без дополнительной инициализации атрибутов гостем.

#### Scenario: Первый символ после mode 03h
- **WHEN** гость выполняет INT 10h AX=0003h и затем AX=0E41h
- **THEN** в первой клетке отображается A с атрибутом 07h, остальные клетки содержат пробелы с атрибутом 07h

### Requirement: Прямой вызов BIOS через IVT

BIOS SHALL устанавливать действительные IVT-адреса реализованных INT 10h/11h/12h/13h/15h/16h. Вызов PUSHF/CALL FAR через эти адреса SHALL возвращать тот же результат сервиса, включая CF/ZF, и восстанавливать указатель стека вызывающего кода.

#### Scenario: Определение памяти через адрес INT 15h

- **WHEN** гость выполняет PUSHF/CALL FAR [0054h] с AH=88h и RAM=16 МиБ
- **THEN** AX=15360, CF=0, управление возвращается к следующей инструкции, SP совпадает с исходным

#### Scenario: Ошибка BIOS

- **WHEN** тем же способом вызывается неподдерживаемая функция INT 15h
- **THEN** возвращается CF=1, даже если сохранённое перед вызовом FLAGS содержало CF=0

### Requirement: Число жёстких дисков BDA
BIOS SHALL записывать в физический адрес475h число уникальных зарегистрированных HD с BIOS-номерами80h–DFh; CD и floppy не учитываются.

#### Scenario: HD вместе с CD
- **WHEN** POST регистрирует одинHD и триCD
- **THEN** BDA475h равен1 и загрузчик может начать INT13 probing HD

#### Scenario: Нет HD
- **WHEN** POST регистрирует толькоCD или floppy
- **THEN** BDA475h равен0, в том числе после прежнего ненулевого значения

### Requirement: Large disk geometry

BIOS SHALL возвращать AH08 maximum cylinder не более1023 без оборачивания, сохраняяheads/sectors. AH48 SHALL заполнять26 байт по DS:SI: фактический размер, flags,32-битныеCHS,64-битное число секторов и16-битный sector size. Буфер меньше26 SHALL отклоняться с CF/AH error без изменения; байты за26 SHALL сохраняться.

Основание: GNU GRUB0.97, официальный [архив исходников](https://alpha.gnu.org/gnu/grub/grub-0.97.tar.gz), stage2/bios.c get_diskinfo. Полный диск доступен через LBA независимо от legacy CHS-предела.

#### Scenario: 2GiB HD
- **WHEN** загрузчик спрашивает параметры2ГиБ диска
- **THEN** AH08 сообщает максимальный цилиндр1023, AH48 —4194304 секторов по512 байт, без потери ёмкости.

#### Scenario: Buffer bounds
- **WHEN** размер входного буфера меньше26 либо больше26
- **THEN** слишком малый буфер не меняется; успешный вызов пишет только26 байт.

### Requirement: Чтение часов BIOS
BIOS SHALL обслуживать INT1A AH=00h (CX:DX — тики, AL — флаг смены суток с очисткой), AH=02h (CH/CL/DH — BCD часы/минуты/секунды, DL — daylight flag) и AH=04h (CH/CL/DH/DL — BCD век/год/месяц/день). Время SHALL поступать из RTC машины, независимо от его режима BCD/binary и 12/24 часа, с CF=1 при UIP. Неизвестные функции SHALL возвращать CF=1. IVT SHALL содержать действительный адрес вызова с сохранением результатов флагов.

#### Scenario: Фиксированные часы
- **WHEN** RTC настроен на 2026-09-11T12:34:56Z и гость читает время и дату
- **THEN** AH02 возвращает 12h/34h/56h, AH04 — 20h/26h/09h/11h с CF=0

#### Scenario: Чтение тиков
- **WHEN** счётчик равен 12345678h и байт смены суток равен 1
- **THEN** AH00 возвращает CX=1234h, DX=5678h, AL=1 и очищает байт смены суток

### Requirement: Счётчик системных тиков BIOS
BIOS SHALL после аппаратного IRQ0 увеличивать DWORD 0040:006C, подтверждать прерывание PIC и возвращать исходные регистры и флаги гостя. При достижении 001800B0h счётчик SHALL обнуляться и устанавливать байт смены суток 0040:0070. BIOS-загрузка SHALL программировать PIT с делителем 65536 и разрешать IRQ0. После замены гостем IVT-вектора счётчик изменяется только его обработчиком.

#### Scenario: Ожидание тиков
- **WHEN** BIOS-гость разрешает прерывания и ожидает в HLT
- **THEN** несколько аппаратных IRQ0 последовательно изменяют счётчик и возвращаются в гостя

#### Scenario: Смена суток
- **WHEN** счётчик равен 001800AFh и приходит IRQ0
- **THEN** счётчик становится нулевым, байт 0040:0070 равен 1

### Requirement: Загрузка El Torito с эмуляцией дискеты

BIOS SHALL загружать Initial/Default Entry с media 1/2/3 как дискеты 1,2/1,44/2,88 МиБ, передавать DL=0 и предоставлять INT 13h чтение 512-байтовых секторов встроенного образа. Геометрия SHALL составлять 80 цилиндров, 2 головки и 15/18/36 секторов на дорожку соответственно. Запись SHALL отклоняться; исходное CD SHALL оставаться доступным.

#### Scenario: Загрузка FreeBSD

- **WHEN** BIOS получает media=3, image LBA=172, load count=1
- **THEN** первые 512 байт загружаются по load segment, гость получает DL=0 и может читать следующие секторы встроенной дискеты через INT 13h

#### Scenario: Геометрия и защита

- **WHEN** гость запрашивает INT 13h AH=08h для встроенной дискеты 2,88 МиБ
- **THEN** возвращаются CH=79, DH=1, CL=36
- **AND** запись AH=03h возвращает CF=1/AH=03h без изменения CD

#### Scenario: Существующая дискета

- **WHEN** при загрузке CD уже подключена обычная дискета DL=0
- **THEN** она доступна через DL=1, встроенный образ занимает DL=0

#### Scenario: Неполный образ

- **WHEN** объявленная дискета выходит за границу CD
- **THEN** BIOS пропускает её и продолжает очередь загрузки

### Requirement: VBE BIOS
BIOS SHALL предоставлять интерфейс VBE1.2 INT10h AX4F00h–4F08h для mode101h и возвращать стандартный статус успеха/ошибки в AX. Информационные блоки SHALL описывать фактически доступные возможности.

#### Scenario: Обнаружение и установка
- **WHEN** гость запрашивает контроллер, список режимов и mode101h, затем устанавливает его
- **THEN** возвращаются VESA, версия0102h, завершённый FFFFh список, геометрия640×480/8bpp, банковое окноA000h и статус004Fh

#### Scenario: Банки и геометрия
- **WHEN** вызываются4F05h–4F07h с допустимыми либо недопустимыми параметрами
- **THEN** банк, строка и начало кадра устанавливаются/читаются; ошибка не повреждает прежнее состояние

#### Scenario: Сохранение и восстановление
- **WHEN** гость сохраняет аппаратное, BIOS, DAC и расширенное состояние через4F04h, изменяет их и восстанавливает
- **THEN** выбранные части состояния восстановлены, содержимое видеопамяти не откатывается

#### Scenario: DAC и неизвестные возможности
- **WHEN** гость запрашивает6-битный DAC либо неподдерживаемый режим/формат
- **THEN** поддержанный запрос успешен; неподдержанный возвращает ошибку без ложного объявления поддержки

### Requirement: Текущий видеорежим в BDA

BIOS SHALL обновлять byte BDA по физическому адресу449h после успешной
смены видеорежима через INT10 AH00. Неуспешный запрос SHALL сохранять
прежний номер режима и состояние VGA.

#### Scenario: Условное восстановление текста гостем
- **WHEN** гость устанавливает графический режим13h и читает BDA449
- **THEN** поле содержит13h
- **AND** последующий INT10 AX0003 возвращает текстовый режим и поле03h
- **AND** teletype снова виден в текстовом кадре

#### Scenario: Неизвестный режим
- **WHEN** гость запрашивает неподдерживаемый номер режима
- **THEN** BDA449 и текущий VGA режим остаются прежними

### Requirement: Исходная доставка клавиатурного IRQ BIOS

BIOS SHALL устанавливать исходный обработчик IRQ1 и разрешать его при POST
с подключённой PS/2-клавиатурой. Обработчик SHALL обслуживать выходной буфер
контроллера и выдавать EOI, сохраняя события для существующего INT16 сервиса.

#### Scenario: Клавиши до замены BIOS-вектора
- **WHEN** гость использует исходный IRQ1 и поступают make/break клавиши
- **THEN** BIOS читает клавиатурные байты и завершает обслуживание IRQ1
- **AND** INT16 получает одно событие нажатия и последующие клавиши работают
- **AND** регистры и сохранённые флаги прерванного кода не повреждаются

#### Scenario: Замена обработчика гостем
- **WHEN** гость заменяет IVT9 собственным обработчиком без перепрограммирования PIC
- **THEN** скан-коды получает гостевой обработчик IRQ1
- **AND** native BIOS hook не подменяет гостевой обработчик
- **AND** явно установленные гостем маски PIC соблюдаются

#### Scenario: Вызов исходного ROM обработчика
- **WHEN** обработчик гостя передаёт управление исходному BIOS ROM-вектору IRQ1
- **THEN** исходный обработчик обслуживает клавиатуру и EOI и возвращает сохранённое состояние

### Requirement: Текстовые операции INT 10h используют видимое окно

Все чтения и записи текстовой клетки через INT 10h (teletype AH=0Eh,
запись символа, прокрутка AH=06/07) SHALL использовать одинаковую видимую
оконную адресацию (CRTC start address), а не физический `0xB8000` без
учёта origin.

#### Scenario: Прокрутка при hardware scroll

- **WHEN** CRTC start address ≠ 0, и гость скроллит окно INT 10h AH=06/07
  (типично `dir` длинным списком после Doom)
- **THEN** исходные строки читаются из видимого окна (та же адресация, что
  запись символа); на экране не появляется пустой VRAM вместо текста

#### Scenario: Teletype при ненулевом origin

- **WHEN** CRTC start address ≠ 0, и гость вызывает INT 10h AH=0Eh
- **THEN** символ записывается в видимую позицию курсора, перенос строки и
  прокрутка читают и пишут через ту же видимую адресацию
