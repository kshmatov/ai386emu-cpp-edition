# Остаток приёмки CPU/FPU, звука и сети

> История Go-издания: упоминания Go-команд, путей и цифр ниже относятся к Go-реализации (ai386).

Сверка 2026-10-14 по текущему рабочему дереву. Это перечень проверяемых
критериев; отметки задач и производственный код при сверке не изменялись.
Результаты Doom 9.5–9.8 записаны в [актуальном отчёте](../doom-acceptance.md). Исторические гостевые прогоны
не считаются повторной приёмкой текущих незакоммиченных изменений.

В рамках сверки выполнен `go test` для `internal/dma`, `internal/sb16`,
`internal/audio`, `tools/fpu-reference/guest` и `tools/freebsd-hd-prepare`
с `GOCACHE=/tmp/ai386-status-go-cache`, `-count=1`: 64 теста в пяти пакетах
прошли. Гостевые и физические прогоны в этой сверке не запускались.

## CPU/FPU: остаток покрытия, а не отсутствие шести команд

[CPU-аудит от 11 сентября](../../openspec/changes/project-roadmap/cpu-remaining-audit.md)
устарел: [архив CPU-functional-completion от 16 сентября](../../openspec/changes/archive/2026-09-16-cpu-functional-completion/tasks.md)
фиксирует реализацию и приёмку FYL2X, FYL2XP1, FSIN/FCOS, FSINCOS и FPTAN,
общих классов/округления/исключений x87, окружения, debug/NMI, TSS,
системных команд и legacy IRQ13. Приняты отдельные
[FreeBSD](../../openspec/changes/archive/2026-09-16-cpu-functional-completion/freebsd-acceptance.md)
и [DSL](../../openspec/changes/archive/2026-09-16-cpu-functional-completion/dsl-fpu-acceptance.md)
FPU-сессии с отчётом на HD и сохранностью после перезапуска.

Открытые критерии по [отложенным задачам](../../openspec/changes/archive/2026-09-16-cpu-functional-completion/deferred-next-release.md):

| Задача | Что ещё требуется |
|---|---|
| 5.4a / roadmap 2.2 | Для каждой допустимой integer/system-формы сопоставить тесты матрицы M: режим, размер, адресация, права, fault/restart, определённые флаги; добавить отсутствующие проверки и исправить доказанные дефекты. |
| 5.4b / roadmap 2.8 | Для каждой допустимой x87-формы сопоставить тесты матрицы X: raw80-классы, PC/RC, TOP, маски, memory fault, waiting/no-wait, приоритет исключений. |
| 5.4c | После M/X согласовать базовую CPU-спецификацию с окончательным контрактом; сохранить уточнения Intel для FIST/FISTP/FBSTP precision, FBLD undefined digits и FLD denormal. |
| 5.4 / roadmap 2.5 | Зафиксировать итоговую приёмку полного этапа после предыдущих пунктов и успешных общих проверок. |

[Последний аудит покрытия](../../openspec/changes/archive/2026-09-16-cpu-functional-completion/coverage-audit-progress.md)
содержит уже добавленные матрицы; перед каждой новой регрессией сверять его
и текущие `internal/cpu/*_test.go`. Общий корпус 80386 и загрузка ОС
не заменяют M/X. SMM/RSM исключены из текущего согласованного объёма;
reserved/undefined формы не становятся обязательными архитектурными эталонами.

Повторимые команды для автоматической проверки:

```sh
ctest --test-dir build -R cpu
ctest --test-dir build -R 'FPU|Legacy'
ctest --test-dir build -R 'fpu-reference|freebsd-hd-prepare'
```

Гостевую проверку повторять по командам двух отчётов выше на отдельной
проверенной копии установленного HD. Строгий результат требует текста
FPU-отчёта, успешного статуса и сохранности после штатного shutdown/reboot.
Для повторного получения аппаратных эталонов нужны native x87 или QEMU
и инструменты из `tools/fpu-reference/README.md`; сами сохранённые эталоны
в Go-тестах не требуют native x87.

## SB16: Doom принят в файл, ОС и физические тракты остаются

[SB16 tasks](../../openspec/changes/sb16/tasks.md) отмечает DMA,
DSP/микшер, backend и интеграцию выполненными. Roadmap 7.1/7.2/7.5
по-прежнему открыты: это расхождение уровня сводки, а не доказательство
отсутствия реализации. Нельзя закрывать весь этап 7 по наличию кода.

| Задача | Незавершённый критерий |
|---|---|
| sb16-audio 5.1 | DSL: известный PCM воспроизводится с проверкой содержимого дампа; запись из `/dev/dsp` совпадает с заданным файловым источником. |
| 5.2 | FreeBSD: те же два направления через штатный snd_sbc/snd_sb16 и `/dev/dsp`, с сохранённым протоколом. |
| 5.3 / roadmap 7.3 | Linux host, backend=auto: звук действительно слышен и вход реального устройства поступает гостю. |
| 5.4 / roadmap 7.3 | Windows host, waveOut/waveIn: пользовательский протокол воспроизведения и записи; задача явно отложена до прогона пользователя. |
| 5.5 / roadmap 7.4 | Общие test/race/vet/build, Linux/Windows desktop и strict validate уже PASS после Doom fixes; закрытие всего SB16 этапа и итоговый отчёт ждут предыдущих гостевых/физических критериев. Кросс-сборка не подтверждает устройства Windows. |

Doom подтвердил ненулевой эффект, DMA/IRQ5 и PCM в режимах 2/4 при 1/100 МГц;
протокол (`../tools/doom/guest-sound.md`). Это не заменяет DSL/FreeBSD
playback/capture и реальные аудиоустройства. Существующий `TestDSLSB16Guest`
включается явно:

```sh
ctest --test-dir build -R 'dma|sb16|audio'
ctest --test-dir build -R '^TestDSLSB16Guest$' --timeout 3600
```

Перед вторым запуском подготовить отдельную копию DSL HD скриптом
`tools/freebsd-hd-prepare/prepare-freebsd-working-hd.sh` и передать её путь.
Этот тест пока не удовлетворяет строгой приёмке: воспроизводит нули и
проверяет только непустой dump; запись проверяется по `SBREC=0`, без
сравнения фактических байтов с источником. Ожидание маркеров должно
различать набранную строку команды и её выполненный вывод. Комментарий
про контрольную сумму не подкреплён командой её вычисления. Штатная
остановка также не утверждается строгим условием в конце теста.

DSL-драйвер из разведки: `modprobe sb io=0x220 irq=5 dma=1 dma16=5`;
при отсутствии mixer: `mknod /dev/mixer c 14 0`. Для FreeBSD использовать
разведку [recon-guests](../../openspec/changes/sb16/recon-guests.md),
проверив реальные модули и ISA non-PnP-конфигурацию в живом госте.
Диагностические DSL/FreeBSD harness сейчас имеют `-guest-network`, но
не общий флаг включения SB16; FreeBSD-звук требует отдельного harness
либо запуска CLI с соответствующим TOML.

Linux backend использует `aplay`/`arecord`; оба найдены в текущей среде,
но `/dev/snd` отсутствует (проверка 14 октября). Файловая приёмка доступна;
для физической нужны доступные playback/capture-устройства и наблюдение
человека. Для Windows нужны Windows host, аудиоустройства и пользовательский
прогон. `auto` может деградировать в `off`, поэтому подтверждать фактический
backend в протоколе.

## Сеть: DHCP/DNS/HTTP приняты, успешный HTTPS остаётся открытым

[Отчёт 22 сентября](../../openspec/changes/network/network-verification-2026-09-22.md)
заменяет отрицательные отчёты DSL/FreeBSD от 21 сентября: PROM panic и
короткие TCP-кадры исправлены с регрессиями; обе ОС подтвердили NE2000,
DHCP `10.0.2.15/24`, DNS `10.0.2.3`, HTTP 559 байт и штатную остановку.
В нём зафиксированы успешные test/race/vet/build и strict validate.

Открытая `ne2000-usernat 4.3`: успешный HTTP/HTTPS-ответ из **обеих** ОС
к заранее выбранному узлу и протокол отсутствия незапрошенного входящего
трафика. DSL HTTPS получил `403 Forbidden`; FreeBSD fetch сообщал
`SSL support disabled`/`Authentication error`. Эти результаты не объявлены
успешной HTTPS-приёмкой. Нужно явно разделить возможности гостевого TLS-клиента,
TLS/сертификаты endpoint и Ethernet/NAT/TCP; наличие соединения с портом 443
не доказывает успешный TLS. Совместимый клиент/endpoint следует подготовить
до прогона и сохранить фактическую команду и полученный ответ.

```sh
ctest --test-dir build -R 'ne2000|network|usernat' --timeout 120
ctest --test-dir build -R '^TestNetwork' --timeout 120
cmake --build build  # тестовый бинарник для гостевой сетевой приёмки
```

Последние два набора требуют разрешённых локальных TCP/UDP-сокетов; запрет
`listen ... socket: operation not permitted` — ограничение окружения,
но не PASS. Гостевые команды и PS/2 control-loop взять из отчёта
22 сентября; FreeBSD требуется активированный `ed0` на port 0x300/IRQ10
в `/boot/kernel.conf`, DSL — `modprobe ne io=0x300 irq=10` и `pump -i eth0`.
Для обоих прогонов нужны разрешённые исходящие соединения и DNS хоста,
отдельные рабочие HD и наблюдаемое завершение процесса через session runner.

## Итог проекта

Roadmap 9.3/9.4 требует закрытия гостевой/физической приёмки звука, сети,
CPU/FPU и общей интеграции. После изменений выполняются:

```sh
ctest --test-dir build --output-on-failure
ctest --test-dir build --output-on-failure -C ThreadSanitizer
run-clang-tidy -p build
cmake --build build
# кросс-сборка под Windows (команда фиксируется при настройке toolchain)
openspec validate --all --strict
```

Зафиксировать commit/состояние дерева, команды, конфигурации, hashes образов,
бюджеты шагов и окончательные exit codes. Исходный отрицательный отчёт Doom сохранён отдельно; текущие результаты
общего gate записываются в [актуальном отчёте](../doom-acceptance.md). Не закрывать ручные или гостевые критерии только по unit tests.
