# Review: завершение DEMO1 в Doom

> История Go-издания: упоминания Go-команд, путей и цифр ниже относятся к Go-реализации (ai386).

Проверено 2026-10-14. Объём: `tools/doom/guest_demo_test.go` и
`tools/doom/guest-demo.md`. Живая матрица режимов 2/4 и 1/100 МГц выполняется
отдельно; ниже подтверждён финальный независимый gate4/4, scope закрывает
основной агент после остальных обязательных checks.

## Standards

Тест opt-in: без config пропускается, допустимые режимы, частота и бюджеты
проверяются. Каждый запуск создаёт новый каталог и HD-копию через `copyDisk`,
не перезаписывающий существующий target. RAM 16 МиБ, HD-only boot order,
фиксированный RTC, звук и сеть не подключаются. Guest ввод идёт через PS/2;
код, память и файлы гостя извне не патчатся.

Загрузка и timedemo имеют раздельные конечные instruction budgets.
В циклах последний chunk ограничен остатком, лимит не превышается.
250M-интервал логов/PNG достаточен для наблюдения долгого прогона. Go test
timeout отключается документированной командой, но инструкции остаются
ограниченными. `m.Stop` зарегистрирован cleanup после создания машины.
Блокирующих нарушений правил `AGENTS.md` не найдено.

## Spec и критерий полного завершения

Итог ищется в VGA text как `timed N gametics in M realtics`. Требуется N=5026
и M>0, вместе с возвратом в DOS. Изменение кадров или появление игрового
изображения само по себе не даёт PASS. `demo-start.png` и `demo-progress.png`
являются промежуточными свидетельствами. При отсутствии timing или своего
DOS prompt тест теперь сохраняет `budget-exhausted` и `result.txt` со
`status=inconclusive-budget`, затем завершается FAIL. Это означает отсутствие
доказанного завершения в бюджете, а не самостоятельный диагноз дефекта.
Снимок `completed` создаётся только после обнаружения timing+prompt,
но до проверок N=5026/M>0; его имя без окончательного PASS не является
вердиктом. Итог успешного пути записывается после всех numeric assertions.

После review gate усилен: `doomDemoDOSPrompt` требует самостоятельную
строку `strings.TrimSpace(line)=="C:\\DOOM>"`, как при break цикла,
так и при финальной assertion. Echo строки запуска больше не считается
возвратом в DOS. Unit-тест отвергает echoed command и timing без приглашения,
принимает отдельное приглашение с VGA-пробелами. Первоначальное замечание
устранено.

## Диагностический nodraw и exit trace

Новый `-doom-demo-diagnostic-nodraw` по умолчанию false. True явно добавляет
гостевой `-nodraw`, пишет предупреждение и `diagnostic_nodraw=true` в итог.
Такой PASS проверяет выход и BDA, но не является rendered demo acceptance
для roadmap9.8. Свежая полная матрица запускается с false и явным бюджетом
20 млрд; результаты принимаются отдельно по каждому завершённому запуску.

`exitTrace` включается только в диагностическом режиме. Он читает CPU PC,
AX/CR0, instruction bytes через raw RAM либо `linearBytes` и обычный RAM
BDA449. В цикле нет записи guest памяти/регистров, программирования PIC,
дополнительного BIOS вызова или host SetMode. Единственный исполнитель
по-прежнему тот же поток `m.Step`. Запись делается до шага, поэтому текст
«mode request» означает наблюдённую инструкцию/аргументы, а не эксклюзивное
доказательство успешного завершения INT10. Final BDA/CPU/frame фиксируются
отдельно, read-only. Трасса не меняет гостевые A/D и fault metadata.

Actual nodraw diagnostic после BDA fix:
`/tmp/ai386-doom-demo-3770866498`, итог 5026 gametics/191 realtics и свой DOS
prompt. Init request AX0013 при BDA03, shutdown AX0003 при BDA13, финальный
BDA03 и real-mode подтверждают предсказанный путь. Это полезное подтверждение
причины исправления, но не переносится в PASS полного рендера.

Обычный путь сохраняет первый непустой 320×200 кадр в `demo-start.png`.
После review добавлена обязательная `frameSaved` assertion перед успешным
итогом, когда diagnostic flag false. Теперь полный путь не может дать PASS
без такого кадра; nodraw остаётся отдельно помеченной диагностикой.
Численное завершение и порог цветных пикселей не распознают смысл кадра;
для полной матрицы остаётся визуальная проверка артефакта.
Уже запущенные четыре бинарника с прежней predicate требуют независимой
проверки наличия/содержимого `demo-start.png` и строгого итогового screen;
успешное завершение процесса отдельно от этих свидетельств не принимается.
Открытых блокирующих standards/spec замечаний к финальному коду нет.

Первый полный результат после BDA fix независимо проверен:
`/tmp/ai386-doom-demo-2609101376`, mode4/100МГц, diagnostic_nodraw=false,
executed4396900000, итог5026/2860. В `screen.txt` самостоятельное DOS

## Проверка pinned DEMO1

Независимо разобран локальный `build/freedos/doom-cd/DOOM/DOOM1.WAD`.
SHA256 совпал с зафиксированным в `build/freedos/README.md`:
`1d7d43be501e67d927e415e0b8f3e29c3bf33075e859721816f652a526cac771`.
IWAD directory содержит DEMO1 по offset 23468, size 20118. Header имеет
версию 109 и одного активного игрока; после 13 байт header следуют
5026 четырёхбайтовых tic records и конечный marker 80h:
`20118 = 13 + 5026*4 + 1`, остаток отсутствует. Требуемое число 5026
не выбрано по краткому изменению кадров и соответствует полному lump.

Тест использует установленную копию на согласованном HD; он не проверяет
SHA256 гостевого WAD при каждом запуске. Привязка к этому IWAD относится
к комплекту FreeDOS/Doom и зафиксированным артефактам установки. Для других
пользовательских WAD этот opt-in acceptance test не заявляет совместимость.
Guest realtics являются виртуальным временем, не измерением host FPS.

рассматриваются отдельно выше.
