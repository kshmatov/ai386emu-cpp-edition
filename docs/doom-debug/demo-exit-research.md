## Подтверждённые факты

В конце CR0=60000010, CSbase=74a0, EIP=1cd3: CPU вернулась в real-mode
FreeDOS. По gametic=5026 и указателю на terminal marker DEMO1 другой
диагностический разбор подтверждает потребление всей демозаписи.
VGA остаётся в графическом режиме, PNG показывает остановившийся кадр.
`TextCell` возвращает нули: в графике `TextGeometry` возвращает (0,0),
и это ожидаемая семантика API, а не доказательство пустой текстовой VRAM.

Raw snapshot RAM[B8000] содержит нули. Эти байты также нельзя считать
снимком VRAM: Machine подключает VGA как отдельное memory device, Bus
перенаправляет видеоокно в planes VGA; `m.RAM()` содержит обычный RAM backing.
Для видимого текста нужны работающие VGA mode и TextCell/Frame.

В ordinary RAM около 23e02f найден остаток фактически отформатированной
строки `26 gametics in 2860 realtics.\r\n`. Это отличается от format literal
`timed %i gametics in %i realtics` по 1d93cc: форматирование результата
уже происходило. Первые байты output buffer позднее заняты другими данными;
этот фрагмент сам по себе не заменяет полный итоговый текст на экране.

## Причина: несогласованность BIOS mode и BDA 449h

Разобран код исходного DOS Doom из completed.ram через objdump i386.
I_Error по 18ab10 вызывает процедуру по 18a110 перед печатью результата:

```text
18ab19: call 18a110

18a110: push ebx
18a111: push edx
18a112: mov eax, 449h
18a117: cmp byte [eax], 13h
18a11a: jne 18a136
18a11c: mov word [1e0110h], 3
18a125: mov edx, 1e0110h
18a12a: mov eax, 10h
18a12f: mov ebx, edx
18a131: call 1b05bf
18a136: pop edx
18a137: pop ebx
18a138: ret
```

Это guest shutdown graphics: он меняет видео на mode3 только если BIOS
Data Area 0040:0049 сообщает mode13. В конечном артефакте RAM[449h]=03h.
По этому коду ветка restore пропускается, вызова INT10 AX=0003 нет.

`internal/bios/int10.go`, AH00, после успешного `display.SetMode(AL)`
обновляет только локальную `mode` closure и VGA. BDA449 остаётся исходной
3. AH0F читает closure, поэтому получение режима через BIOS и чтение его
из BDA расходятся. IVT10 конечного артефакта указывает на штатный F1400,
что не указывает на замену BIOS service гостем как причину этой ветки.

Печать через INT10 AH0E затем вызывает `teletypeChar`, который сразу
возвращается при TextGeometry=(0,0). FreeDOS может снова ожидать ввод,
но и сообщение timedemo, и новое приглашение остаются невидимыми.
Увеличение instruction budget это состояние не исправит.

## Минимальное исправление и проверка

После успешного BIOS set mode необходимо синхронизировать BDA449 с
действительно установленным mode. Неподдерживаемый mode не должен менять
VGA, closure или BDA. Это аппаратные гостевые данные BIOS, не workaround
в виде изменения поля Doom либо принудительного host restore VGA.

Red-регрессия должна пройти mode3→13, прочитать 0040:0049, выполнить
гостевой условный shutdown по тому же контракту и убедиться в mode3,
видимом teletype и обновлённом BDA. После исправления нужен свежий live
timedemo: полный итог 5026 gametics, положительные realtics и отдельная
строка C:\\DOOM>. Остальные ещё выполняющиеся демозаписи не принимаются
по одним gametic/terminal marker; старый failed запуск остаётся failed.

Изменения production выполняет основной агент после согласования
узкого объёма; этот файл содержит диагностические факты и проверяемую
причину, а не заявление о завершённом исправлении.
