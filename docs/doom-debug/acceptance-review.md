# Review итоговых документов приёмки Doom

> История Go-издания: упоминания Go-команд, путей и цифр ниже относятся к Go-реализации (ai386).

2026-10-14. Проверены `docs/doom-acceptance.md`, `status.md`,
`timer-results.md`, `remaining-acceptance.md` и отметки scoped/roadmap tasks.
Изменён только этот review; центральные документы принадлежат root.
Новые тесты и гостевые прогоны в этом чисто документальном аудите не запускались.

## Подкреплённые результаты

- Все четыре строки timer matrix совпали с фактическими
  `result.txt`, `before.txt`, `after.txt` перечисленных каталогов:
  timer 142→326 / 2→3 / 8→156 / 2→3,
  sample steps 2000657 / 2000000 / 2000000 / 2138358 и указанные INTA.
- Input matrix завершена для mode2/4 × 1/100МГц: проверяются реальное
  menuactive, player/mobj backpointer/начальные координаты, движение и
  расход патронов. Четвёртый root-run mode4/1МГц не получил чужой SHA-256
  сохранённого test binary — это корректно отражено в guest-input.md.
- Sound matrix совпала с четырьмя `result.txt`: 8920 / 7550 / 8573 / 7550
  отсчётов, отличных от unsigned silence128; обе полярности, 50→49 патронов,
  IRQ5 и реальные non-silent DMA reads/writes присутствуют. Нулевой
  выборочный `max_guest_non_silence` в 100МГц не подменён утверждением
  успешного snapshot кольца: сигнал подтверждают наблюдаемые reads/writes.
- GUI принят только при1МГц в двух режимах. Финальные пары menu/closed
  показали overlay26.43%→0.38% и визуально проверены; post-join RAM
  подтвердил движение/стрельбу. Старый JEMM GUI с невидимым меню оставлен
  partial в истории, его Go PASS не используется для оконной приёмки Esc.
- OS regression подтверждает ограниченный контракт boot/shell/VGA/files/
  shutdown; FreeBSD сохранила новый файл после повторного boot. Это не
  объявлено проверкой всей ISA, сети или физического звука.
- Локальные Markdown-ссылки четырёх центральных документов существуют.

## Отметки задач и границы приёмки

Roadmap9.5/9.6/9.7 отмечены выполненными на соответствующих свидетельствах.
Roadmap9.8 остаётся `[ ]`: полное DEMO1 до результата/возврата в DOS пока
не принято; движущиеся кадры и исправленный timer не заменяют завершение.
Scoped `doom-interrupt-compatibility` закрывает исправление/регрессию
прерываний, а не весь следующий Doom integration milestone.

Roadmap9.3/9.4 и CPU2.2/2.8/2.5 остаются открытыми. Документы не объявляют
готовым весь проект: полные CPU/FPU M/X, DSL/FreeBSD playback/capture,
физические Linux/Windows audio devices и HTTPS обеих ОС остаются отдельно.
Оконные100МГц, физический монитор, OPL/MIDI и точные DX4/TLB/CRTC timings
не выдаются за принятые. Общий автоматический gate описан как успешный
по результатам root; он не превращает opt-in guest/physical tests в PASS.

## Замечания к согласованности документов

### D1 — историческое основание ведёт на новый отчёт

**P2, ссылка/история.** В roadmap tasks строка «Основание — отчёт от
2026-10-11», proposal и design с той же датой всё ещё ссылаются на
`docs/doom-acceptance.md`, который теперь датирован14октября и содержит
успешную приёмку. Исходный отрицательный документ сохранён как
`docs/doom-acceptance-2026-10-11.md`.

Disposition для root: перевести исторические ссылки на сохранённый отчёт;
новые результаты оставить на основном. Проблемы и fixes подкреплены,
но нынешняя ссылка не идентифицирует исходное воспроизведение по своей дате.

### D2 — ссылка «подтверждение причины» заканчивается открытыми гипотезами

**P2, attribution/status.** Центральный report называет
`irq0-research.md` «Последний IRQ0 и подтверждение причины». Этот файл
подтверждает guest-ветку пропуска EOI, но заканчивается разделами «Что ещё
не доказано» и «Следующий probe» без итоговой clock-причины. Само
подтверждение правильно записано в `research.md` и scoped design:
однофакторное исключение walk-time, затем permanent ClockCycles и red→green.

Disposition: изменить текст/адрес ссылки, разделив trace и окончательную
причину, либо добавить явное позднее закрытие гипотез в irq0-research.
Нельзя читать его исторические открытые вопросы как нынешний диагноз.

### D3 — timer sample считает шаги Machine, а не все выполненные инструкции

**P3, единицы бюджета.** `timer-results.md` говорит «минимум2млн инструкций».
Цикл tools/doom вызывает Machine.Step2млн раз; CPU.Run1 может обслужить
IRQ и вернуть0 выполненных инструкций. Фактические `sample_steps` и
таблица корректны; README уже использует «шаги».

Disposition: использовать «шаги Machine.Step» для sample/budget, без
изменения числовых данных или результата PASS.

### D4 — автоматическая часть SB16 итогового gate уже выполнена

**P3, детализация остатка.** Таблица remaining-acceptance описывает
sb16-audio5.5 как незавершённые общие test/race/vet/build/cross-build/strict
и полный отчёт. Эти общие проверки root уже объявляет успешными;
незавершён весь этап из-за гостевой/физической приёмки, а не обязательно
каждая автоматическая команда.

Disposition: при следующей детализации отделить выполненный автоматический
gate от недостающей stage acceptance. Оставлять5.5/7.4 открытыми допустимо;
закрывать их по одному Doom PCM нельзя.

Высокоприоритетных неподкреплённых claims о принятом игровом управлении,
таймере, эффекте или готовности всего проекта не обнаружено. D1/D2 —
документальные несогласования ссылок; D3/D4 — уточнения единиц и остатка.
